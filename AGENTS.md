# AGENTS.md — общие правила KK-VIM

Единый документ обязательных правил для всех агентов и исполнителей проекта.

## 1. Перед началом работы

Перед каждой новой задачей и при продолжении работы после сброса контекста агент обязан:

1. прочитать `AGENTS.md`;
2. прочитать `docs/PROJECT_GOALS.md`;
3. прочитать `docs/DECISIONS.md`;
4. прочитать `docs/STATUS.md`;
5. прочитать постановку текущей задачи;
6. определить ID цели (G…) и границы работы.

`docs/STATUS.md` фиксирует фактическое состояние проекта, следующий шаг и блокирующие вопросы.
Текущей задачей считается задание, явно выданное пользователем. Если в STATUS.md задача
не указана, это не даёт права придумывать этап.

## 2. Научные правила

- Формулы и алгоритмы подтверждаются первоисточниками.
- Все научные обзоры, формулы, математические постановки и алгоритмы KK-VIM разрабатываются
  заново по оригинальным публикациям из `references/` (D-026).
- Ссылка указывает файл, страницу и номер формулы (определения, теоремы). Шаблон:
  `[метка, ур. (№), с. №] references/primary/<файл>.pdf`.
- Различаются: формула автора; собственный вывод проекта; инженерный численный выбор.
- Собственный вывод сопровождается проверяемыми шагами и ссылками на исходные формулы.
- Собственные выводы не приписываются авторам.
- Неизвестное не заменяется догадкой.
- Противоречия записываются как открытые вопросы. Останавливается только та работа, которую
  противоречие затрагивает.
- Метод, модель, краевые условия, материальный закон и допуски не меняются без явного решения,
  зафиксированного в `docs/DECISIONS.md`. Это относится и к подмене КК-ВИМ или его шагов другими
  методами. Если вспомогательная процедура входит в авторскую схему, её роль определяется
  по первоисточнику.
- Если код расходится с первоисточником, исправляется код, а не определение метода.
- Результаты не подгоняются под эталон.
- Сходимость итераций не доказывает правильность модели или реализации.

### Иерархия источников

1. `references/primary/` — первоисточники КК-ВИМ; главный критерий.
2. `references/additional/` — поздние работы группы Крысько; развитие метода, не замена определения.
3. Остальная часть `references/` — справочная библиотека. Наличие статьи в библиотеке
   не даёт разрешения менять метод. Найденный файл не становится первоисточником автоматически.

Других источников нет. Материалы прежних проектов не являются источником ни для формул,
ни для выводов, ни как подсказка (D-026).

## 3. Правила разработки

- KK-VIM разрабатывается с нуля как независимый проект (D-001, D-026). К прежним проектам
  и репозиториям не обращаться: их код, научные обзоры, математические спецификации, протоколы,
  индексы и выводы не читаются, не переносятся и не используются.
- Работа ведётся только в пределах назначенной задачи.
- Попутный рефакторинг не выполняется.
- Файлы другого активного исполнителя не изменяются.
- Чужие изменения не удаляются и не перезаписываются.
- Математический код пишется после утверждения спецификации соответствующей постановки.
- Разрешение писать служебный код не означает разрешения выбирать математическую модель.
- Оригинальные научные публикации (PDF, DjVu, DOC, DOCX) не добавляются в git ни при какой
  лицензии (D-021). Они хранятся локально. Нельзя ослаблять правила `.gitignore`, применять
  `git add -f` к публикациям или добавлять исключения без нового решения в `docs/DECISIONS.md`.
- В git хранятся индексы, библиографические данные и самостоятельно написанные литературные
  обзоры. Обзор пишется своими словами со ссылками на публикации и не является копией
  или переводом их текста.
- Политика D-021 добровольная. Сведения о лицензиях в `references/INDEX.md` (раздел 6)
  справочные и не являются основанием для исключений.

## 4. Проверки

- Независимый эталон не вызывает основной решатель КК-ВИМ для получения эталонного результата.
- Одномерный МКР внутри ВИМ не является независимым двумерным МКР.
- Успешный запуск, численная сходимость и научная приёмка — три разных статуса.
- Допуски фиксируются до итогового сравнения.

## 5. Отчёт агента

1. ID задачи и цели.
2. Что изменено.
3. Какие источники использованы.
4. Что проверено и каков результат.
5. Что осталось неподтверждённым.
6. Следующий необходимый шаг.

Этап не считается принятым только по собственному отчёту агента. Нужны проверка,
предусмотренная задачей, и фиксация принятия.
