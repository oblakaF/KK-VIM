## 1. Постановка и область

**Задача** [принято: MATH_SPEC, часть C, C.1–C.4, C.9; D-050]. Ω = (0, a) × (0, b), Кирхгоф–Ляв, изотропия, D∇⁴w = q, q = const ≠ 0, CCCC.
Представление w = Σᵢ₌₁ᴺ Xᵢ(x)Yᵢ(y), N фиксировано; чередование полушагов — авторская схема (уровень А). Дискретизация Π_h^C, D4, отражение —
уровень Б (D-049.1, ВБC-12), авторам не приписывается.

**Старт и ориентация** [D-049.3; MATH_SPEC C.7]. Заданный набор s = 1: Uᵢ = sin²(iπl/nₓ), l = 1…nₓ − 1, i = 1…N (базис A, подпространство 𝒯_N);
сопряжённый множитель — нули (w⁽⁰⁾ = 0). Первый полушаг — по y. Ориентация пишется в результат (C.11.2, п. 7).

**Область.** Вне её — отказ до вычислений.

| Параметр | Значение | Основание |
|---|---|---|
| N | 2 или 3, параметр `--N` обязателен | C.1; D-049.5; D-060, п. 4. N = 1 — только `run-cccc-n1` |
| Форма, нагрузка | 0,2 ≤ b/a ≤ 5; q = const, конечная, ≠ 0 | как ПОЛИТИКА-1, разд. 1; данные s = 1 (разд. 6.1): r = 1/5…5 |
| Сетки | целые 7 ≤ nₓ, n_y ≤ 1280 | наименьшее и наибольшее n в данных s = 1 при N = 2, 3 (разд. 6.1). Границы базы, а не допуски |
| Число полушагов | обязательный параметр, целое 1…8 | общий интерфейс с N = 1. **Исполняется только s = 1**, s ≥ 2 — разд. 4 |

**Следствие области (доказано, проверять в тестах как свойство).** При n ≥ 7 и N ≤ 3: N ≤ ⌊nₓ/2⌋ (независимость 𝒯_N, ВБC-13, п. 4), 2N < nₓ

## 2. Дискретная задача полушага [принято: D-049.1; MATH_SPEC ВБC-13, пп. 1–2; NS 4.2–4.3]

Сетка, Ł, W, D4 = L² + (2/h⁴)(e₁e₁ᵀ + e_me_mᵀ), шаблоны (1, −4, 6, −4, 1)/h⁴ и (7, −4, 1)/h⁴ — как ПОЛИТИКА-1, разд. 2. Для заданного набора
U ∈ ℝ^{(nₓ−1)×N}:

$$A=h_xU^{\mathsf T}U,\quad B=-h_xU^{\mathsf T}L_xU,\quad C=h_xU^{\mathsf T}D4_xU,\quad F=q\,h_xU^{\mathsf T}\mathbf 1,$$
$$\mathcal K^C\,\mathrm{vec}(V)=F\otimes\mathbf 1,\qquad \mathcal K^C=D\bigl[A\otimes D4_y-2B\otimes L_y+C\otimes I\bigr]\qquad(\text{ЧФ-C1}).$$

vec — «сначала номер члена»: vec(V) = [V₁; …; V_N]. 𝒦^C ≻ 0 ⇔ столбцы U независимы (ВБC-13, п. 2). X-полушаг (ЧФ-C2) не исполняется.

## 3. Полушаг s = 1: обязательный порядок операций [NS 5.1; D-049.2, п. 3; D-054.3; D-057.1, п. 2]

Порядок и арифметика нормативны: на них получены данные разд. 6.1 и сверка разд. 13. Импорт `kkvim_reference` и `scripts` запрещён (D-028); Builder пишет свой код.

**Шаг 1. Старт и ранг заданного набора.**

```python
l  = arange(1, n_x)
T  = column_stack([sin(i * pi * l / n_x) ** 2 for i in range(1, N + 1)])   # базис A, D-049.3; биты зависят от платформы (D-057.2, OD-12)
```

Точный ранг T в `Fraction` (исключение по столбцам, без порога). Ранг < N — доказанная зависимость, `STOP_BEFORE_QR_S1` до QR (D-049.5, п. 2).
Записываются условия разд. 1 (N ≤ ⌊nₓ/2⌋, 2N < nₓ, N ≤ ⌊n_y/2⌋) — все истинны в области.

**Шаг 2. QR стартового набора** (R4 5.4; NS 5.1, шаг 2; уровень В). Замена базиса той же оболочки; при w⁽⁰⁾ = 0 поле не меняется.

```python
hf = a / n_x
Q, R = numpy.linalg.qr(sqrt(hf) * T)                 # Householder (LAPACK)
G  = Q / sqrt(hf)                                    # решаемый набор U~; дальше всё строится по G
```

Если диагональ R содержит 0 или точный ранг G меньше N — `PROTECTIVE_STOP_FACTORIZATION`. Результат относится к span(G), то есть к 𝒯_N
после округления QR, а не к точной оболочке 𝒯_N (то же ограничение, что у ОП-8 и данных разд. 6.1).

**Шаг 3. Обусловленность (только запись, NS 5.1, шаг 3).** cond(A) до QR = cond(R)² по сингулярным числам R (в точной арифметике 1 + 2N, ВБC-17);
cond(A) после QR — по собственным числам A(G); позже — cond(S). Порогов нет.

**Шаг 4. Коэффициенты и сборка C-3⁺ матрицы** (D-054.3, п. 1; исследование сборки C, разд. 7; уровень В).

```python
A  = hf * (G.T @ G)
P  = zeros((m + 2, N)); P[1:-1] = G                                  # m = n_x - 1
LG = (P[:-2] - 2.0 * P[1:-1] + P[2:]) / hf**2
B  = -hf * (G.T @ LG)
F  = q * hf * G.sum(axis=0)
Y3 = rd(G[i-1, j] - 2*G[i, j] + G[i+1, j])                           # по каждому столбцу: точная сумма в Fraction, одно округление; вне сетки 0
h2 = hf * hf;  h3 = h2 * hf;  s = 2.0 / h3
X  = Y3 / h2
C_L = hf * (X.T @ X)
E   = s * (outer(G[0], G[0]) + outer(G[-1], G[-1]))
C   = C_L + E
```

Это ПОЛИТИКА-1, разд. 3, с векторами вместо скаляров. **Запрещено:** C через шаблон D4 в double (OLD), запасной CONTROL или OLD (D-057.3, OD-8);
пересборка B через Y3.

**Предпосылки П-1…П-5** — как ПОЛИТИКА-1, разд. 3, поэлементно для матриц: П-2 и П-3 проверяются на Y3, X, G[0], G[−1], C, C_L, E, h, h², h³, 2/h³;
m·max|X|² и 2·max(‖G[0]‖∞², ‖G[−1]‖∞²)·s < DBL_MAX; квадраты наименьших ненулевых |X|, |G[0]|, |G[−1]| и их произведение с s не ниже 2⁻¹⁰²²; дополнительно
C побитово равно fl(C_L + E). П-1 и FTZ/DAZ — пробы до сборки и после решения. П-4 — ASSUMED, в результат пишется `ESTABLISHED_CONDITIONAL_ON_P4`.
П-5: k·u < 1, k = m + 13. Нарушение — `UNRESOLVED_C3PLUS_PREMISE`, решения нет. Образец: `c3plus_premises` в `scripts/r5_cccc_q4_d1_c3plus_trajectories.py`.

**Шаг 5. B-C с поправкой ранга 2N** (D-049.2, п. 1; NS 5; уровень В). Порядок как у прототипа `r5_cccc_bc.solve_bc` с путём ёмкости `"modal"`:

```python
h  = b / n_y;  m = n_y - 1;  k = arange(1, n_y)
dst = lambda v, axis=-1: scipy.fft.dst(v, type=1, norm="ortho", axis=axis)
mu = 4.0 / h**2 * sin(k * pi / (2 * n_y))**2
DM = D * (mu[:, None, None]**2 * A + 2.0 * mu[:, None, None] * B + C)       # (m, N, N)
numpy.linalg.cholesky(DM); numpy.linalg.cholesky(A)                         # отказ -> PROTECTIVE_STOP_FACTORIZATION
rhs  = F[None, :] * dst(ones(m))[:, None]
x0   = dst(numpy.linalg.solve(DM, rhs[:, :, None])[:, :, 0].T, axis=1).reshape(-1)
rows = [i * m + p for i in range(N) for p in (0, m - 1)]
Minv = numpy.linalg.solve(DM, broadcast_to(eye(N), DM.shape))
z    = [dst(eye(m)[p]) for p in (0, m - 1)]
Y0   = empty((N * m, 2 * N))
for i in range(N):
    for side in (0, 1):
        Y0[:, 2 * i + side] = dst(Minv[:, :, i].T * z[side][None, :], axis=1).reshape(-1)
Ginv = h**4 / (2.0 * D) * kron(numpy.linalg.inv(A), eye(2))
psi1 = sqrt(2.0 / n_y) * sin(k * pi / n_y)
zk   = stack([psi1, where(k % 2 == 1, 1.0, -1.0) * psi1], axis=1)
S    = Ginv + einsum("kij,ks,kt->isjt", Minv, zk, zk).reshape(2 * N, 2 * N)
c    = numpy.linalg.solve(S, x0[rows])                                     # отказ -> PROTECTIVE_STOP_FACTORIZATION
V    = (x0 - Y0 @ c).reshape(N, m).T                                       # (m, N): Y-множители
```

A-C — только контроль QA (D-049.2, п. 2). `kkvim.linear_solver`, `coefficients`, `coupled*`, `grid.fourth_difference` не используются (схема SSSS).

**Шаг 6. Невязка исходной системы** (NS 5, У-R2), без модального преобразования; ‖·‖∞ матрицы — максимум суммы модулей строки:

```python
r   = F[None, :] - D * (D4_apply(V, h) @ A.T - 2.0 * L_apply(V, h) @ B.T + V @ C.T)
eta = max(abs(r)) / (D * (16 * norm_inf(A) / h**4 + 8 * norm_inf(B) / h**2 + norm_inf(C)) * max(abs(V)) + max(abs(F)))
```

`D4_apply`, `L_apply` — шаблоны разд. 2 по столбцам. Затем защита по η (только вариант А, разд. 6.2). V ≡ 0 точно — `STOP_ZERO_FIELD`.

**Шаг 7. Диагностика ранга поля w⁽¹⁾ = G Vᵀ** (D-049.5, п. 1: «на первом и последнем»; R4 5.2, 5.4.1; только OBSERVATION). Точный ранг V в
`Fraction`; σ₁ ≥ … ≥ σ_N матрицы R_G R_Vᵀ (QR от √hₓ G и √h_y V), ρ̂_N = σ_N/σ₁, κ_rep = ‖R_G‖₂‖R_V‖₂/σ₁. Запись
`rank_decision = "UNRESOLVED (no approved numerical rank criterion; D-049.5, D-049.6)"`. Значения статус расчёта не меняют: поле w⁽¹⁾ — точный
минимум Π_h^C на M_h(G) при любом ранге V (ВБC-13, п. 2; ЧВ4-5 по ВБC-14).

**Шаг 8. Поле.** w⁽¹⁾ = G Vᵀ во внутренних узлах (ось 0 — x, ось 1 — y), на границе 0. Нормировки нет: следующего полушага нет.

## 4. Защита ранга при s ≥ 2 [D-049.5, п. 1; D-057.1, пп. 1–5, 9]

**Разрешено:** s = 1 при N = 2, 3, с QR только стартового набора (D-057.1, п. 2).

**Если запрошено `--half-steps` ≥ 2:** после s = 1 выполняется только проверка полушага s = 2, **до QR решённого набора V** и без сборки и решения:

1. точный ранг V < N → `STOP_BEFORE_QR_S1` (доказанная зависимость, D-049.5, п. 2);
2. конфигурационный S-1 по РН-3 (N > ⌊nₓ/2⌋ для решаемого x) — в области невозможен, условия записываются;
3. иначе → **`STOPPED_RANK_GUARD_UNCERTIFIED`** (D-057.1, п. 4): QR не выполняется, N не понижается, направления не восстанавливаются,
   регуляризации нет, ранговый допуск не используется.

Поле s = 1 сохраняется как диагностическое (разд. 5). Это тот же порядок, что у ОП-8 (`run_step`, (b)–(d)), поэтому его проверяет К-1.

**Почему s ≥ 2 нельзя исполнить сейчас.** QR и B-C на V корректны только при полном ранге V. Точный ранг V не гарантирует ранга точной последовательности:
ошибка сохранённого V относительно неё не оценена (O4 — UNRESOLVED, D-054.5; R4NS 5.2, п. 9). Численного критерия нет. Вариант В D-057.1 выбран
владельцем именно для этого случая.

**Ровно то решение, которое снимет блок s ≥ 2.** Решение владельца, заменяющее для N = 2, 3 при s ≥ 2 защитную остановку D-057.1, п. 2
квалифицированной процедурой ранга решённого набора перед QR: **либо сертификат ранга (вариант Б ПАКЕТА PR #49, РН-5…РН-9) после его
QA-квалификации, либо численный критерий ранга CCCC по D-049.6, п. 3 (K, c_rank, c_d, τ_set; S-2)**. Без него Builder s ≥ 2 не программирует.
Для s ≥ 2 понадобятся и свои числа η и TS-1: данные Q3/EQ при s ≥ 2 — парные полушаги на входах R-AC, на собственные траектории не переносятся.
