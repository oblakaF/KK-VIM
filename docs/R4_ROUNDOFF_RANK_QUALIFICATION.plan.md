## 1. Вопрос и что считается ответом

R4_NUMERICAL_SPEC, разд. 5.2, п. 7: если ε — **доказанная** верхняя оценка и ε < 1, то

ρ̂_N > ε/(1 − ε) ⇒ σ_N(W*) > 0,  ε = c_d(n, N)·u·κ_rep + δ_f,

где W* — поле точной дискретной последовательности на той же сетке, Ŵ — точное произведение сохранённых факторов, δ_f = ‖Ŵ_w − W*_w‖₂/‖W*_w‖₂,
c_d·u·κ_rep — ошибка вычисления σ̂_k по сохранённым факторам (QR, произведение, SVD). D-046, D-048.5: c_d, c_rank, τ_set, накопленная δ_f —
NOT_QUALIFIED.

**Вопрос кампании.** Можно ли во всей области D-048 для N = 2–3 установить **обоснованные верхние бюджеты** всех составляющих ε, которые
рабочий решатель может применять (т. е. не только для записанного прогона), с явными предпосылками.

Различаются три вида результата для каждой составляющей:

| Вид | Смысл |
|---|---|
| **СТРОГАЯ ГРАНИЦА** | априорная или вычислимая во время расчёта граница, доказанная при явных предпосылках (модель IEEE 754 и т. п.); проверяется сертифицированным измерением |
| **СЕРТИФИЦИРОВАННОЕ ИЗМЕРЕНИЕ** | строгая оболочка (шаровая арифметика) фактической ошибки **конкретных массивов** записанного прогона на этой платформе. Это не бюджет для других прогонов и платформ |
| **МОДЕЛЬ / OBSERVATION** | модель первого порядка или наблюдённая константа; отношение «измерено / модель» — наблюдение |

Ошибка **одного полушага** и **накопленная** δ_f разделяются (разд. 3). Малая невязка η_N **не** принимается доказательством малой δ_f
(D-048.2); это проверяется отдельно (разд. 6, Г-2).

Строгая оценка ранга N23-4 относится к **точным** последовательностям и автоматически на вычисленные поля **не переносится**. Она
используется только как известный факт о W* в сертифицированных ячейках (rank W*(s) = N; S-1 там невозможна) и не подменяет измерения.

## 2. Область

Область D-048 для N = 2–3 — она же 132 дискретные ячейки N23-4 (в):

| Часть | Значения |
|---|---|
| N | 2, 3 |
| r = b/a (a = 1, D = q = 1) | 1/5, 1/3, 1/2, 2/3, 1, 7/5, 3/2, 2, 3, 5 |
| семейство I | n_x = n_y = n ∈ {40, 80, 160, 320, 640, 1280} × 10 r — 60 сеток |
| семейство II (h_x = h_y, r = n_y/n_x) | (1600, 320), (960, 320), (640, 320), (320, 640), (320, 960), (320, 1600) |
| ячеек | (60 + 6) × 2 N = **132** |

Отдельные пункты D-048 используют подмножества (обязательная энергия s = 2 — n = 160, 640, 1280 и семейство II; остановка — n = 40, 160, 640;
`dense` — контроль). Кампания охватывает объединение.

**Входные данные.** a = 1.0, b = float(r), D = q = 1.0 — как в D-048 К-2…К-5 и D-053. «Точная задача» — дискретная задача R4_NUMERICAL_SPEC 2.1
при **этих binary64-входах** и точной арифметике дальше (h = a/n — точное рациональное число). Отличие float(r) от r — вопрос входа, а не
округления решателя; оно не входит в δ_f. Отличие binary64-шага `Grid1D.h` от a/n входит в δ_f (сборка, источник 1).

**Режимы продолжения (все предусмотренные D-047/D-048):**

| Режим | Вызов `run_coupled` | Последовательность |
|---|---|---|
| M0 нормативный | `research_mode=False` | только s = 1, затем NOT_QUALIFIED (или HALF_STEP_LIMIT_REACHED при half_steps = 1) |
| M1 исследовательский, остановка | `research_mode=True`, `stop_on_stabilization=True`, half_steps = 100 | до PROVISIONAL_FIELD_STABILIZED, защитной остановки, E1-остановки или s_max = 100 |
| M2 фиксированное число полушагов | `research_mode=True`, `stop_on_stabilization=False`, half_steps = 100 | до s_max = 100 (MAX_HALF_STEPS) или защитной/E1-остановки |

M0 — первый полушаг M1. M1 — префикс M2: это проверяется побитово (поля, журналы до s_stop), как в К-2. Поэтому основной расчёт — M2 на всех
132 ячейках, все полушаги s = 1…s_end (s_end — фактический последний полушаг M2, до 100). Величины M1 — те же записи при s ≤ s_stop.

**Преобразование.** `fft` — основной путь (D-048.6), вся область. `dense` — контроль: M1 на всех ячейках с max(n_x, n_y) ≤ 1280 (там, где К-6
проверил модель элемента) и M2 на семействе I при n ∈ {40, 1280}, r ∈ {1/5, 1, 5}. Ячейки с n = 1600 для `dense` — вне контрольной области
(NOT_RUN по определению).

Если расчёт какой-либо ячейки не выполнен (ресурсы, недостигнутая точность оболочки), ячейка получает **NOT_RUN** или **UNRESOLVED** с причиной;
молчаливых пропусков нет. Ячейка без результата не может войти в область PASS.

## 3. Измеряемые величины

Всё вычисляется в координатах DST-I: Ŵ = Ψ_xWΨ_y, Ψ точно ортогональна, поэтому взвешенные нормы поля (вес h_xh_y, R4_NUMERICAL_SPEC 5.2)
и сингулярные числа совпадают с нормами матриц коэффициентов, умноженными на √(h_xh_y). Задача в этих координатах — N23-1 (в):
вес (μ^x_m + μ^y_n)², цель Ω_mn = q·c^x_m·c^y_n/(D(μ^x_m + μ^y_n)²), c_m = √(2/n)·ctg(mπ/(2n)) для нечётных m и 0 для чётных.
Y-полушаг с заданным набором коэффициентов X (все моды, включая чётные — шум сохранённых массивов): для каждой y-моды k

D(μ_k²A′ + 2μ_kB′ + C′)·y_k = q·c^y_k·F′,  A′ = XᵀX, B′ = Xᵀdiag(μ^x)X, C′ = Xᵀdiag((μ^x)²)X, F′ = Xᵀc^x.

Это та же система ЧФ-3 решателя, делённая на h (A = hA′, B = hB′, C = hC′, F = qhF′ по ЧВ4-1 и ортогональности Ψ). X-полушаг — симметрично.

| Обозначение | Определение |
|---|---|
| W*(s) | точная последовательность от точного старта РВ4-1 (точная арифметика) |
| Ũ_s, V̂_s | заданный и полученный наборы полушага s, сохранённые решателем (binary64; до QR полушага s) |
| W̃(s) | точное произведение Ũ_sV̂_sᵀ сохранённых массивов |
| W^♮(s) | точное решение полушага s **с сохранённым заданным набором** Ũ_s (одна точная операция полушага) |
| W̃^QR(s) | точное произведение массивов после QR полушага s (companion·(Q/√h)ᵀ) — поле, передаваемое на s + 1 |
| δ_f(s) | ‖W̃(s) − W*(s)‖/σ₁(W*(s)) — накопленная ошибка поля |
| e_step(s) | ‖W̃(s) − W^♮(s)‖/σ₁(W*(s)) — ошибка одного полушага |
| t(s) | ‖W^♮(s) − W*(s)‖/σ₁(W*(s)) — перенос ошибки предыдущих полушагов |
| δ_QR(s) | ‖W̃^QR(s) − W̃(s)‖/σ₁(W*(s)) — ошибка сохранения поля при QR |
| L_s | t(s)/δ_f^QR(s − 1), δ_f^QR = ‖W̃^QR − W*‖/σ₁ — наблюдённый множитель переноса |

Нормы: числитель — Фробениус (верхняя граница спектральной нормы), знаменатель — нижняя граница σ₁ (строгие собственные числа). Поэтому δ_f, e_step,
t, δ_QR — **строгие верхние оценки** соответствующих спектральных величин. По неравенству треугольника δ_f(s) ≤ e_step(s) + t(s); это проверяется.

**Разложение e_step(s) по источникам** (точное телескопическое; каждая разность — сертифицированная величина поля ‖Ũ_s·Δᵀ‖/σ₁):

| Шаг | Данные точного решения моды | Разность — источник |
|---|---|---|
| V⁽⁰⁾ | точные A′…F′ из Ũ_s, точные μ_k, c_k | — (это W^♮) |
| V⁽¹⁾ | binary64 A, B, C, F решателя, точные μ_k, c_k | V⁽¹⁾ − V⁽⁰⁾ — (1) сборка A, B, C, F |
| V⁽²⁾ | то же + binary64 μ_k (`sine_eigenvalues`) | (1′) собственные числа |
| V⁽³⁾ | то же + binary64 ψ_kᵀ𝟏 (DST от 𝟏) | (3′) DST нагрузки |
| V⁽⁴⁾ | точное решение binary64-систем решателя M_k = fl(μ_k²A + 2μ_kB + C), b_k = fl(F·ψ_kᵀ𝟏) | (2а) формирование систем мод |
| V⁽⁵⁾ | фактические моды решателя (Холецкий, /D) | (2б) решение Холецкого |
| V̂ | Ψ·(сохранённый узловой V̂) | (3) DST результата (`fft` или `dense`) |

Если решатель выполнил уточнение (D-048.2), полушаг отмечается и разлагается только суммарно. Уточнений не ожидается (К-4: 0 случаев); это
проверяется.

**Энергетический маршрут (диагностика QA, не критерий решателя).** Для любого поля w: если ‖w − ω_h‖_{a_h} < d_{N−1} := inf_{rank z ≤ N−1}‖z − ω_h‖_{a_h},
то rank w = N, и dist(w, 𝓡_{N−1}) ≥ d_{N−1} − ‖w − ω_h‖ (определение d_{N−1} и неравенство треугольника; та же логика, что ВБ-20, без
монотонности). Это применяется к **сохранённому** полю W̃(s): ‖W̃ − ω_h‖²_{a_h} вычисляется строго, d²_{N−1} ≥ D^{low}_{N−1} — лемма N23-3 (своя
строгая реализация QA `_d_lower`, `scripts/r4_n23_qualification.py`, на ω_h задачи с binary64-входами). Маршрут сертифицирует полный ранг
**сохранённого** поля и не использует δ_f и c_d. Вывод тривиален, но он собственный вывод QA и требует проверки Reviewer; в нормативный критерий
сам по себе не превращается.

## 5. Инструменты (новые, `src/` не меняется)

`scripts/r4_roundoff_rank_qualification.py`:

1. **Запись прогона.** На время одного `run_coupled` функции `solve_coupled_halfstep`, `refine_once` и `orthogonalize_received`
   в пространстве имён `kkvim.coupled_run` заменяются обёртками, которые вызывают оригиналы и сохраняют копии массивов (заданный набор, полученный
   набор, моды, коэффициенты, массивы после QR). Численный путь не меняется. Проверяется: итоговые X, Y записи = `run.x`, `run.y` побитово; журнал
   (ρ_N, κ_rep, η_N, Π_h) прогона с обёртками = журнал прогона без обёрток побитово.
2. **Точная последовательность W*(s)** в шаровой арифметике arb (python-flint) в координатах DST, только нечётные моды (чётные точно нулевые,
   R4_NUMERICAL_SPEC 4.3, п. 1). После каждого полушага полученный набор переводится в почти ортонормированный базис умножением на **точно
   представимую** матрицу (приближённое R⁻¹; невырожденность проверяется строго): поле от базиса не зависит (ВБ-16), обёртывание не растёт
   от обусловленности представления. Точность адаптивная: старт 256 бит; если max относительный радиус коэффициентов W*(s) на каком-либо s > 2⁻¹²⁰,
   точность удваивается и расчёт повторяется (до 16 384 бит); иначе ячейка — UNRESOLVED.
3. **Строгий перенос сохранённых массивов** в координаты DST: x (binary64 точно) ↦ Ψx в arb, Ψ строго (sin_pi по таблице 2n значений), 256 бит.
4. **Строгие сингулярные числа** поля ранга ≤ N и ≤ 2N: σ_k² — собственные числа N × N-матрицы Lᵀ G_Y L (G_X = LLᵀ — строгий Холецкий в arb);
   оболочки — алгоритм Rump в arb (`acb_mat.eig(algorithm="rump")`); при отказе сертификации — UNRESOLVED.
5. **Разложение по источникам** (разд. 3) — точные решения мод N × N в arb с данными, взятыми побитово из массивов решателя
   (`step.coefficients`, `sine_eigenvalues`, `sine_transform(𝟏)`; формирование M_k повторяется тем же выражением NumPy, что в `_solve_modes`,
   и сверяется побитово на контрольной выборке).
6. **Независимый узловой путь на малых сетках** (вариант A, R4_NUMERICAL_SPEC 3.1): A, B, C, F — узловыми суммами в arb, блочная система
   𝒦 = D[L² ⊗ A − 2L ⊗ B + I ⊗ C] собирается из узловых разностных матриц и решается в arb без DST и без модального разделения;
   двумерная проверка проекционности — двумерная узловая сборка a_h по вторым разностям.

**Общие операторы и пределы независимости (известны заранее).** Путь 2 и `kkvim_reference.r4_spectral_control.run_control` используют ту же
спектральную формулировку (диагонализацию L DST-I, N23-1 (в)); это не независимый двумерный эталон, а другая реализация той же дискретной
задачи. Независимым от модального пути служит только путь 6 (малые сетки). `kkvim_reference.r4_dst_check`, `r4_rank_diagnostics` —
прежний код QA. `_d_lower` — прежний QA-код N23 (`cfa9888`). QA и Builder — исполнители одного типа.

## 7. Критерии

**Проверка строгой границы** (источники 1, 2, 3 `dense`, 4 — Вейль, 5) в каждой точке: **PASS**, если верхний конец оболочки ошибки ≤ нижнего
конца границы; **FAIL**, если нижний конец ошибки > верхнего конца границы (граница или её предпосылка неверна); иначе **UNRESOLVED**. Одно FAIL
переводит соответствующую границу в FAIL во всей области.

**Модель** (`fft`, c_d, сохранение поля при QR, Холецкий, R(w), R_f, линейное накопление): записывается max отношения «измерено / модель» по
области, без PASS/FAIL. Значение, превышающее модельную оценку, отмечается как опровержение модели в роли верхней границы.

**Сертифицированное измерение.** Для каждой ячейки и s — строгие верхние оценки δ_f, e_step, t, δ_QR и строгие оболочки σ_k(W̃_w), σ_k(W*_w).
Ранговый критерий проверяется с **измеренным** ε_cert(s) := max_k |σ̂_k − σ_k(W*_w)|/σ₁(W*_w) (верхний конец): «различим в этом прогоне»,
если ρ̂_N > ε_cert/(1 − ε_cert) и ε_cert < 1. Это **апостериорный** результат для записанных массивов и платформы, не бюджет решателя.

**Энергетический маршрут:** «полный ранг сохранённого поля сертифицирован», если верхний конец ‖W̃ − ω_h‖_{a_h} < нижнего конца (D^{low}_{N−1})^{1/2}.

**Кандидаты c_d, c_rank, τ_set** выводятся только из строгих границ: c_d — из доказанной оценки обратной ошибки QR/SVD с явной константой;
τ_set = c·u·√N + max_jε_j — из доказанных оценок ошибок столбцов; c_rank — только при доказанном ε. Наблюдённые отношения кандидатами
**не** становятся.

**Итоговый вердикт.**
- **QUALIFICATION_READY** — только если во всей области разд. 2 (все 132 ячейки, все полушаги режимов M0–M2, `fft`; `dense` в его области) для
  обеих составляющих ε (c_d·u·κ_rep и δ_f, включая перенос по s и DST `fft`) есть **строгие границы, применимые рабочим решателем**, ни одна
  проверка строгой границы не FAIL, сертифицированные измерения их не опровергают, и кандидаты c_d, c_rank, τ_set выведены из этих границ.
- **NOT_QUALIFIED** — если хотя бы одной необходимой строгой границы нет (в том числе если есть только сертифицированные измерения записанных
  прогонов). Отчёт перечисляет недостающие оценки и минимальные дополнительные исследования.
- **BLOCKED** — если не пройдены проверки инструментов В-1…В-5.

Нормативными кандидаты становятся только решением владельца.
