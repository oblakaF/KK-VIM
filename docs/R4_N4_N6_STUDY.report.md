## 2. Изоляция от рабочего решателя

- `src/kkvim`, `src/kkvim_reference` и спецификации не изменены. `N_SOLVE = (2, 3)` сохранён: `meta.json`, `N_SOLVE_before = N_SOLVE_after = [2, 3]`;
  тест `test_production_range_and_guards_are_unchanged`. `solve_coupled_halfstep` и `run_coupled` по-прежнему отклоняют N = 4. Monkeypatch не применялся.
- `research_halfstep` выполняет **те же операции и в том же порядке**, что `kkvim.coupled.solve_coupled_halfstep`:
  `coupled_coefficients` → `sine_eigenvalues`, ψᵀ𝟏 → `_solve_modes` → обратное `sine_transform` → проверка конечности. Отличие одно — нет проверки N_SOLVE.
- `run_cell` повторяет цикл `run_coupled(research_mode=True, stop_on_stabilization=False)`: решение → контроль η_N (D-048.2) → диагностика поля и набора →
  энергия → защиты K_RESEARCH (D-048.5) → QR → следующий полушаг. Остановка — до QR, N не меняется. Константы, защиты, ε_floor и правило конфигурации
  импортируются из `kkvim.coupled_run`. Новых определений метода, полушага, ранга и правила остановки нет.
- **Проверка эквивалентности.** При N = 2–3 оркестрация совпадает с `run_coupled` побитово: наборы X, Y, журналы, статус и s первой стабилизации.
  Это проверено на 12 контрольных ячейках полного расчёта и в 5 тестовых конфигурациях. Значит, для N = 4–6 исследуется тот же путь решателя, а не его аналог.
- D-048 относится к N = 2–3. Применение его исследовательского контроллера без изменений к N = 4–6 — выбор этого исследования, а не расширение D-048.

## 5. Результаты

### 5.1. Где расчёт успешен и причины неудач (T1, T9)

- **Успешно, s = 40 (RESEARCH_LIMIT_REACHED):**
  - N = 4 и 5 — все 66 + 66 ячеек;
  - N = 6 — 52 ячейки при r ∈ {1/2, 2/3, 1, 7/5, 3/2, 2, 3, 5};
  - контрольные N = 2, 3 — все 12.
- **Ошибок решения нет.** Не было ни одного случая ERROR_LINEAR_SOLVE, ERROR_NONFINITE, ERROR_DEGENERATE или срабатывания E1. Невязка max η_N = 4,9·10⁻¹⁶,
  уточнений 0; max cond M_k = 2,0·10⁵ (N = 6); κ_rep = 1 на всех полушагах после QR.
- **Неудачи: N = 6, r = 1/5 и 1/3 — все 14 ячеек** (семейство I 40…1280 и семейство II). Статус PROVISIONAL_RANK_GUARD_STOP на **s = 1**, до QR, N не меняется.
  - Причина: ρ_N(w¹) ≤ K·u·κ_rep = 1,11·10⁻¹⁰ (κ_rep = 1).
    - r = 1/5: ρ_N = 1,74·10⁻¹², ρ/порог = 0,016; дополнительно не проходит защита набора, σ_min(R_V·D_c)/(K·u) = 0,28;
    - r = 1/3: ρ_N = 7,4·10⁻¹¹, ρ/порог = 0,67.
  - **Это свойство поля первого полушага, а не сетки.** ρ_N почти не зависит от n (r = 1/5: от 1,452·10⁻¹² при n = 40 до 1,7404·10⁻¹² при n = 1280).
    Значение ρ_N непрерывного полушага по рекурсии Парсеваля (M = 4001) — 1,741·10⁻¹² (r = 1/5) и 7,39·10⁻¹¹ (r = 1/3). Сгущение сетки остановку не снимает.
  - Статус **не** является доказанной потерей ранга (S-1) и **не** присваивает S-2: математически rank w¹ = N при n_x, n_y ≥ 2N (ЧВ4-9).
    Это недостаточный запас относительно исследовательской защиты, критерий которой не квалифицирован.
- **Близко к защите**, но прошли (min ρ/порог по полушагам): N = 5, r = 1/5 — 1,27; N = 6, r = 5 — 1,47; N = 5, r = 5 — 81; N = 6, r = 1/2 — 5,2.
  Наименьший запас — на s = 1.
- **Асимметрия r ↔ 1/r.** Старт задаётся по x, поэтому на s = 1 при r < 1 ρ_N меньше, чем при r > 1. Пример N = 6: 1,7·10⁻¹² (1/5) против 3,6·10⁻⁹ (5).

  на той же сетке: при n = 1280 — 6,9·10⁻⁸ (r = 1), 6,66·10⁻⁷ (r = 1/5, 5). Это наблюдение, не оценка (R4_NUMERICAL_SPEC 9.4).
- **Семейство II** (h_x = h_y): дискретизационная ошибка определяется короткой стороной с 320 интервалами — 3,4·10⁻⁶…7,6·10⁻⁶ (T5).

## 7. Что не утверждается и ограничения

1. Исследование — не приёмка N = 4–6. Все результаты PROVISIONAL / NOT_QUALIFIED. Сетки исследования не нормативны; пороги по результатам не выбирались.
2. Для N = 4–6 применён без изменений исследовательский контроллер D-048, включая K_RESEARCH = 10⁶. Его критерии для N ≥ 4 не квалифицированы.
   Остановка N = 6 при r ∈ {1/5, 1/3} — следствие этой защиты, не доказательство потери ранга. Продолжать расчёт за защитой исследование не вправе.
3. Сходимость при фиксированном N не доказана. PROVISIONAL_FIELD_STABILIZED здесь не используется: стабилизация только регистрируется.
4. Утверждения о неусечённом непрерывном методе при s ≥ 2 — не выше PROVISIONAL (Q-022 OPEN).
5. Дискретный контроль V5 не выполнялся на n = 1280. Вариант A (сборка блочной системы, А4-5) и расчёты в повышенной точности (QA-δ1, QA-δ2) в объём не входили.
6. Классы ζ^(N) — эвристика. Класс A не достигнут при N = 5, r ∈ {1/5, 5} и N = 6, r = 5 на n ≤ 1280. Для N = 6, r = 5 он недостижим и в пределе 1905
   правила конфигурации.
7. Энергетическая ошибка e_rel,h дискретного поля по энергетическому пути при N ≥ 4 на мелких сетках неразрешима моделью R(w). Значения прямого пути
   согласуются с непрерывными (например, 5,15·10⁻¹² против 5,22·10⁻¹² при N = 6, r = 1, n = 640), но статуса не получают: строгой модели округления
   прямого пути нет.
8. Побитовое совпадение результатов между платформами не требуется (AGENTS.md, разд. 4). Тест воспроизводимости сравнивает статусы и s точно, а w(центр)
   и Π_h — с относительным допуском 10⁻¹⁰. Величины на уровне округления (дефект тождества, рост Π_h после стабилизации) от платформы зависят.
9. Расчёт выполнен на одной машине (Windows 10, Python 3.14.8). Тесты — на 3.13.15 и 3.14.8.
