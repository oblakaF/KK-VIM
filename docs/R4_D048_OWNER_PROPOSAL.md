## 1. Решение по пунктам

### D-048.1. Энергетический контроль

- **Утверждается как действующая форма** (R4_NUMERICAL_SPEC 6.3; реализация проверена: QA B5, PR #16, 0 нарушений E1/E2):
  τ_s^(N) = |γ_s| + 10[R(ŵ^(s−1)) + R(ŵ^(s)) + R_f^(N)]; E1: ΔP_s ≥ −τ_s^(N); E2: |ΔP_s − Q_s| ≤ τ_s^(N); тест разрешён при Q_s ≥ 10τ_s^(N),
  иначе **UNRESOLVED** (не FAIL и не PASS).
- **Множитель 10** — параметр принятой формы, перенесённый из R2; **не** выведенная универсальная константа (NOT_QUALIFIED как выведенное число).
- **s = 2 — обязательная область только на фактически проверенных уровнях:** семейство I n = 160, 640, 1280; шесть сеток семейства II.
  Основание — правило резерва D-039 (m_s = Q_s/(10τ_s) ≥ 4 для всех r уровня): min m₂ = 12,7–12,8 (N = 3, r = 5, n = 1280; QA и Auditor).
  - **Не обязательна:** n < 160, промежуточные уровни (n = 320 семейства I, промежуточные уровни цепочек II) и n > 1280. m₂ падает примерно
    в 4,2 раза за удвоение n (54 → 12,7 при 640 → 1280, N = 3); около n ≈ 2560 правило m ≥ 4 ожидаемо нарушится.
  - *Вариант для владельца (не включён по умолчанию):* распространить обязательность на промежуточные уровни 160 ≤ n ≤ 1280 по монотонности
    m₂(n) без отдельного расчёта (аудит, Э-2).
- **s ≥ 3 — необязательная область** на всех уровнях (UNRESOLVED допустим): m₃ ≤ 9,4 при n = 160 и < 1 при n ≥ 640.
- Не выполненный на обязательном уровне тест (Q_2 < 10τ_2) — «тест не выполнен» с объяснением, как в R2 (NUMERICAL_SPEC 10.4), а не FAIL.
- **NOT_QUALIFIED:** соответствие FAIL E1 статусам ERROR_ENERGY_TEST и PROVISIONAL_ENERGY_E1_STOP (в предквалификации не проверялось; аудит, О-2).

### D-048.2. Невязка

- **η_max = 10⁻¹²** (значение R2) — **контроль реализации** модального решения в обследованной области: семейство I n ≤ 1280 и сетки семейства II
  (QA B7: 1008 полушагов, max η_N = 3,6·10⁻¹⁶, запас 2,8·10³; Auditor: ≤ 3,2·10⁻¹⁶). Действие при превышении — по R4_NUMERICAL_SPEC 7: один шаг
  уточнения, иначе ERROR_LINEAR_SOLVE.
- η_N **не** является оценкой полной ошибки поля и не оценивает δ_f (R4_NUMERICAL_SPEC 5.2.1 (2)).

### D-048.3. Остановка

- **Кандидаты R2:** tol_∞ = 10⁻¹⁰, tol_E = 10⁻⁸, s_min = 3, s_max = 100; правило конфигурации tol_E ≥ 10·ε_floor^(N),
  ε_floor^(N) = 10u(max(n_x, n_y)/π)²·√N/(1 − γ_N√N) (модель первого порядка, R4_NUMERICAL_SPEC 6.3; не строгая граница), иначе ERROR_INPUT.
  Критерий стабилизации — по R2 (NUMERICAL_SPEC 11.3, п. 2): ε^∞ ≤ tol_∞ и ε^E ≤ tol_E на s − 1 и s при s ≥ s_min; s = s_max без него — MAX_HALF_STEPS.
- **Область подтверждения:** семейство I n = 40, 160, 640; N = 2, 3; r = 1/5, 1, 5 (QA B6, 18 расчётов: s_stop = 9…12 ≪ s_max;
  tol_E/(10ε_floor^(N)) = 12,5…3,9·10³; воспроизведено Auditor при n = 640). Перенос на другие r этой сетки и на семейство II — **не** утверждается.
- **n = 1280 — квалификация неполная:** выполнена одна адресная проверка Auditor (N = 3, r = 1/5, 5: s_stop = 12, плато ε^E ≈ 6·10⁻¹¹,
  tol_E/(10ε_floor^(N)) = 3,1); полной выборки по плану QA (критерий (ii) B6) нет. Применение при n = 1280 — только как исследовательское, с пометкой.
- **Автоматически не переносятся (NOT_QUALIFIED):** STAGNATED (θ_s ≥ 0,9 десять полушагов подряд); строгий режим
  tol_∞,strict = tol_∞/100, tol_E,strict = max(tol_E/100, 10ε_floor^(N)) (при n = 1280, N = 3 10ε_floor^(N) = 3,2·10⁻⁹ > tol_E/100 — режим ограничен снизу);
  аналог А-11 (S_stop ≤ 0,01·E_disc); диагностика хвоста T_s. Нужны отдельное решение и проверка.

### D-048.4. Статус стабилизации поля

Два варианта для выбора владельцем:

| Вариант | Формулировка | Оценка |
|---|---|---|
| **(а) — рекомендуется** | отдельный статус **PROVISIONAL_FIELD_STABILIZED** | не смешивается с принятым CONVERGED R2/R3 (D-035, D-043); однозначен в метаданных и отчётах |
| (б) | имя **CONVERGED** с обязательной пометкой **PROVISIONAL / NOT_QUALIFIED** и определением ниже | совместим с R2 по имени, но допускает смешение с квалифицированным CONVERGED принятых этапов |

**Определение (оба варианта):** выполнен критерий D-048.3 для **конечной дискретной задачи при фиксированном N** — стабилизация поля. Это **не**
сходимость к ω₀ (ВБ-19: ошибка метода при фиксированном N положительна; Q-025), **не** доказанная сходимость последовательности при s → ∞
(ЧВ-13) и **не** сертификация ранга (D-048.5). Статус допустим только если на **всех** полушагах пройдены защиты ранга D-048.5; пометку PROVISIONAL
снимать нельзя, пока не квалифицированы δ_f и критерий ранга. Отличается от RESEARCH_LIMIT_REACHED (D-047, доп. 1) и MAX_HALF_STEPS.
Эмпирическая опора (наблюдение, не гарантия): дрейф центра после остановки ≤ 2,6·10⁻⁶ от |w_h − ω₀|, энергии ≤ 2,5·10⁻¹⁵ (QA B6).

### D-048.5. Ранг и QR

- **K_RESEARCH = 10⁶** (D-047, доп. 1) — **временный критерий продолжения** последовательности через QR со статусом PROVISIONAL в обследованной
  области: ρ̂_N > K·u·κ_rep, σ_min(R_V·D_c) > K·u, K·u·κ_rep < 1 и прочие условия D-047, доп. 1. Запасы на реальных полях: ρ̂_N/(K·u·κ_rep) ≥ 2,0·10⁴,
  σ_set/(K·u) ≥ 1,2·10⁵, κ_rep = 1,000 (QA B9, Auditor). K не меняется для получения успешных прогонов.
- **NOT_QUALIFIED:** строгие c_d, c_rank, τ_set; накопленная δ_f (перенос по s — аналог Q-022); нормативный критерий S-2 (по K_RESEARCH **не
  присваивается**); константа сохранения поля при QR (наблюдение ≤ 42u при κ_rep = 1). Ранг этим решением **не сертифицируется**.
- **Что потребуется от Builder для продолжения через QR** (по отдельному заданию, разд. 4, Б-2): режим продолжения, включаемый явно и не
  меняющий умолчание NOT_QUALIFIED; порядок «полушаг → диагностика поля и набора → проверка защит → QR» (R4_NUMERICAL_SPEC 5.4.1); остановка до QR
  со статусами S-1, PROVISIONAL_RANK_GUARD_STOP, PROVISIONAL_SET_GUARD_STOP без уменьшения N, регуляризации и восстановления направлений;
  преобразование сопряжённого набора V_prev ← V_prevRᵀ и P_{s−1} по преобразованным массивам (оба значения — в журнал); остановка по D-048.3 со
  статусом D-048.4; маркировка PROVISIONAL / NOT_QUALIFIED каждого результата.

### D-048.6. DST

- **Основной путь — `fft`** (`scipy.fft.dst`, тип I) как инженерный выбор; c_DST — **NOT_QUALIFIED** (наблюдение: ≤ 2,34·u·log₂n·‖x‖, при n = 1280 ≤ 0,18·u·log₂n·‖x‖).
- **`dense` в текущем коде** (`sine_matrix`, аргумент ikπ/n без приведения) — только контроль при **n ≤ 40** (аудит, D-2; ошибка элемента до
  144·u√(2/n)); как эталон точности при n ≥ 160 не использовать.
- **Предложение для Builder (код пока не менять):** полное целочисленное приведение аргумента к [0, π/2] со знаком, а не только `% (2n)`:
  m = ik mod 2n; если m ≥ n: m ← m − n, знак −1; если 2m > n: m ← n − m; Ψ_ik = знак·√(2/n)·sin(πm/n). Тогда к `dense` применима заранее выведенная
  покомпонентная модель QA |fl(Ψ̂x) − Ψx| ≤ (7u + γ_{n−1}(1 + 7u))|Ψ||x| — **при её предпосылках** (стандартная модель IEEE, sin в пределах 1 ulp на
  [0, π/2], классическое произведение без быстрых схем); строгость 7u зависит от этих предпосылок. Вариант `% (2n)` устраняет рост ошибки, но модель 7u
  к нему не применима (только абсолютная оценка первого порядка ≈ 19,3u·√(2/n), вывод Auditor; аудит, разд. 3, п. 3, Н-7). После исправления и
  тестов QA — `dense` как контроль при n ≤ 1280; `fft` остаётся основным.

> эталонов: их применение для N = 2–3 определяется D-048.8 в указанной там области; вне её прежние ограничения D-046 и РВ4-8 сохраняются.

Если владелец не утверждает С-1/С-2 одновременно с D-048, пункт D-048.8 в части Навье-m и Π(ω₀) следует отложить (аудит, Н-6).

## 4. Поручения Builder после принятия D-048

Каждое — по отдельному заданию владельца (D-047, поэтапность); путь N = 1 и результаты `transform="fft"` побитово не меняются.

| № | Поручение | Связь |
|---|---|---|
| Б-1 | Контроллер остановки: tol_∞, tol_E, s_min, s_max, правило tol_E ≥ 10·ε_floor^(N) → ERROR_INPUT; MAX_HALF_STEPS; статус стабилизации по выбранному варианту D-048.4 с определением в метаданных; без STAGNATED и строгого режима до отдельного решения | D-048.3, D-048.4 |
| Б-2 | Явно включаемый режим продолжения через QR по защитам D-048.5 (K_RESEARCH фиксирован); порядок «диагностика → QR»; статусы S-1, PROVISIONAL_RANK_GUARD_STOP, PROVISIONAL_SET_GUARD_STOP; S-2 не присваивается; оба значения P_{s−1} в журнале | D-048.5 |
| Б-3 | Энергетический тест: разрешимость s = 2 на обязательных уровнях D-048.1 — запись «тест не выполнен» с объяснением при Q_2 < 10τ_2; s ≥ 3 — UNRESOLVED допустим; запись m_s | D-048.1 |
| Б-4 | Проверка η_N ≤ η_max = 10⁻¹²: один шаг уточнения, иначе ERROR_LINEAR_SOLVE | D-048.2 |
| Б-5 | (если владелец выберет) `dense`: полное целочисленное приведение аргумента к [0, π/2] со знаком; модульные тесты Builder: точные нули Ψ при ik ≡ 0 (mod n) и антисимметрия знака; совпадение с текущими элементами при ik < n/2 | D-048.6 |
| Б-6 | Маркировка результатов PROVISIONAL / NOT_QUALIFIED; запись ε_floor^(N), m_s, ρ̂_N, κ_rep, σ_min(R_VD_c), η_N в метаданных | все |

Builder не вводит нормативных констант по результатам своих тестов и не использует `src/kkvim_reference/` (D-047).

## 5. Критерии последующей проверки QA

Фиксируются **до** расчётов отдельным коммитом плана (как `7748877`); допуски — из априорных моделей, не по наблюдению; побитового равенства
не требовать, кроме оговорённых случаев (AGENTS.md, разд. 4).

| № | Проверка | Критерий |
|---|---|---|
| К-1 | регрессия | путь N = 1 и `transform="fft"` — побитово без изменений; R2/R3 тесты проходят |
| К-2 | остановка | на выборке D-048.3 (n = 40, 160, 640; r = 1/5, 1, 5; N = 2, 3): статус стабилизации при s_stop < s_max во всех расчётах; правило ε_floor^(N) отвергает недопустимые tol_E. Для расширения на n = 1280 — полная выборка по критерию (ii) B6 |
| К-3 | энергия | 0 нарушений E1/E2 при разрешённом тесте; m₂ ≥ 4 на всех обязательных уровнях D-048.1; запасы m_s в отчёте |
| К-4 | невязка | η_N ≤ η_max на всех полушагах; запас в отчёте |
| К-5 | ранг | ни одно поле известного неполного ранга не проходит защиту (как B4); S-2 не присваивается; запасы B9 в отчёте |
| К-6 | `dense` после Б-5 | элементы против эталона ≥ 50 знаков при n = 40, 160, 640, 1280 (таблица 2n значений; `mpmath` — вне обязательного CI) в модели QA 7u; импульсы e₁, e_mid, e_{n−1} при n = 1280 против `fft` и эталона в пределах модели; проверка предпосылки «sin ≤ 1 ulp» на платформах CI |
| К-7 | допуски | А4-3 по каждому коэффициенту ≤ 10⁻¹³ на n ≤ 640 с запасом в отчёте; А4-12 в области D-048.7 |
| К-8 | статус стабилизации | нигде не представлен как сходимость к ω₀ или сертификация ранга; метка PROVISIONAL присутствует |
| К-9 | независимость | эталоны не вызывают `kkvim` (D-028); сравнения — по полевым и инвариантным величинам |

## 6. Что этот проект не делает

Не принимает R4 и не разрешает новых этапов программирования сверх D-047; не меняет R2/R3, принятые спецификации, нормативы и код; не закрывает
Q-020, Q-022, Q-025; не утверждает уточнение С-1/С-2 к D-046; не вводит числовых значений вместо отсутствующих.
