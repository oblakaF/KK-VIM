## 6. Совместимость диапазона (часть В)

**Текущее различие** (полная таблица QA; «доля u» — отклонение min/max от 1/5 в единицах u):

Для всех принятых Навье пластин повторный вызов `swapped().swapped()` тоже принимается.

**Предлагаемое правило (проект D-038, не принято):**

min(a, b)/max(a, b) ≥ (1/5)(1 − 4u), u = 2⁻⁵³.

Проверка выполняется на точных рациональных значениях входных float, без вычисления округлённого отношения. Прототип QA (не внесён в
код):

```python
from fractions import Fraction
LOW = Fraction(1, 5) * (1 - 4 * Fraction(1, 2**53))
def in_r3_range(a, b):
    lo, hi = sorted((Fraction(a), Fraction(b)))   # a, b > 0, конечные float
    return lo >= LOW * hi
```

**Свойства прототипа (проверено QA):**
- на всех случаях таблицы решение совпадает с текущим Навье;
- правило симметрично: из 200 000 случайных пар у обеих границ ни одна не дала разного решения для (a, b) и (b, a). Поэтому `swapped()`
  никогда не отвергает принятую пластину — асимметрия D-037, п. 4, устраняется;
- отличие от текущей формулы Навье 0,2(1 − 4u) ≤ b/a ≤ 5(1 + 4u) только в верхней границе: 5/(1 − 4u) против 5(1 + 4u), разница
  ≈ 2·10⁻³¹ относительно. Ни один случай таблицы её не задевает. Формально это меняет формулировку D-037, п. 1, поэтому решение должно
  явно указать, что D-038 её заменяет для всех трёх эталонов.

**План внедрения при интеграции** (после утверждения D-038; отдельный коммит):
1. Один общий валидатор с этим правилом; каждый эталон вызывает его в конструкторе и функциях, принимающих отношение, с одинаковым текстом
   `ERROR_INPUT`:
   - Навье — `_ratio`, `_check_ratio`;
   - Парсеваль — `_check_r3_ratio`;
   - Леви — `levy_orientation`, `_check_ratio_l`, `levy_centre_wbar`.
2. Внутренние методы после проверки не перепроверяют округлённое r = fl(b/a) — как в поправке D-037 Навье.
3. **Леви:** при отношении чуть больше 5 (в полосе) r_L = fl(b_L/a_L) может оказаться > 5. Функции с аргументом r_L
   (`_check_ratio_l`, `levy_alpha_141`) должны принимать его по тому же правилу, а не строго ≤ 5.
4. Тесты: таблица выше в виде параметров; повторный `swapped()`; перебор ±12 ulp у 0,2·a и 5·a; совпадение решений трёх эталонов на одних и
   тех же парах.

## 7. Спецификация будущей П-12 (часть Г; правило — проект D-038, П-12 не выполняется)

**Мера.** Δ(P) = w_N(P) − w_L(P) в одной нормировке — **qa⁴/D** с опорной стороной a исходной пластины (Р-3), q = D = 1.

**Правило:**

$$|w_N-w_L|\le B_N+B_L+R_N+R_L .$$

| Величина | Определение | Статус |
|---|---|---|
| w_N | `NavierRectangle(a, b, q=1, D=1, nu=0.3)`, M_N = 2559 (D-037); узлы — `at_nodes`, точки — `at_points`; w̄ = `w_coef` | квалифицировано (D-037) |
| w_L | `levy_series_w` / `levy_series_w_grid`, M_L = 1131 (уровень по умолчанию, LEVY_FIELD_TOL, зафиксирован автором до сравнений); функции возвращают физический прогиб, перевод в qa⁴/D — делением на qa⁴/D исходной пластины | реализация — этот отчёт |
| B_N | строгая граница ЧВ-R2: 0,0021881·r²/M_N² qa⁴/D, равномерно по полю | подтверждена (D-036, D-037) |
| B_L | ЧВ-Л4: (4/π⁵)/(8M_L⁴)·(a_L/a)⁴ qa⁴/D, равномерно по полю | **ожидает независимого подтверждения Аудитором** |
| R_N | `rounding_w` результата Навье: узлы и точки — для своего способа вычисления | модель округления, не строгая оценка |
| R_L | `levy_field_bounds(...).rounding_model` | модель округления, не строгая оценка |

**Контрольный набор** (фиксируется до вычислений):
- **Пластины** — те же 10 r, что в квалификации Навье: (1; 0,2), (3; 1), (2; 1), (3; 2), (1; 1), (1; 1,4), (2; 3), (1; 2), (1; 3), (1; 5).
- **Сетка 41 × 41:** узлы x_i = ia/40, y_j = jb/40, i, j = 0…40, включая края.
- **Точки у краёв:** x ∈ {10⁻³a, 10⁻⁶a, 10⁻⁹a, a − 10⁻³a, a − 10⁻⁶a, a − 10⁻⁹a} при y ∈ {b/4, b/2, 3b/4}; симметрично y у краёв при
  x ∈ {a/4, a/2, 3a/4}. Итого 36 точек.
- **Центр** (a/2, b/2).
- Только прогиб. Моменты в П-12 R3 не входят (D-034, п. 3; Q-030).

**Вердикты (раздельный смысл):**
- **PASS** — неравенство выполнено во всех узлах и точках всех 10 пластин, оценка B_L подтверждена Аудитором, D-038 утверждено.
- **FAIL** — в какой-то точке |Δ| > B_N + B_L + R_N + R_L, **и** независимый пересчёт обоих усечённых рядов в повышенной точности (mpmath,
  ≥ 40 знаков) в этой точке подтверждает |Δ_hp| > B_N + B_L. Значит, сами строгие оценки или формулы (реализации) нарушены — это ошибка.
- **UNRESOLVED** — любой из случаев:
  - превышение есть, но в повышенной точности |Δ_hp| ≤ B_N + B_L, то есть превышение вызвано округлением сверх моделей R_N, R_L
    (модели неадекватны, ряды верны);
  - B_L не подтверждена Аудитором или D-038 не утверждено;
  - один из эталонов не принимает вход (правило диапазона не унифицировано);
  - пересчёт в повышенной точности невозможен.

**Не подбирать порог.** Известное диагностическое расхождение 4,9·10⁻¹⁶ qa⁴/D (r = 5; документ автора, 8.3) не используется для выбора
мер, уровней M или множителей. Правило сравнивает только с суммой зафиксированных оценок. При B_N = 1,3·10⁻¹¹…8,4·10⁻⁹ оно в первую
очередь ловит грубые ошибки; более тонкое сравнение требует отдельного решения владельца.

## 8. Неблокирующие замечания

- **Н-1.** При строгом режиме `np.seterr(all="raise")` функции поля падают на **underflow** exp(−2α) → 0 при больших α (воспроизведено при
  r_L = 5, M ≥ 1131). Результат 0 корректен. При настройках NumPy по умолчанию (underflow игнорируется) проблемы нет. Для устойчивости
  можно обернуть `_bracket` в `np.errstate(under="ignore")`; тест автора проверяет только overflow и invalid.
- **Н-2.** Граница ЧВ-Л4 почти достигается (до 0,87) у краёв x_L = 0, a_L. Для П-12 это не запас, а свойство оценки; уровень M_L = 1131 при
  этом оставляет B_L ≈ 10⁻¹⁵ qa_L⁴/D.
- **Н-3.** Модель округления центра (`_centre_rounding_model`) в 20–80 раз больше фактической ошибки (разд. 3) — консервативна.
