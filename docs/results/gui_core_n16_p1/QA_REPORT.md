## 4. Независимые функциональные проверки (`scripts/gui_check.py`)
**Как устроены сравнения:**
- **Путь GUI** — дочерний spawn-процесс `kkvim_gui.backend.process.SolverProcess`.
- **Эталоны:**
  - CLI `python -m kkvim …` в том же окружении;
  - прямой вызов библиотеки, написанный в QA.
- **Критерий** — побитовое равенство в одном окружении. Новых допусков нет.

| Случай | Статус | Роль / файл | Результат |
|---|---|---|---|

| S5 R4 N2 нормативный | NOT_QUALIFIED, s = 1 | research | = прямому `run_coupled` (Н3) |
| S6 SSSS N4 40×40, s = 2, явное исследование | RESEARCH_LIMIT_REACHED | research | поле побитово = `run-ssss --research-only` (Н2) |

| C5 то же, −q | COMPLETED | research | = CLI и опубликованному контролю D-068 `D_N5_neg` (D равны, 22 проверки true) и его прогону; w(−q) = −w(q), w̄ равны |
| C6 N6, a = 5, b = 1, 32×13, s = 2 | STOPPED_RANK_GUARD_UNCERTIFIED, s = 1 | diagnostic | RN5_UNRESOLVED; QR при s = 2 нет; поле s = 1; CLI exit 6; = прогону QA D-068 `C_pos` |
| C7 N4 33×9 s = 2 | STOPPED_RANK_GUARD_UNCERTIFIED, s = 1 | diagnostic | остановка до RN-5 и QR; CLI exit 6 |

**В каждом случае также проверено:**
- **Манифест схемы 2:** статус и причина решателя, научный статус, `requested_run_completed`, роль и файл поля, выполненное и запрошенное s, модель, маршрут, решения, ограничения.
- **`read_manifest`** читает манифест обратно.
- **`report.html`** согласован с манифестом.
- **Экспорт поля** побитово равен массиву решателя.
- **Повторный экспорт** в ту же папку отклонён (`FileExistsError`), первый пакет не изменён (SHA256).
- **CONVERGED** встречается только у R3; CCCC N1 никогда не получает роль accepted.

**Отказы до расчёта.** Возвращается `INPUT` из дочернего процесса, расчёт не выполняется:
- SSSS N5 без явного исследования (D-056.7);
- сетка, s и b/a вне исследованной области N = 4–6;
- CCCC s = 3 при N = 2–6, s = 9 при N = 1, сетка < 2N + 1, q = 0;
- N = 7; неизвестное закрепление.

**Форма.** Исследовательский выбор сбрасывается при смене N или закрепления: SSSS N4–6, режим R4, CCCC s = 2 → 1. Для CCCC N ≥ 2 s = 3 не предлагается.

**Схема 1.** Настоящие манифесты базового экспорта `306e85a` читаются так:

| Манифест схемы 1 | Роль после чтения |
|---|---|
| R3 CONVERGED | accepted |
| R3 MAX_HALF_STEPS | diagnostic (в схеме 1 был `field.csv` без роли) |
| R4 normative / research | research |

- `requested_run_completed = None` — значение не выдумывается.
- Схема 3 отклоняется.

**Демо-режим.** Все файлы получают суффикс `_TEST-DATA`; метка TEST DATA есть в манифесте и в отчёте.

## 6. Наблюдения (не блокируют)
- **Н1. `w_bar` в R4 вычисляет GUI.**
  - Формула `w·D/(q·a⁴)` существует ещё с `306e85a` и в diff P1 не входит.
  - CLI делит на `w_scale`, поэтому `w_bar` расходится не более чем на 1 ulp в 62 из 289 и 54 из 289 узлов. Поле w совпадает побитово.
  - Независимая QA `1d6af27` раньше принимала эту формулу.
- **Н2. SSSS N4–6: `w_max` в истории GUI — в единицах ячейки.**
  - Столбец подписан «max|w̄| (ячейка)», единица [1]. В `history.csv` CLI этот столбец в метрах.
  - Подписи верны, но представления различаются.
- **Н3. Нормативный режим R4 (D-047), только в GUI.**
  - NOT_QUALIFIED после s = 1 считается запрошенным концом: роль research, `field_research.csv`. Так описано в `KKVIM_BACKEND.md`.
  - В отчёте «s = 1 из запрошенных 100»: 100 — предел s, хотя нормативный режим всегда останавливается при s = 1. Подпись может ввести в заблуждение.
  - Решение о классификации — за владельцем или Integrator, если требуется.
- **Н4.** RN-5 консервативно отказывает в случае C6, где независимая RN-5 сертифицирует с запасом 1,03 (QA D-068). GUI лишь передаёт решение решателя.
- **Н5.** Ruff, правила по умолчанию: одно F401 (`CRASH` в `runs.py`) было и в базе. Новых нарушений нет; в базе было 2 нарушения, теперь 1.
- **Н6. Частичный пакет при сбое не проверялся.** `write_package` сначала пишет манифест, историю и поле, затем рисунки и отчёт. Сбой рендеринга оставил бы неполный пакет в новой папке; такой сценарий я не тестировал.
