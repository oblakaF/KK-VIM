# R4 — численная предквалификация N = 2–3: план и критерии (фиксация до расчётов)

Цели: G2, G3.3, G4. Роль: QA. База: `main` @ `ebd29154c248a68a998f386977c88febff7ee3ad` (PR #19–#21 объединены).

Этот документ фиксирует критерии, выборки, области и модели округления **до** численных проверок части B. Он коммитится отдельно, до запуска
расчётов. Результаты, отчёт и квалификационная матрица — в последующем коммите (`docs/R4_NUMERICAL_PREQUALIFICATION.qa-report.md`).
Критерии и выборки после этого коммита **не меняются**. Если какая-то проверка окажется невыполнимой, это записывается в отчёт как отклонение,
без замены критерия.

## 0. Правила

- Основания: D-045 (часть B MATH_SPEC), D-046 (РВ4-1…РВ4-8, правило 1/100, перечень NOT_QUALIFIED), D-047 и дополнение 1 (исследовательский
  режим), `docs/R4_NUMERICAL_SPEC.md` (разд. 4–7, 9–12); результаты группы B (PR #19) и интеграционной проверки (PR #21).
- Проверяется **фактический** решатель `kkvim.coupled_run.run_coupled` и его ядро (`kkvim.coupled*`) в `main`. Код Builder, спецификации, DECISIONS
  и нормативы не меняются.
- Пороги **не подбираются** по результатам. Числа предлагаются владельцу только тогда, когда у них есть априорное основание: принятая формула R2/R3,
  строгая оценка или принятое правило (1/100, резерв D-039). Наблюдённые максимумы — наблюдения, а не константы. Пункт без основания остаётся
  NOT_QUALIFIED с указанием причины.
- Конечная дискретная (спектральная) задача и неусечённый непрерывный метод не смешиваются; Q-022 и Q-025 остаются открытыми.
- Высокая точность — только временно (`uv run --with mpmath`), не в обязательном CI.
- Исследование группы B не повторяется; сетки расширяются только там, где это прямо нужно для критерия.

## 1. Часть A — квалификационная матрица (что разбирается)

Для каждого пункта перечня NOT_QUALIFIED D-046 и R4_NUMERICAL_SPEC разд. 11.1, 12 устанавливается:
- (а) что уже проверено (с источником);
- (б) чего не хватает;
- (в) какая проверка необходима;
- (г) можно ли предложить ограниченную область квалификации и на каком основании.

Пункты:
1. защита ранга: c_d, c_rank, τ_set, накопленная δ_f;
2. QR: константа сохранения поля, порядок «диагностика → QR»;
3. DST: c_DST (быстрый), плотная Ψ;
4. η_max;
5. энергетический тест: множитель 10, разрешимость, обязательные области, E1/E2;
6. tol^(N) и s_max (с s_min);
7. допуски А4-1…А4-14;
8. классы сеток ζ^(N);
9. независимые эталоны: ω₀ (Леви), s = 1 (Навье-m), s ≥ 2 (рекурсия Парсеваля), Π(ω₀).

Возможные статусы пункта:

| Статус | Значение |
|---|---|
| `PROPOSAL_LIMITED` | можно предложить владельцу ограниченную область и/или значение с априорным основанием |
| `VERIFIED_IMPLEMENTATION` | реализация проверена, норматив не нужен или уже определён |
| `OBSERVATION_ONLY` | есть только наблюдения, предложения нет |
| `NOT_QUALIFIED` | основания нет; причина указывается |

## 2. Часть B — проверки, выборки и критерии

Общие параметры: a = 1, b = r, q = D = 1, `research_mode=True`, `transform="fft"`, если не указано иное. u = 2⁻⁵³. Семейство I: n_x = n_y = n.
Семейство II: h_x = h_y, сетки цепочек группы B.

### B1. QA-δ1 — полевая δ_f(s) фактического решателя против точной дискретной последовательности

- **Эталон.** Та же дискретная задача в 40 знаках (`mpmath`): спектральная форма двумерного функционала Π_h (r4_spectral_control, п. 2–3).
  На каждом полушаге — ортонормирование заданного набора (Грам–Шмидт) и точные нормальные уравнения каждой моды. Поле не зависит от
  представления, поэтому сравниваются поля.
- **Выборка:** N = 2, 3; r = 1/5, 1, 5; n = 16 и 40 (семейство I); s = 1…20.
- **Измеряется:**
  - δ_f(s) = ‖W_B − W*‖₂/‖W*‖₂ (поле Builder против точного);
  - δ_step(s) — ошибка одного полушага Builder при точно заданном (сохранённом Builder) входном наборе.
- **Модель (априорная, первого порядка):** «не хуже линейного накопления» δ_f(s) ≤ Σ_{j≤s} δ_step(j). Проверяется как наблюдение.
- **Статус:** накопленная δ_f остаётся NOT_QUALIFIED при любом результате (аналог Q-022: строгого переноса нет).

### B2. QA-δ4 — строгая оценка ошибки модального решения на реальных M_k

- **Объект.** Для каждой моды k полушага: M_k = μ_k²A + 2μ_kB + C, b_k = F·(ψ_kᵀ𝟏) — это данные Builder (сохранённые A, B, C, F, вычисленные μ_k
  и нагрузка), v̂_k — решение Builder.
- **Строгая оценка** (R4_NUMERICAL_SPEC 5.2.1 (1)): ‖v_k − v̂_k‖₂ ≤ ‖r_k‖₂/(D·λ_min(M_k)), где r_k = b_k − D·M_k·v̂_k. r_k, λ_min и v_k вычисляются
  в 40 знаках из тех же double-данных.
- **Выборка:** все моды всех полушагов B1 (n = 16, 40) и n = 640 (N = 2, 3; r = 1; s = 1…4).
- **Критерий:** оценка ≥ фактической ошибки во **всех** модах (0 нарушений) ⇒ компонент (1) δ_f^шаг подтверждён на реальных матрицах
  (VERIFIED_IMPLEMENTATION). Отношение оценка/факт сообщается.

### B3. QA-δ2 — DST фактического ядра

- **Быстрый DST** (`sine_transform(..., "fft")`): расширение предквалификации (n ≤ 640) на n = 1280.
  - Входы: импульсы e₁, e_mid, e_{n−1}; гармоники k = 1, n/2, n − 1; нечётные синусы N = 3; модальные векторы реального полушага.
  - Эталон — Ψx в 40 знаках.
  - Измеряется c_obs = ‖ошибка‖₂/(u·log₂n·‖x‖₂).
  - **Статус c_DST — NOT_QUALIFIED при любом c_obs**: априорной модели для `scipy.fft` нет.
- **Плотная Ψ Builder** (`sine_matrix`, аргумент sin без целочисленного приведения): ошибка элемента при n = 40, 160, 640, 1280 против
  40-значного значения.
  - **Модель (априорная):** |fl(Ψ_ik) − Ψ_ik| ≤ √(2/n)·(2,35u·θ_ik + 2u) + 1,5u·|Ψ_ik|, θ_ik = ikπ/n — аргумент без приведения.
    Слагаемые: fl(π) и два округления аргумента; 1 ulp sin; масштаб.
  - **Критерий:** 0 нарушений модели ⇒ модель элемента подтверждена.
  - Строгая оценка QA (≤ 7u, с приведением аргумента) к пути Builder **не применяется**. Это фиксируется как замечание.

### B4. QA-δ3 — диагностика ранга фактического ядра на построенных факторах

- **Объект:** `kkvim.coupled_rank.rank_diagnostics` и защита `coupled_run._guards`.
- **Конструкции предквалификации:**
  - точные малые целые факторы с взаимным уничтожением, ранг произведения N − 1, K = 10⁰…10¹² — точный ранг подтверждается рациональной
    арифметикой;
  - поле точного ранга N − 1 в N членах с плотным T (тип Reviewer).
- **Критерии:**
  - (i) для каждой конструкции точного ранга N − 1 с K_RESEARCH·u·κ_rep < 1 защита `rank_ok` ложна (ρ̂_N ≤ K_RESEARCH·u·κ_rep);
  - (ii) отношение ρ̂_N/(u·κ_rep) сообщается как наблюдение c_d,obs (не константа).

  Нарушение (i) — дефект защиты.

### B5. Энергетический тест на фактическом решателе

- **Выборка:**
  - семейство I: все 10 контрольных r × N = 2, 3 × n = 160, 640, 1280;
  - семейство II: верхние уровни цепочек группы B — (1600, 320), (960, 320), (640, 320), (320, 640), (320, 960), (320, 1600);
  - s = 2, 3, 4.
- **Измеряются:** m_s = Q_s/(10τ_s^(N)), γ_s, статус E1/E2 Builder.
- **Критерии (априорные; форма и множитель 10 — R2/D-039, не подбираются):**
  - (i) нарушение E1/E2 при разрешённом тесте (m_s ≥ 1) — FAIL, требует анализа;
  - (ii) предложение «обязательная область s» на уровне сетки — только если m_s ≥ 4 для **всех** выборочных r на этом уровне. Это резерв D-039
    «около одного удвоения». Иначе s на этом уровне — необязательная область (UNRESOLVED допустим).
- **Множитель 10:** NOT_QUALIFIED. Основания его менять нет, предлагается сохранить форму R2 как кандидат.

### B6. Критерии остановки: tol^(N), s_max, s_min

- **Выборка:** N = 2, 3; r = 1/5, 1, 5; n = 40, 160, 640 (семейство I); s = 1…40; ε_s^∞, ε_s^E — из журнала Builder.
- **Априорная модель пола (R2, NUMERICAL_SPEC 11.2, с κ_W разд. 6.3):** ε_floor^(N) = 10u(max n/π)²·κ_W.
- **Кандидаты R2:** tol_∞ = 10⁻¹⁰, tol_E = 10⁻⁸, s_max = 100, s_min = 3, правило конфигурации tol_E ≥ 10·ε_floor^(N).
- **Критерии переноса (априорные):**
  - (i) tol_E ≥ 10·ε_floor^(N) на всех сетках области (как правило R2);
  - (ii) правило CONVERGED R2 — ε^∞ ≤ tol_∞ и ε^E ≤ tol_E для s − 1 и s, s ≥ s_min — достигается при s_stop < s_max во **всех** выборочных расчётах;
  - (iii) после s_stop сообщается дрейф до s = 40: |δ_c(40) − δ_c(s_stop)|/|δ_c(40)| и |Π_h(40) − Π_h(s_stop)|/|Π_h(40)|. Это информация для владельца,
    а не подгонка.
- Перенос предлагается (`PROPOSAL_LIMITED`) только при выполнении (i) и (ii).

### B7. η_N

- **Выборка:** все полушаги B5 и B6.
- **Кандидат R2:** η_max = 10⁻¹².
- **Критерий:** max η_N ≤ 10⁻¹²/100 (запас 100, по образцу правила 1/100) ⇒ перенос предлагается как контроль реализации на исследованной
  области. Иначе — NOT_QUALIFIED.

### B8. Мера ζ^(N)

- **Определение** (R4_NUMERICAL_SPEC 4.4): κ_s^(N) = λ_max(A⁻¹C)^{1/4} для заданного набора каждого полушага; ζ^(N) = max_s(κ_s^(N)·h) по полушагам
  и направлениям (h — шаг сетки заданного набора), s = 1…3. Вычисляется на наборах фактического решателя.
- **Выборка:** N = 2, 3; r = 1/5, 1, 5; семейство I n = 20…1280; семейство II — уровни цепочек группы B.
- **Классы (R3_NUMERICAL_SPEC 6.3, D-039):** Q — ζ ≤ ζ_A5^{R2}(80) = 0,039420; A — ζ ≤ ζ_A5^{R2}(20) = 0,157681; иначе G.
- **Сопоставление** с наблюдённым порядком p группы B (`richardson.csv`, окно [1,9; 2,1]). Если p в окне на парах, где ζ^(N) — класс G, мера ζ^(N)
  консервативна. Это сообщается как наблюдение; классы не меняются.

### B9. Защиты и запасы ранга на реальных полях

- **Из B5/B6:** min ρ̂_N/(u·κ_rep), min σ_min(R_VD_c)/u, сравнение с K_RESEARCH = 10⁶ и с наблюдённой δ_f (B1).
- **Критерий для предложения ограниченной области различимости ранга:** ρ̂_N ≥ 100·2ε_obs с ε_obs = c_d,obs·u·κ_rep + δ_f,obs (B1, B4). Запас 100 —
  правило 1/100.
- **Статус:** даже при выполнении критерия ранг **не сертифицируется**: δ_f с накоплением не оценена строго (Q-022). Предложение — только
  ограниченная исследовательская область (`PROPOSAL_LIMITED` с оговоркой PROVISIONAL).

### B10. А4-1…А4-14 и эталоны

- **Новых расчётов нет:** сводка по существующим проверкам — сравнение контроллера PR #16, интеграционная проверка PR #21, группа B PR #19.
  Добавляются данные B1–B9, где они относятся к пункту.
- Для пунктов с кандидатным допуском спецификации (А4-3 ≤ 10⁻¹³, А4-12 ≤ 10⁻¹²/10⁻¹¹) сообщается фактический запас. Допуски не меняются.
