## 4. Представление строгих границ (QA-1)

### 4.1. Что было

В `scripts/r4_n23/expected/certificate_*.txt` и в табл. 3.4 `R4_N23_SCIENTIFIC_CLOSURE.md` границы печатались форматами `%.4g`, `%.4f`
с округлением к ближайшему (Н-1 рецензии; QA-1). Подтверждено: в 152 строках непрерывного и дискретного режимов «μ ≤ p» округлено вниз
в **70** строках, «d(N)_low/err2_up ≥ p» округлено вверх в **95** строках. Отклонение — одна единица последнего знака.

### 4.2. Что исправлено (только печать)

- **Причина — печать, а не алгоритм.** μ = (hi(E2)/lo(D_{N−1}))^{1/2}, отношение d_N^{low}/err₂^{up} = (lo(D_N)/hi(E2))^{1/2} и err/‖ω₀‖ = hi(…)/lo(‖ω₀‖)
  вычисляются из правильных концов интервалов. Изменена только функция печати `report` в `n23_rank_certificate.py`: новая `outward`
  округляет наружу — «≤» вверх, «≥» вниз — до тех же знаков. Поправочный множитель 1 ± 2⁻²⁰⁰ перекрывает округление к ближайшему в `mp`
  (относительная ошибка ~2⁻²⁵⁰), а проверка внутри функции гарантирует, что напечатанные цифры равны направленно округлённому значению.
- **Эталонные выходы** пересчитаны тем же кодом (Python 3.14.8, NumPy 2.5.4, mpmath 1.4.1; continuous ≈ 30 с, discrete ≈ 2 мин,
  dense ≈ 10 мин). Построчное сравнение со старыми выходами:

  | Режим | строк | изменено: err1 / err2 / μ / нижняя граница | изменение | прочие поля |
  |---|---|---|---|---|
  | `continuous` | 20 | 11 / 11 / 11 / 14 | ровно одна единица последнего знака наружу | побайтно те же |
  | `discrete` | 132 | — / 63 / 59 / 81 | то же | те же |
  | `dense` | 402 | 212 / 204 / 203 / 191 | то же | те же |

  μ: 11 + 59 = **70**, нижняя граница: 14 + 81 = **95** — совпадает с QA-1. `ALL CERTIFIED` во всех трёх режимах; столбцы `j_cert`,
  `CERTIFIED`, `d(N-1)/|w0|`, `d(N)/|w0|` не изменились.
- **Независимая проверка направлений** — код QA (`scripts/r4_n23_qualification.py rank`, Python 3.13.15, вывод вне репозитория) на новых
  выходах: **152/152** «μ ≤» — верхние границы, **152/152** «≥» — нижние (прежде 82 и 57). Тот же прогон воспроизвёл `rank_checks.csv` QA (21 строка, все поля совпадают). Направления 402 строк `dense` подтверждены построчным сравнением (каждое изменение — одна единица наружу) и проверкой внутри `outward`; независимого пересчёта dense нет.
- **Документ Literature:** табл. 3.4 (20 строк) и таблица сеток (7 строк) пересобраны программой из новых выходов (25 строк изменились);
  диапазоны «0,25…0,92» → «0,24…0,91» (вердикт, п. 4), «1,09…1,45» → «1,10…1,45» и «1,37…4,05» → «1,38…4,05» (разд. 4.4),
  «0,69…0,92 … 0,25…0,73» → «0,69…0,91 … 0,24…0,72» (разд. 4.6), «max μ = 0,0864 (N = 2)» → «0,0865» (разд. 3.5); под табл. 3.4 — пометка о печати. Формулировки, доказательства,

### 4.3. Дефект, который печатью не исправляется (И-1)

Столбцы `d(N-1)/|w0| >=` и `d(N)/|w0| >=` (выходы `expected/`, табл. 3.4) делят **нижнюю** оценку d на **нижнюю** оценку ‖ω₀‖
(`norm = sqrt(lo(c0·W0))`, W0 — частичная сумма блока). Частное нижней границей d/‖ω₀‖ не является, знак «≥» для этих столбцов
**не гарантирован**. Исправить это можно только изменением вычисления — нужна строгая **верхняя** оценка ‖ω₀‖ (хвост ряда) — либо
отказом от знака «≥». По заданию эта часть **остановлена**: значения и подписи столбцов оставлены как есть, добавлена только пометка.
На μ, на d_N^{low}/err₂^{up}, на сертификаты и на N23-4/N23-8 этот дефект **не влияет**: эти величины от ‖ω₀‖ не зависят (N23, разд. 3.4).
Исправление — по отдельному заданию Literature.

## 5. QA-3: мера E_∞ на выборке 65 × 65

| Вопрос задания | Ответ | Основание |
|---|---|---|
| Глобальная оценка через Γ*? | **Да.** max\|w_s − w′_s\| ≤ Γ*·E_s ≤ Γ*·Ê′_s при Γ* = Γ(c): для полей из нечётных мод φ_mn(c)² = 1, а φ_mn(x)² ≤ 1, поэтому sup_x Γ(x) = Γ(c). Γ(c)² — сумма по нечётным модам ≤ M в шарах arb (320 бит) плюс строгий хвост; в правило входит верхний конец шара | Q22-6, п. 1 и З-3 (принято, `b2b2daa`); `ArbProblem.__init__`, `run_combine` (`R_E_inf = β_∞ + Γ(c)^{up}·B_tr/(E_∞·(1 − β_∞))`) |
| Обоснована нечётная модальная симметрия? | **Да, в сертифицированных ячейках.** ВБ-22, п. 6 сохраняет симметрию, **пока** rank w⁽ˢ⁾ = N; N23-4 доказывает полный ранг на всех s для (а) и (б) (M = 4001 прямо: QA, разд. 6). Усечённая рекурсия по построению содержит только нечётные моды. Разность w_s − w′_s — из нечётных мод | MATH_SPEC ВБ-22 п. 6 (D-045); N23-4 |
| Не подменён ли максимум на сетке максимумом по области? | **Нет.** Оценка Γ*·Ê′ ограничивает sup по всей области и тем более max по узлам: \|E_∞(w_s) − E_∞(w′_s)\| ≤ max_узлы\|w_s − w′_s\|/max\|ω₀\| ≤ Γ*Ê′/max\|ω₀\|. - **И-3.** Отчёт QA, табл. 3.1, строка «N = 2, e_rel, сверху»: «max R_U = 0,000689 на девяти r» неверно. По `matrix.csv` наибольшее значение

  Это учтено в решениях 3 и 4.
- **И-6. Тяжёлый тест сведения зависит от концов строк checkout.** `test_combine_reproduces_the_committed_tables` сравнивает байты
  сгенерированных файлов с файлами рабочей копии. `.gitattributes` не фиксирует `eol` для `docs/results/`, поэтому при Git for Windows
  (`core.autocrlf=true`) новый checkout содержит CRLF, а `combine` пишет `matrix.csv` и `smax.csv` с LF (`summary.json` — с CRLF через
  `write_text`). Тест падает на `matrix.csv` (первое отличие — `
` против `
`). У QA он проходил, потому что файлы в его рабочей копии
  были записаны самим скриптом. Прямое сравнение с блобами git: `matrix.csv` и `smax.csv` — побайтно равны, `summary.json` — равен после
  CRLF → LF (3.13 и 3.14). В штатном CI тест пропускается. Исправление (сравнение с нормализацией концов строк или правило `eol` для
  `docs/results/`) — по отдельному заданию QA: задание Integrator разрешает только правку печати границ.
- **И-5.** μ и d_N^{low}/err₂^{up} вычисляются в `mp` из интервальных концов, а не в `iv` (рецензия, разд. 4, п. 3). При запасе μ ≤ 0,265 < 1 это
  на сертификат не влияет; печать теперь это перекрывает (разд. 4.2).
