## 2. Что и чем сравнивается

| Сторона | Что вычисляет | Независимость |
|---|---|---|
| Builder | `run_coupled(..., research_mode=True)`: модальный ЧФ-3 (Холецкий M_k = μ_k²A + 2μ_kB + C), DST dense/fft, QR с сопряжённым преобразованием | проверяемый код |

**Допуски** — модели первого порядка, зафиксированные до сравнения из величин обусловленности и округления с единичными
константами (не подогнаны). Для поля на шаге s:

ε(s) = Σ_{j ≤ s} u·[cond(M)_j·(1 + (2n_fix/π)²) + cond_LS,j² + log₂ n_solve + κ_rep,j·√N].

Для σ_k — неравенство Вейля (|Δσ_k| ≤ ‖ΔW‖₂ + округление диагностики); для энергии —
|Π(w₁) − Π(w₂)| ≤ (‖w‖_a + ‖ω_h‖_a)‖w₁ − w₂‖_a + R(w₁) + R(w₂). «Согласовано» = «внутри модели»; это не доказанная оценка
и не нормативный PASS.

### 4.2. Дефект C-1: защиты не применяются на последнем полушаге

В `src/kkvim/coupled_run.py` (Builder, `4c86c1f`) цикл полушага имеет порядок:

```
guards = _guards(rank) if research_mode else None
... ERROR_NONFINITE ...
if s == half_steps:
    return stop(RESEARCH_LIMIT_REACHED if research_mode else HALF_STEP_LIMIT_REACHED, ...)   # (1)
if not research_mode: ... NOT_QUALIFIED
if not (guards.applicable and guards.rank_ok): ... PROVISIONAL_RANK_GUARD_STOP           # (2)
if not guards.set_ok: ... PROVISIONAL_SET_GUARD_STOP                                     # (3)
ortho = orthogonalize_received(...)
```

Проверка предела (1) стоит **до** защит (2), (3). Если на последнем полушаге ранг неразличим (ρ_N ≤ K·u·κ_rep) или
σ_min(R_V D_c) ≤ K·u, расчёт возвращает `RESEARCH_LIMIT_REACHED`. Читатель журнала не может отличить такой исход
от прохождения защит. Значения `guards` в записи журнала верны (rank_ok = False), но итоговый статус расчёта вводит
в заблуждение. R4_NUMERICAL_SPEC 5.4.1 и РВ4-2/РВ4-4 требуют, чтобы диагностика предшествовала любому дальнейшему действию
и чтобы неразличимый ранг был виден в статусе.

**Воспроизведение (только в тесте):**
- естественного срабатывания защит при N = 2–3 нет (разд. 6.3), поэтому в тесте подставлен `cr.K_RESEARCH = 10¹³`
  (monkeypatch, код Builder не меняется);
- запуск: N = 3, (40,40), `half_steps = 1`;
- результат: `log.guards.rank_ok = False`, статус `RESEARCH_LIMIT_REACHED`;
- тест `test_guard_failure_on_the_last_half_step_is_reported` фиксирует это как **xfail «DEFECT C-1»**: это не PASS
  и не skip. После исправления тест начнёт проходить без изменений.

**Минимальное исправление (предложение; код Builder не изменён):** в исследовательском режиме проверять защиты до предела.

```
if research_mode and not (guards.applicable and guards.rank_ok): return stop(PROVISIONAL_RANK_GUARD_STOP, ...)
if research_mode and not guards.set_ok:                          return stop(PROVISIONAL_SET_GUARD_STOP, ...)
if s == half_steps: return stop(RESEARCH_LIMIT_REACHED if research_mode else HALF_STEP_LIMIT_REACHED, ...)
```

Эквивалентный вариант: возвращать `RESEARCH_LIMIT_REACHED` только при `guards.passed`, иначе — статус защиты.

Поле последнего полушага в обоих вариантах остаётся выходом расчёта; меняется только статус. Нормативный режим
(guards = None) не затрагивается. Тест Builder на этот случай нужно добавить в ветку Builder.

### 4.3. Наблюдение O-1 (не дефект контроллера)

Ядро `solve_coupled_halfstep` решает моды через нормальные уравнения (M_k содержит A = Gram заданного набора). Для
неортогонального заданного набора X₀T ошибка поля растёт как u·cond(T)² (разд. 5.2). Успешный Холецкий не подтверждает
точность. В контроллере заданный набор всегда ортонормирован QR (или это нечётные синусы при s = 1), поэтому O-1 вне рабочего
цикла не проявляется. Оно ограничивает применение ядра вне контроллера и входит в вопрос о c_d/δ_f (разд. 7).

### 5.3. Бюджет δ_f: что можно и чего нельзя оценить строго

Строгий бюджет δ_f **не построен**.

| Компонента | Состояние |
|---|---|
| сборка A, B, C, F (суммы произведений) | оценима строго в модели IEEE (γ_n-оценки сумм); наблюдение ≤ 4,3·10⁻¹⁶ |
| модальное решение (Холецкий M_k) | нужна обратная ошибка Холецкого и константа перехода к ошибке поля: в `references/` первоисточника нет — **NOT_VERIFIED**; наблюдение ≤ 1,3·10⁻¹⁵ |
| DST dense | оценка условная (элемент Ψ̂ — ≤ 7u при проверенной предпосылке sin, отчёт префквалификации Р-8) |
| DST fft (`scipy.fft.dst`) | константа c_DST — **NOT_VERIFIED** (нет модели округления реализации) |
| QR и сопряжённое преобразование | константа сохранения поля — **NOT_VERIFIED**; наблюдение ≤ 36u (Builder), ≤ 2,6·10⁻¹⁶ (высокая точность) |
| перенос ошибки между полушагами | не доказан (Q-022); наблюдение — без накопления при s ≤ 10 |
| c_d | **не выводится** из эмпирического максимума |

Неизвестные компоненты: обратная ошибка Холецкого для M_k с её обусловленностью, c_DST для fft, константа QR, оператор
переноса ошибки по s. Значения c_d и δ_f из наблюдённых максимумов **не объявляются**.
