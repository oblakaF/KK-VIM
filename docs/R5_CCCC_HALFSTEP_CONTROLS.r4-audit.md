## 2. Математическая проверка Р-4

### 2.1. `norm_lower`

ŝ — конечный вектор double. Сумма квадратов ‖ŝ‖₂² = Σ Fraction(ŝᵢ)² = P/Q вычисляется точно (P, Q ≥ 1 при ŝ ≠ 0). Пусть z = PQ·4⁶⁴. Тогда
√(P/Q) = √z/(Q·2⁶⁴), и isqrt(z) ≤ √z, поэтому L = isqrt(z)/(Q·2⁶⁴) ≤ ‖ŝ‖₂. Недобор: √z − isqrt(z) < 1, значит
(‖ŝ‖₂ − L)/‖ŝ‖₂ < 1/√z ≤ 2⁻⁶⁴, так как PQ ≥ 1. При ŝ = 0 L = 0.

Реализация совпадает с доказательством:
- `Fraction(float(x))` точен для double;
- переполнения и исчезновения порядка нет, вычисление целочисленное;
- `np.asarray(s, dtype=float).ravel()` даёт евклидову норму всего набора — ту же, что в `error_bound`.

Тест QA проверяет недобор 2⁻⁶⁰, аудит — 2⁻⁶³.

### 2.2. `relative_bounds`

Предпосылка: b ≥ ‖ŝ − s\*‖₂, где b = `error_bound(hs, ŝ, λ_low)` для **того же** ŝ. Во всех вызовах скрипта это так, включая R-H с
нормировкой на собственный ŝ_H.

1. **К вычисленному набору.** При L > 0: ‖ŝ − s\*‖₂/‖ŝ‖₂ ≤ b/‖ŝ‖₂ ≤ b/L.
2. **К точному решению.** При L > b: ‖s\*‖₂ ≥ ‖ŝ‖₂ − ‖ŝ − s\*‖₂ ≥ L − b > 0, поэтому ‖ŝ − s\*‖₂/‖s\*‖₂ ≤ b/(L − b).
3. **Различие нормировок.** b/(L − b) ≥ b/L всегда. При малом b/L разница второго порядка, при ε = 10⁻⁶ — 0,2406 против 0,1939.
4. **Строгость вычисления.** Проверки L > 0 и L > b — в Fraction; B = Fraction(b) точно; частное точное, перевод `_float_up` вверх
   (принят в `4f92c82`). При переполнении — inf, тривиально верная граница. При исчезновении порядка — 5·10⁻³²⁴ вверх.
5. **Отказ.** b = inf, L = 0 или L ≤ b дают `None` → `UNRESOLVED` в CSV; число не подставляется. Вход: b не float, nan, b < 0 →
   `ValueError`.

**Проверка аудитора против точного s\*.** Своё точное решение: K по определениям (разд. 5), ленточное LDLᵀ в Fraction без выбора
главного элемента. Положительные опорные элементы одновременно доказывают, что K положительно определена.

| Набор | Строки | Результат |
|---|---|---|
| `chain.csv`, R-AC без уточнения и с уточнением; R-H при n ≤ 32 | 30 строк (N = 1–3, обе ориентации, 16 × 16 … 128 × 256), 72 набора; `*_hex` воспроизведены | ‖ŝ − s\*‖² ≤ b², ≤ (b/L)²‖ŝ‖², ≤ (b/(L − b))²‖s\*‖² — точно; λ_min(K) > λ_low (LDLᵀ для K − λ_low·I) |
| `ill_conditioned.csv`, ε = 10⁻², 10⁻⁴, 10⁻⁶ | 3 | то же. При ε = 10⁻⁶: b = 133,5 при фактической ошибке 1,7·10⁻⁶; b/L = 0,1939 и b/(L − b) = 0,2406 при фактических 2,4·10⁻⁹. Граница очень пессимистична, но верна |
| R-H при ε = 10⁻⁶ (в CSV нет) | 1 | фактическая ошибка 0,254 к ŝ_H и 0,336 к s\*; границы 0,694 и 2,263 выполняются. Значит, «разность наборов R-H − R-AC = 0,336» в CSV — ошибка самого R-H, как и пишет `address-fix.md`, разд. 3 |
| ε = 10⁻⁸ | 1 | CSV: UNRESOLVED. Точная K положительно определена (минимальный опорный элемент 4,2·10⁻¹¹) — пометка в CSV подтверждена |

Фактическая ошибка / b по всем 72 наборам цепочки — 1,2·10⁻⁷…0,42, то есть всегда < 1. Граница бывает очень пессимистичной; это свойство ‖r‖₂/λ_low, а не дефект.

### 2.3. Набор S и поле W

## 5. М-1, М-3, М-4

- **М-1.** `isinstance(lambda_low, float)`, конечность и положительность; затем `Fraction(lambda_low)` — точно. int 2⁵³ + 3 и 10⁴⁰⁰
  отвергаются, `ValueError` вместо `OverflowError`. `np.float64` — подкласс float; `np.float32` отвергается.
- **М-3.** Пересчёт аудитора множителей (1 + δ)^{±1} относительно точного h = l/n:

  | Шаг | Итог |
  |---|---|
  | h_f | 1 |
  | L = (…)/h_f² | 2 + 2 + 1 = 5 |
  | L·L, 3 слагаемых | 5 + 5 + 1 + 2 = 13 |
  | угол 2/h_f⁴ | 4 + 2 + 1 = 7; сложение — 14 |
  | D4_f G, 5 слагаемых | 19 |
  | Gᵀ(·), n_f − 1 слагаемых | n_f + 18 |
  | ·h_f, член C | n_f + 20 |
  | A ⊗ D4_s; B ⊗ L_s | n_f + 16; n_f + 15 |
  | две суммы и D | **n_f + 23** |

  Совпадает с исправленным текстом. γ(2n_f + 32) ≥ γ(n_f + 23) при n_f ≥ 0. Допущение о pow (≤ 1 ulp) записано явно.
- **М-4.** Собственная K аудитора строилась так:
  - A = h_f GᵀG, B = −h_f GᵀL_fG, C = h_f GᵀD4_fG, F = q·h_f·Gᵀ𝟏;
  - D4 = L·L + E₂ произведением матриц;
  - K = D[A ⊗ D4_s − 2B ⊗ L_s + C ⊗ I] в своей индексации.

  Она точно совпала с лентой сертификата (своя перестановка узел-член) и со столбцами оператора R-HP, K e_c = r(0) − r(e_c), в 24 случаях
  из 24. Тест QA М-4 делает то же на 6 случаях и правильно сравнивает `exact_dense` с K по определению.
