### 2.1. И-1: логика статусов

`continuous_status(s, meas_status, budget_s1, diagnostic, measured)`:
- **s = 1** → `status(budget_s1, measured)`: RESOLVED при budget_s1 ≤ 1/100·|measured|, иначе UNRESOLVED. Значение `meas_status` при s = 1 не используется, но budget_s1 уже содержит бюджет измерения (строгая часть и модель).
- **s ≥ 2** → PROVISIONAL, если `meas_status == RESOLVED` и `diagnostic` ≤ 1/100; во всех остальных случаях UNRESOLVED. **RESOLVED при s ≥ 2 недостижим.**

**Проверка достаточности хвоста s = 1.** Неусечённый первый полушаг — m-усечённая сумма Навье с полной суммой по n (ВБ-23).
- Энергия. Истинная err² лежит в [block, block + out_ht], то есть отличается от середины `err2_direct` не более чем на ½·out_ht. Для пути E Π отличается не более чем на ½·out_ht. Код прибавляет out_ht (путь D, сверх `strict_D` = ½·out_ht) и ½·out_ht (путь E): **достаточно, с запасом**.
- δ_c и E_∞: прибавлен поточечный хвост `navier_m_tail_bound(modes_L, M)` — строгая оценка (R4_NUMERICAL_SPEC 9.1 (б)): **достаточно**.
- Модельные (нестрогие) части округления входят и в s = 1. Это согласуется с формулировкой «RESOLVED на уровне измерения» (отчёт, разд. 2.3; разд. 10, п. 2).

**Покрытие тестом.** `test_measurement_status_and_continuous_method_status_are_separate` проверяет все пять ветвей:
- s = 1: RESOLVED и UNRESOLVED;
- s = 2: PROVISIONAL; UNRESOLVED из-за диагностики; UNRESOLVED из-за измерения.

Тест также проверяет расчёт N = 3, M = 401. Тест `test_master_and_tables_are_consistent_with_the_sources` проверяет, что в `master.csv` при s ≥ 2 нет RESOLVED у `status_cont_*`.

**Фактическое распределение** (`continuous.csv`, 800 строк × 4 меры: e_rel по пути D, e_rel по пути E, δ_c, E_∞; подсчитано рецензентом):
