## 1. Независимый эталон D2

### 1.1. Определение и независимость

D2 — решение 𝒜 vec(w) = (q/D)·𝟏 с 13-точечной схемой: (δ⁴ₓ + 2δ²ₓδ²ᵧ + δ⁴ᵧ)w = q/D во внутренних узлах, w = 0 на границе,
∂w/∂n = 0 через фиктивный узел w₋₁ = w₁ (подготовка, разд. 9.3; рецензия `62db9f2`, разд. 5).

Требования к реализации QA (`kkvim_reference`, отдельный модуль):
- не импортирует `kkvim` (существующий `tests/test_package_independence.py`);
- не использует кронекерову формулу проекта как способ сборки. Основная сборка — **поузловая** по шаблону с явным фиктивным узлом;
- кронекерова формула 𝒜 = D4ₓ⊗I + 2Lₓ⊗L_y + I⊗D4_y и гессиан Π_h^C строятся отдельными функциями QA только как **контрольные**
  сборки (D2-2, D2-4);
- решение — разреженная прямая факторизация с обязательным уточнением по невязке в повышенной точности (§1.4).

**D2 независим по коду, но не по дискретизации:** при основе Π_h^C D1 = D2. Ошибку сетки проверяют только A и B (`62db9f2`, 5.4 (б)).

### 1.3. Собственный вывод QA для D2-6

D4 = L² + E₂, E₂ ⪰ 0. Тогда

𝒜 = (Lₓ⊗I + I⊗L_y)² + E₂ₓ⊗I + I⊗E₂ᵧ ⪰ (Lₓ⊗I + I⊗L_y)².

Собственные значения правой части — (λᵢ(Lₓ) + λⱼ(L_y))², все λ < 0. Минимум (μ₁ₓ + μ₁ᵧ)². Верхняя граница —
‖D4‖₂ ≤ ‖D4‖∞ ≤ 16/h⁴ (равенство при n ≥ 6), ‖L‖₂ ≤ 4/h².

Проверено при подготовке плана на трёх малых сетках с hₓ ≠ h_y: λ_min/граница = 3,1–3,8; λ_max/граница = 0,95. Это **собственный вывод QA**.
*(АП-10, §12: сверен Reviewer `403755b`, разд. 4.1 — «вывод доказан», П-9 со стороны Reviewer закрыт; там же λ_min/граница = 3,22–4,65
на семи сетках.)*

### 1.3а. Модель ошибки вычисленного λ_min (АП-6)

Критерий D2-6 сравнивает **вычисленное** λ̂_min с доказанной границей. Ошибка λ̂_min определяется не относительной точностью, а нормой
матрицы: для обратно устойчивого симметричного собственного решателя |λ̂ − λ| ≤ p(m)·u·‖𝒜‖₂, m — размер, а относительная ошибка
λ̂_min ~ u·λ_max/λ_min растёт как n⁴ (рецензия `403755b`: 1,8·10⁻¹² уже при 24 × 24). Множитель (1 − 10⁻¹²) первой редакции из модели
не следует и заменён.

| Способ | e_λ | Статус |
|---|---|---|
| плотный `eigvalsh` (малые сетки) | c_λ·m·u·λ̂_max, где λ̂_max — вычисленное или верхняя граница §1.3 | форма — стандартная модель обратной устойчивости; c_λ — **инженерный кандидат** [ИНЖ], фиксируется владельцем до сравнения (Р-6) |
| shift-invert (средние сетки) | ‖𝒜v̂ − λ̂v̂‖₂/‖v̂‖₂ (для симметричной матрицы в этой окрестности λ̂ есть собственное значение) + c_λ·m·u·λ̂_max (округление самой невязки) | то же; дополнительно — вычисленная невязка пары |

c_λ не выводится из наблюдённого запаса ≥ 3,1. Положительная определённость на всех сетках доказана (§1.3); D2-6 проверяет код сборки,
а не утверждение о SPD.

### 1.4. Точность решения D2 (оценка собственной ошибки эталона)

Проба §6: факторизация SuperLU в двойной точности без уточнения даёт для случайной правой части ошибку до 8,7·10⁻⁹ (r = 5, n = 256) и
до 4,6·10⁻⁸ (r = 1, 2, n = 512). Это того же порядка, что разброс R₂ по перекрывающимся тройкам внешних данных — до **1,9·10⁻⁸ отн.**
(r = 1: 2,36·10⁻¹¹ абс., 1,9·10⁻⁸ отн.; r = 2, 3, 5: 2,5·10⁻⁹, 2,9·10⁻⁹, 3,1·10⁻⁹ отн.) *(ФА-6, §13)* — и зависимости от модели разложения (до 3·10⁻⁸ отн. при r = 1)
*(АП-2, §12: в первой редакции «≤ 3·10⁻⁹ отн.» — неверно в 10 раз при r = 1)*. Для таблиц решение без уточнения непригодно.
Поэтому для D2 **обязательны**:

1. **Невязка в повышенной точности.** При hₓ = h_y = 1/n:
   - 𝒜 = n⁴·(целочисленный шаблон);
   - r = (q/D)𝟏 − 𝒜x вычисляется точно — рациональная арифметика (`fractions`) или безошибочные преобразования double-double —
     и округляется до double.

   При недиадических шагах (например, ℓ = 3, h = 3/n) невязка вычисляется по **точному рациональному оператору**: 𝒜 = (n/ℓ)⁴·Z при
   hₓ = h_y, Z — целочисленный шаблон; в общем случае a, b — точные двоичные дроби входных double, hₓ = a/nₓ, h_y = b/n_y —
   точные рациональные числа. Zx — точно, масштабные множители (например, (n/ℓ)⁴ = n⁴/81 при ℓ = 3, не представимый в double и
   double-double) — в рациональной арифметике; округлённая матрица в невязке не используется: ошибка округления её элементов (~cond·u) уточнением не устраняется *(АП-8, §12)*. Без `mpmath`, чтобы проверка
   работала в CI на малых сетках.
2. **Итеративное уточнение** той же факторизацией: x ← x + 𝒜⁻¹r, до 5 шагов, пока ‖δx‖∞/‖x‖∞ не перестанет убывать.

   Предпосылка сходимости: cond(𝒜)·u < 1. По §1.3 при h = 1/n (короткая сторона 1) cond(𝒜) ≤ 64n⁴/(μ₁ₓ + μ₁ᵧ)² < 64n⁴/μ₁ᵧ² ≈ 64n⁴/π⁴
   при любом r. Отсюда cond(𝒜)·u ≲ 5·10⁻⁶ при n ≤ 512 и ≲ 3·10⁻⁷ при n ≤ 256 — предпосылка выполнена.
3. **Оценка ошибки эталона** e_D2 := ‖δx_last‖∞ — последняя поправка, записывается в таблицу.
   - Если e_D2/|α| > 10⁻¹³, значение α получает статус UNRESOLVED (эталон недостаточно точен).
   - Порог 10⁻¹³ — кандидат [ИНЖ], §4.7.
4. **Контроль упорядочения:** α по двум упорядочениям (MMD_AT_PLUS_A и COLAMD) после уточнения. Различие ≤ 4·e_D2 + 4u·α —
   проверка оценки ошибки, а не допуск к консультанту.
