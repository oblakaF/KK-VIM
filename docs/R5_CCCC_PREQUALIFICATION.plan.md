## 1. Независимый эталон D2

### 1.1. Определение и независимость

D2 — решение 𝒜 vec(w) = (q/D)·𝟏 с 13-точечной схемой: (δ⁴ₓ + 2δ²ₓδ²ᵧ + δ⁴ᵧ)w = q/D во внутренних узлах, w = 0 на границе,
∂w/∂n = 0 через фиктивный узел w₋₁ = w₁ (подготовка, разд. 9.3; рецензия `62db9f2`, разд. 5).

Требования к реализации QA (`kkvim_reference`, отдельный модуль):
- не импортирует `kkvim` (существующий `tests/test_package_independence.py`);
- не использует кронекерову формулу проекта как способ сборки. Основная сборка — **поузловая** по шаблону с явным фиктивным узлом;
- кронекерова формула 𝒜 = D4ₓ⊗I + 2Lₓ⊗L_y + I⊗D4_y и гессиан Π_h^C строятся отдельными функциями QA только как **контрольные**
  сборки (D2-2, D2-4);
- решение — разреженная прямая факторизация с обязательным уточнением по невязке в повышенной точности (§1.4).

**D2 независим по коду, но не по дискретизации:** при основе Π_h^C D1 = D2. Ошибку сетки проверяют только A и B (`62db9f2`, 5.4 (б)).

### 1.3. Собственный вывод QA для D2-6

D4 = L² + E₂, E₂ ⪰ 0. Тогда

𝒜 = (Lₓ⊗I + I⊗L_y)² + E₂ₓ⊗I + I⊗E₂ᵧ ⪰ (Lₓ⊗I + I⊗L_y)².

Собственные значения правой части — (λᵢ(Lₓ) + λⱼ(L_y))², все λ < 0. Минимум (μ₁ₓ + μ₁ᵧ)². Верхняя граница —
‖D4‖₂ ≤ ‖D4‖∞ = 16/h⁴, ‖L‖₂ ≤ 4/h².

Проверено при подготовке плана на трёх малых сетках с hₓ ≠ h_y: λ_min/граница = 3,1–3,8; λ_max/граница = 0,95. Это **собственный вывод QA**,
до использования в тестах — сверка Reviewer.

### 1.4. Точность решения D2 (оценка собственной ошибки эталона)

Проба §6: факторизация SuperLU в двойной точности без уточнения даёт для случайной правой части ошибку до 8,7·10⁻⁹ (r = 5, n = 256) и
до 4,6·10⁻⁸ (r = 1, 2, n = 512). Это сопоставимо с разбросом Ричардсона консультанта (≤ 3·10⁻⁹ отн.) и для таблиц недостаточно.
Поэтому для D2 **обязательны**:

1. **Невязка в повышенной точности.** При hₓ = h_y = 1/n:
   - 𝒜 = n⁴·(целочисленный шаблон);
   - r = (q/D)𝟏 − 𝒜x вычисляется точно — рациональная арифметика (`fractions`) или безошибочные преобразования double-double —
     и округляется до double.

   При недиадических шагах — double-double. Без `mpmath`, чтобы проверка работала в CI на малых сетках.
2. **Итеративное уточнение** той же факторизацией: x ← x + 𝒜⁻¹r, до 5 шагов, пока ‖δx‖∞/‖x‖∞ не перестанет убывать.

   Предпосылка сходимости: cond(𝒜)·u < 1. По §1.3 при h = 1/n (короткая сторона 1) cond(𝒜) ≤ 64n⁴/(μ₁ₓ + μ₁ᵧ)² < 64n⁴/μ₁ᵧ² ≈ 64n⁴/π⁴
   при любом r. Отсюда cond(𝒜)·u ≲ 5·10⁻⁶ при n ≤ 512 и ≲ 3·10⁻⁷ при n ≤ 256 — предпосылка выполнена.
3. **Оценка ошибки эталона** e_D2 := ‖δx_last‖∞ — последняя поправка, записывается в таблицу.
   - Если e_D2/|α| > 10⁻¹³, значение α получает статус UNRESOLVED (эталон недостаточно точен).
   - Порог 10⁻¹³ — кандидат [ИНЖ], §4.7.
4. **Контроль упорядочения:** α по двум упорядочениям (MMD_AT_PLUS_A и COLAMD) после уточнения. Различие ≤ 4·e_D2 + 4u·α —
   проверка оценки ошибки, а не допуск к консультанту.

### 1.5. Воспроизведение 27 внешних значений и расчёт r = 5, n = 256

**Выборка** — все 27 сырых значений подготовки, разд. 9.8:
- n ∈ {32, 48, 64, 96, 128, 192, 256} × r ∈ {1, 2, 3, 5};
- без r = 5, n = 256;
- ℓ = 1, q = D = 1, n — интервалы по короткой стороне.

**Дополнительно** — r = 5, n = 256, нового значения у консультанта нет. Каждая точка считается в двух ориентациях (D2-8): у консультанта
оси могли быть переставлены.

**Порядок, зафиксированный до сравнения:**
1. QA вычисляет α_ref (уточнённое, §1.4), e_D2 и α_unref — без уточнения, SuperLU COLAMD, как у консультанта.
2. До открытия сравнения записывается граница
   B_ext(n, r) = ½·10^{−13}·|α| (печать 14 значащих цифр) + 10·|α_unref − α_ref| + e_D2.
   - Множитель 10 [ИНЖ, кандидат] покрывает другой порядок операций и платформу консультанта.
   - Он не подбирается по внешним значениям.
3. Сравнение и статусы:

| Статус | Условие |
|---|---|
| REPRODUCED_TO_PRINTED_DIGITS | α_ref, округлённое до 14 значащих цифр, совпадает с напечатанным |
| CONSISTENT_WITHIN_ROUNDING_MODEL | \|α_ref − α_ext\| ≤ B_ext |
| NOT_REPRODUCED | иначе; проверяются ориентация осей и центр. Значение остаётся UNVERIFIED, расхождение записывается в OPEN_QUESTIONS (решение владельца) |
| UNRESOLVED | e_D2/\|α\| > 10⁻¹³ или ресурсы превышены (§6.3) |

**Что повышается:**
- статус сырых значений — только при REPRODUCED или CONSISTENT всех 27 и только решением владельца;
- экстраполированные значения консультанта **не** повышаются. QA пересчитывает Ричардсон по своим α_ref как OBSERVATION (группа B, §5),
  с явной пометкой «показатели — из наблюдения».

r = 5, n = 256 даёт четвёртую сетку цепочки 32–64–128–256 для r = 5 (подготовка, разд. 9.8, п. 2). Наблюдаемый порядок остатка после

подготовка 9.7). Экстраполированный знак — OBSERVATION с указанием модели. Гипотеза H-osc не проверяется как PASS/FAIL.

## 4. Численная политика CCCC — структура будущих допусков

Окончательные пороги утверждает владелец **до** приёмочных сравнений (D-025, AGENTS.md разд. 4). Ниже — структура и кандидаты. Значения

### 4.1. Ошибка решения линейной системы полушага

### 4.2. Бюджет эталона

- **Кандидат:** правило 1/100 D-046 — ошибка эталона ≤ 1/100 допуска сравнения.
- Для R5 нужен явный перенос решением владельца: правило не связано с SSSS, но принято для R4.
- Ошибка эталона:
  - D2 — e_D2, §1.4;
  - R-AC — последняя поправка уточнения;

### 4.3. Энергетический контроль

| Элемент | Статус |
|---|---|
| форма: тождество с γ_s и тест E1/E2 | переносится по структуре (ЧВ4-14 — общий факт; ОВ-S1 закрыт в дискретной части рецензией `4b18761`, 3 п. 5) |

### 4.5. Ранг и обусловленность

| Величина | Кандидат | Нужно |
|---|---|---|
| защита ранга (аналог K_RESEARCH) | форма ρ_N > K·u·κ_rep, σ_min > K·u | значение K — эксперимент на неполноранговых конструкциях CCCC (как B4 R4) и на полях ST-4; решение владельца |

### 4.6. Остановка

- tol_∞, tol_E, s_min, s_max — определения как R4 разд. 7 (по инвариантности). Значения CCCC — эксперимент на QA-эталоне последовательности
  (R-H/R-AC с уточнением) + решение владельца.
- Стабилизация поля — критерий остановки, а не сходимость к ω₀.
- Пограничная полоса для проверки шага остановки — априорно, как в К-2 плана D-048: |ε^E − tol_E| ≤ ε_floor^C, |ε^∞ − tol_∞| ≤ 100u ⇒ UNRESOLVED.

### 4.7. Ошибка независимых эталонов A и D2

| Эталон | Что известно | Следствие для критериев |
|---|---|---|
| D2 | ошибка решения: e_D2 по уточнению (§1.4). Ошибка дискретизации относительно ω₀ — **не оценена** (H-D2-2 — гипотеза) | D2 — эталон **дискретной** задачи (группа A для D1 = D2 и для КК-МВИ − D1). Для оценки точности относительно ω₀ — только группа B |

| A — конечные секции (A-2) | порядок системы N_X + N_Y ≤ ~3·10³ (N_X ~ r·N_Y); плотная LU | секунды; рост секций N = 50…400 — для OBSERVATION |
| B — Ритц на 𝒯_M ⊗ 𝒯_M | M² неизвестных; Грам — диагональ + ранг 1 по каждой оси, поэтому решение через SMW с ёмкостью ~2M | M ≤ 2000: минуты; не обязателен (спецификация 7.3) |

| ST-1…ST-10 | коэффициенты в `decimal` — O(nN²) операций по 50 знаков | ≤ минут |

### 6.3. Правило ресурсов (UNRESOLVED вместо запуска любой ценой)

Тяжёлая точка исполняется, только если проба той же конфигурации укладывается в пределы, зафиксированные до запуска:
- пик памяти ≤ 50 % RAM машины;
- факторизация ≤ 30 мин;
- уточнение сходится (§1.4).

Иначе точка получает статус **UNRESOLVED (ресурсы)** с записью измеренных значений. Ни упрощение схемы, ни замена решателя, ни
ослабление допуска ради прохождения не допускаются.

**CI.** В обязательный CI входят только малые сетки (n ≤ 64; для D2-8 и BC-2 — до n = 128). Тяжёлые точки — локальный прогон QA с
записью платформы.

## 9. Условия перехода к реализации и квалификации

**К реализации QA-эталонов (Q1):**
1. владелец принял этот план (с изменениями или без);
2. дано отдельное задание на эталоны D2/D1/R-H/R-AC/R-HP (код `kkvim_reference`, без импорта `kkvim`);
3. принята основа Π_h^C (Б-5) — для D1 и R-H. D2 от неё не зависит и может начинаться раньше по решению владельца.

**К квалификации Builder N = 1 (Q5):**
1. спецификация CCCC N = 1 принята владельцем:
   - Π_h^C;
   - способ решения РВ5-2;
   - нормировка множителя (П-8);
   - условие У-R5;
2. численная политика CCCC N = 1 утверждена (Q4). Все пороги §4 зафиксированы **до** сравнений;
3. Q1 и Q2 PASS: D2 самопроверен, внешняя таблица воспроизведена или расхождения оформлены;
4. разрешение владельца на программирование и код Builder;
5. решён вопрос Б-1 (принятие R4 или явный отдельный порядок для R5 N = 1).

**К квалификации N = 2–3 (Q6):**
1. Б-2 закрыт:
   - рецензия `a31d1ff` (ВБC-1…ВБC-18) завершена;
   - часть C MATH_SPEC или эквивалентное решение (ОВ-C7);
   - старт 𝒯_N и ориентация утверждены (ОВ-C6);
2. пробел ОВ-C1 явно принят владельцем как контролируемый диагностикой S-1/S-2 (без утверждения теоремы);
3. критерий ранга CCCC утверждён (§4.5).

**Не является условием:**
- доказательство глобального второго порядка D2;
- строгая точность A — они ограничивают только формулировки группы B.
