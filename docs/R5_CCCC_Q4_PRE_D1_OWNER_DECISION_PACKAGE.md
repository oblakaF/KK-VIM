## 1. PRE_D1_RANK — отдельный крупный пункт

### 1.1. Формулировка

Можно ли в кампании D1 при N = 2, 3 выполнять QR и следующие полушаги, если ранг траектории не сертифицирован? Если нельзя — как
останавливать и как маркировать.

### 1.2. Что установлено (ИС, разд. 2, 5.1)

- D-049.5, п. 1 с MS-C C.11.2 и R4NS 5.2 п. 9: при неустановленном бюджете ε ранг «численно неразличим», остановка до QR.
- Принятые QA-инструменты SEQ (D-051.1) и ОП-8 (D-055.1) при N ≥ 2 продолжают QR с меткой RESEARCH_ONLY. Данные Q3 и PR #41–#42 получены
  так же и приняты D-053, D-054 как исследовательская база.
- PROT (D-055.2), разд. 3, блок D требует защитную остановку до QR при неразличимости.
- Literature рассматривала это как **неоднозначность объекта D-049.5** (ВП-1). Прочтения:
  - (а) D-049.5 относится к режиму реализации метода, а QA-цепочки RESEARCH_ONLY допустимы;
  - (б) D-049.5 относится ко всем расчётам N = 2–3, включая D1.
- **Вывод рецензии** [РЕЦ, разд. 6]: для D1 это **не противоречие решений, а невыполненное требование**. D-049.5 и есть
  исследовательский режим N = 2–3; протокол D1 требует остановки однозначно; по R4NS 5.2 п. 9 ранг сейчас неразличим, и до
  сертификата применяется вариант В. Неоднозначность (а)/(б) касается только статуса прежних данных Q3 и PR #41–#42 при N ≥ 2, s ≥ 2;
  они и так RESEARCH_ONLY.
- O1 PROVEN, O3 CERTIFIED (D0, 1312/1312), O4 UNRESOLVED (D-054.5).
- **Новое (ИС; статусы — по РЕЦ):**
  - непрерывный ранг s = 1 при N = 3 — РН-1 + РН-2, **PROVEN**; в MS-C до решения владельца — UNRESOLVED;
  - O4-h при s = 1 сертифицируема (РН-5, PROVEN_CONDITIONAL; на сетках D1 сертификат не вычислялся);
  - для s ≥ 2 есть рекурсивная апостериорная граница (РН-9, PROVEN_CONDITIONAL), замыкание которой UNRESOLVED;
  - на малых сетках фактический перенос сжимающий (наблюдение);
  - отрицательный пример (исправлено по Ф-1): при N > ⌊n_y/2⌋ точный ранг ≤ ⌊n_y/2⌋ (РН-3, PROVEN). На ОП-8 найдены сетки вне D1
    — (12, 4), (10, 4), N = 3, — где вычисленный набор имеет точный ранг 3, и остановка по точной зависимости не срабатывает, QR
    продолжается. На (14, 4) ОП-8 останавливается по S-1; SEQ на всех проверенных сетках останавливается по S-1. Срабатывание зависит
    от округления решателя (ИС, разд. 4.3).

### OD-8. Отказ предпосылок C-3⁺; замечание З-4

1. Статус строки при UNRESOLVED-предпосылках C-3⁺ или при нарушенной точной проверке его неравенства. Отдельно — З-4: неисправная Γ_up и

2. PROT 4.1–4.2: классификатор знает только П-а…П-е. ОП-8 классифицирует П-1…П-5 как ESTABLISHED / ASSUMED / UNRESOLVED; П-4 всегда

   предпосылок C-3⁺ переносится в строку с П-4 = ASSUMED (отчёт QA конвейера, разд. 2, 10.3, З-6).
3. Статусы для C-3⁺ и порядок действий при неисправности Γ_up.
4. **Математика:**
   - **(а) Сертификат τ′ от предпосылок C-3⁺ не зависит.** Э-2 оценивает E_s для **сохранённых** полей и пути G-4, каким бы решателем поля

   - **(б) Наблюдения точности тоже от них не зависят.** TS-1 и BC-1 сравнивают V̂ с точным V* (BR) независимо от способа получения V̂.

     - Γ_up занижена → возможен ложный PASS разрешимости или FAIL_COMPUTATION → BLOCKED_CAMPAIGN; источник неизвестен;
     - Γ_up завышена → ложная UNRESOLVED_RESOLVABILITY → **ложный FAIL_CANDIDATE**. По правилу против подгонки (D-054.2, п. 4) он
       необратим. E-тесты его не видят.
   - **(г) Ф-3 — две разные проверки Γ_up** (исправлено по РЕЦ, Ф-3):

        и интервал не того полушага;

        **γ↓ = RD(γ_B), γ↑ = RU(γ_B)** побитово (RD, RU — округление вниз и вверх до binary64). Это соответствует построению пути B1:
        точное γ и наружное округление (D-054.1, п. 1: Γ_up = max(|γ↓|, |γ↑|) — сертифицированная оценка пути B1).

     Проверка 1 **не обнаруживает завышенную Γ_up**: слишком широкий интервал её проходит. Тогда τ′ завышена, строка с истинно
     разрешимым Q̂ > τ′_true может получить Q̂ ≤ τ′ → UNRESOLVED_RESOLVABILITY → ложный FAIL_CANDIDATE, необратимый по D-054.2, п. 4.
     Для исключения этого риска нужна проверка 2. Требование узости — **предложение** для решения владельца (дополнение процедуры
     PROT 5, п. 9 и З-4); утверждённый протокол этим документом не меняется.

     **Состояние конвейера N = 1** (`dfc019d`, чтение кода [ИНТ]): на строке проверяются точное равенство γ_B = γ_B1 и включение γ_B в
     [γ↓, γ↑] (диагностика второго пути, только при (nₓ − 1)(n_y − 1) ≤ 4096). Побитовое сравнение γ↓, γ↑ с RD(γ_B), RU(γ_B) как условие
     строки **не выполняется**; узость интервала относительно точного γ_B1 проверяется переносимым тестом З-5 на тестовых строках, а не на
     каждой строке.
5. Варианты:
   - для C-3⁺ — отдельные поля наблюдения `C3P_PREMISES` ∈ {ESTABLISHED, ESTABLISHED_CONDITIONAL_ON_P4, UNRESOLVED} и
