## 3. Методика: что от чего независимо

Задание требует не называть контроль независимым, если он использует тот же оператор и тот же вычислительный путь. Поэтому для каждого контроля
указано, что у него общего с решателем.

| Проверка QA | Что вычисляется | Общее с решателем | Независимо от решателя |
|---|---|---|---|
| К-3 (`rho1`) | точное поле W*¹ первого полушага по замкнутой форме нечётного синусного старта (ЧВ4-8, ЧВ4-9: V̂_ik = F_i c_k / (D(a/2)(μ_k + λ_i)²)); сингулярные числа — сертифицированно, по инерции Сильвестра (LDLᵀ в шаровой арифметике arb) | принятая дискретная задача | код, сборка A, B, C, F, DST, LAPACK, QR/SVD решателя |

## 5. Б. Соответствие методу

- **Тот же полушаг.** Тела `research_halfstep` и `kkvim.coupled.solve_coupled_halfstep` сравнены по синтаксическому дереву (`isolation.json`): из 12
  операторов отличается ровно один — проверка `N not in N_SOLVE` против `N not in N_RESEARCH`. Порядок вызовов один: `coupled_coefficients`
  → `sine_eigenvalues` → ψᵀ𝟏 → `_solve_modes` (Холецкий мод) → обратное `sine_transform` → проверка конечности. `refine_once`,
  `rank_diagnostics`, `orthogonalize_received`, `first_energy` / `pair_energy` — общие функции решателя; зависимость от N в них только
  через γ_N = Nu/(1 − Nu) и размеры, ветвлений по N нет.
- **Тот же порядок полушагов.** `run_cell` построчно повторяет ветку `run_coupled(research_mode=True, stop_on_stabilization=False)`: решение → η_N
  с одним уточнением → диагностика поля и набора → энергия → защиты → QR → следующий полушаг; остановка до QR, N не меняется.
  Единственное отличие кода — нет `last = min(half_steps, S_MAX)`; при 40 полушагах это ничего не меняет.
- **Глубокое сравнение с `run_coupled`.** На всех 12 контрольных ячейках сравнены все поля всех `StepLog` и вложенных структур (`RankDiagnostics`,
  `CoupledEnergy`), а не список полей. Наборы X, Y, статусы, s первой стабилизации, все числа журналов совпали побитово. Отличие одно:
  на s = 2 оркестрация не записывает в журнал `energy_s2_mandatory_unresolved` — у `run_coupled` там `False`, у оркестрации `None` (Н-5).
  Численно это ничего не меняет; для N ≥ 4 флаг D-048.1 и не применим.
- **Производственные ограничения не обходились.** `N_SOLVE = (2, 3)` до и после; присваиваний атрибутам `kkvim.*`, `setattr`, monkeypatch и
  `reload` в скрипте нет. `run_coupled(N = 4)` возвращает ERROR_INPUT, `solve_coupled_halfstep(N = 4)` бросает исключение (тест Builder).
- **Новой схемы нет.** Последовательного добавления членов нет, N не меняется, восстановления направлений и регуляризации нет. Независимая
  последовательность К-4, построенная прямо из определения Π_h, совпадает с решателем до 10⁻¹³ и точнее (разд. 6.1). Это подтверждает, что
  решатель реализует ту же совместную схему.
- **Защиты D-048.5 по журналу (К-2).** Для всех 7 854 строк решения защит пересчитаны из записанных ρ_N, κ_rep и σ_min(R_V·D_c):
  ρ_N > K·u·κ_rep, σ_min > K·u, K·u·κ_rep < 1. Расхождений нет, пограничных случаев (ближе 10⁻⁵ к порогу) нет. Отношение
  ρ/порог совпадает с записанным до печати.
- **Нормативные статусы D-048 к N ≥ 4 не применены.** Флаг обязательной области s = 2 (D-048.1) пуст для всех 198 ячеек N = 4–6 и равен
  `True` для 12 контрольных. Нет ни S-2, ни PROVISIONAL_FIELD_STABILIZED, ни CONVERGED, ни MAX_HALF_STEPS. Метка PROVISIONAL / NOT_QUALIFIED
  стоит в каждой строке. Энергетический тест разрешён тогда и только тогда, когда m_s ≥ 1 (Q_s ≥ 10τ_s).
