## 5. Наблюдение: обусловленность набора в R4 (только чтение)

Источник: `src/kkvim/coupled_run.py` (строки 302–422), `src/kkvim/coupled_rank.py` (`rank_diagnostics`, `mode_conditions`,
`orthogonalize_received`). Код не менялся.

Для проверки выполнен короткий прогон `run_coupled(1, 1, 1, 1, 40, 40, N, transform="fft", half_steps=4, research_mode=True,
stop_on_stabilization=False)` при N = 2, 3. Скрипт лежит в scratchpad вне git.

| Что журналирует R4 (`StepLog`) | Смысл | Наблюдение |
|---|---|---|
| `cond_A_given` | cond₂(A) **заданного** набора полушага s, то есть набора, по которому строятся коэффициенты. При s ≥ 2 в исследовательском режиме это набор после QR предыдущего полушага; при s = 1 — стартовые нечётные синусы (дискретно ортогональны) | 1 (с точностью вывода) на всех s при N = 2, 3 |
| `rank.cond_V` | cond₂(√h·V) **полученного** набора **до** его QR. QR выполняется позже, в `orthogonalize_received`, после записи журнала и защит. cond(A) следующего полушага до QR = cond_V² | N = 2: cond_V ≈ 8,1·10²…8,2·10² (cond_V² ≈ 6,5·10⁵…6,8·10⁵); N = 3: cond_V ≈ 3,4·10⁴…3,9·10⁴ (cond_V² ≈ 1,1·10⁹…1,5·10⁹) |
| `rank.set_sigma` | сингулярные числа R_V·D_c (полученный набор с нормированными столбцами); по нему работает защита `set_ok` | — |
| cond(S) | в R4 нет: поправки ШМВ нет | — |

**Вывод.** R4 не записывает «cond(A) до QR» отдельным полем. Поле `cond_A_given` — величина после QR (≈ 1). Обусловленность набора до QR
записывается косвенно, через `rank.cond_V` (и `set_sigma`): cond(A) до QR = cond_V².

Для R5 (NS 5.1, АП-4; PL BC-5) рекомендуется явное поле cond(A) до QR. Это относится к будущей реализации CCCC, а не к R4. В R4 ничего
менять не требуется.
