## 1. Формулы систем полушага

### 1.1. Коэффициенты и система (NS 4.2–4.3)

- В модуле: A = h_f GᵀG, B = −h_f GᵀL_fG, C = h_f GᵀD4_fG, F = q h_f Gᵀ𝟏; K = D[A ⊗ D4_s − 2B ⊗ L_s + C ⊗ I], K vec(S) = F ⊗ 𝟏 (сначала индекс члена).
  - Совпадает с NS 4.2–4.3 (ЧФ-C1/C2) и с выводом, проверенным в `4b18761`, `87a15ab`.
- A, B, C симметричны точно: L, D4 симметричны.
- При независимом G матрица A ≻ 0, K ≻ 0 (D-049.1; MATH_SPEC C, ВБC-13 п. 2).
- Размерности: A ~ [G²]·длина, B ~ /длина, C ~ /длина³, F ~ q·длина. Тест масштаба (A × c, B/c, C/c³, F × c) это подтверждает.

### 1.2. R-H — ограничение гессиана

Hess Π_h^C = D hₓh_y 𝒜, 𝒜 = D4ₓ ⊗ I + 2Lₓ ⊗ L_y + I ⊗ D4_y (Предложение D). Пусть поле w = P vec(S).

- **Y-полушаг:** P = G ⊗ I_{n_y−1}, w_{(i,j)} = Σₖ G_{ik}S_{jk} — порядок D2 k = (i − 1)(n_y − 1) + (j − 1).
- **X-полушаг:** P = [I ⊗ G_{:k}]ₖ.

Тогда

Pᵀ𝒜P = (C/hₓ) ⊗ I − 2(B/hₓ) ⊗ L_y + (A/hₓ) ⊗ D4_y (для Y),

и D hₓh_y Pᵀ𝒜P = h_y K. Значит, K_H = (D hₓh_y/h_s)Pᵀ𝒜P = K и rhs_H = (q hₓh_y/h_s)Pᵀ𝟏 = F ⊗ 𝟏 — **верно**.

Моя независимая сборка K для X-полушага, N = 3, сетка (10, 14, 1, 1,7) совпадает с K_H до 5,2·10⁻¹⁶ отн., правая часть — до 1,3·10⁻¹⁶ (Н-4). Обе ориентации и нумерация верны.

### 1.3. R-AC — ширина ленты

- Нумерация «узел — член», индекс jN + i. D4 связывает j и j ± 2, блоки N × N плотные ⇒ половина ширины ленты p = 2N + (N − 1) = **3N − 1** — верно (У-R1).
- `cholesky_banded` с этой лентой; уточнение — по невязке R-HP; e_AC — последняя поправка, названная **оценкой**. Верно.

### 1.4. R-HP — точная невязка; дефект при n = 2

- Невязка вычисляется в `fractions` по заданным double, D4 — по шаблону (1, −4, 6, −4, 1) со строками (7, −4, 1), без модального преобразования (NS 5). При n ≥ 3 это в точности D4 = L² + E₂.
- **При n = 2** (один внутренний узел) обе граничные поправки приходятся на одну и ту же строку: D4 = L² + (2/h⁴)(e₁e₁ᵀ + e₁e₁ᵀ) = (4 + 4)/h⁴ = **8/h⁴**. По шаблону с отражением w₋₁ = w₁, w₃ = w₁ получается тоже 6 + 1 + 1 = 8.
- `_apply_D4_exact` (стр. 174) и `_exact_band_matrix` (стр. 254) ставят **7**.
- Численно (Н-3): точный шаблон даёт 7·f, а `_D4(2, h)` — 8; при n_f = 2 C_exact = 56, C_float = 64.
- Следствия при n_s = 2 или n_f = 2:
  - точный путь (R-HP, сертификат) решает **другую** систему, чем R-AC и R-H;
  - уточнение R-AC сходится не к той системе.
- `HalfStep` (стр. 63–73) не запрещает n = 2. Нужно ограничение n_f, n_s ≥ 3 или исправленный шаблон (И-4).

### 1.5. Независимость путей — точная область

| Пара | Что общее | Где независимы |
|---|---|---|
| R-H ↔ {R-AC, R-HP, сертификат} | входной набор G; модуль D2 QA (`energy_hessian`, PR #27); NumPy/SciPy | **формулы**: R-H не использует A, B, C, F и D4 = L² + E₂; это единственная независимая проверка формул NS 4.2 (тест «same exact system») |
| R-AC ↔ R-HP | **одни и те же формулы A, B, C, F** (NS 4.2); различаются арифметика (double и рациональная) и представление D4 (L² + E₂ и явный шаблон) | арифметика и D4-путь. Ошибку в формулах коэффициентов R-AC и R-HP повторят вместе |
| уточнённое R-AC ↔ R-HP | невязка R-HP | **не независимы** (отчёт QA, разд. 2 — верно) |
| сертификат ↔ R-HP | точные коэффициенты и тот же шаблон D4 (в том числе дефект n = 2) | — |
| все ↔ Builder | — | `kkvim` не импортируется (тест в отдельном процессе) |

Сравнение «R-H против R-AC по строгим границам» проверяет согласие R-H с **точной системой коэффициентного пути**: если формулы NS 4.2 ошибочны, решение R-H выйдет за границу. Эта логика верна — при условии, что граница действительно строгая (И-1, И-2).

## 3. Сертификат λ_min (`certify_lambda_min`, стр. 268–300)

### 3.1. Доказательство: что верно

Обозначения:

- K — точная матрица системы с точными коэффициентами входных double (порядок «узел — член»);
- t = `Decimal(repr(float(tau)))`;
- u_d = ½·10^{1−d} — единица округления decimal, d = 50;
- `unit` = 10^{1−d} = 2u_d.

1. **Элементы.** `Decimal(numerator)` и `Decimal(denominator)` точны (конструктор Decimal от int не округляет). Деление округлено: |ã_ij − a_ij| ≤ u_d|a_ij| ≤ `unit`·amax. Член `unit·amax` в `err_entry` это покрывает с запасом.
2. **t.** `repr(float(tau))` даёт не более 17 значащих цифр, и Decimal из строки точен. t, вообще говоря, ≠ float(tau): например, Decimal('0.1') ≠ 0.1000000000000000055…. Но **именно t вычитается из K, и именно от t строится граница**, поэтому использование корректно; значение tau как double роли не играет.
3. **Разложение Холецкого.** Если разложение M̃ = Ã − tI (ленточное, половина ширины p) прошло с sᵢᵢ > 0, то R̂ᵀR̂ = M̃ + ΔM, |ΔM| ≤ γ_{p+3}^{(d)}|R̂ᵀ||R̂| (Higham, ASNA, теорема 10.3, ленточный вариант).
   - Каждый элемент — не более p произведений, плюс a_ij, плюс −t, плюс деление или корень.
   - Код берёт (p + 2)·`unit` = 2(p + 2)u_d ≥ γ_{p+3}^{(d)} при p ≥ 1. Запас вдвое покрывает округление при вычислении absrr и возможную неточность `**2` (libmpdec: целая степень с ошибкой не больше 1 ulp).
4. **Норма.** E = (Ã − K) + ΔM ленточная, ширина 2p + 1 ⇒ ‖E‖₂ ≤ ‖E‖∞ ≤ (2p + 1)·err_entry.
5. **Вейль.** R̂ᵀR̂ ≻ 0 (диагональ R̂ > 0) ⇒ λ_min(K − tI + E) > 0 ⇒ **λ_min(K) > t − ‖E‖₂ ≥ t − err_norm**.

В точной записи последнего шага сертификат верен.

### 3.2. Что не обеспечено (И-2)

1. **Округление на выходе.** `float(t - err_norm)` (стр. 300) округляет к ближайшему и может дать число **выше** доказанной границы t − err_norm.
   - Пример: float(Decimal('0.1')) превышает 0,1 на 5,55·10⁻¹⁸ (Н-2).
   - Само t − err_norm и произведения в `err_entry`, `err_norm` округлены в Decimal к ближайшему, а не в безопасную сторону. Это ~10⁻⁵⁰, но без направленного округления граница не строгая.
   - На практике (tau = λ_min,double/2) запас огромен. Нарушение возможно, когда tau выбран в пределах ½ ulp от λ_min — функция заявляет строгость для **любого** tau.
2. **Выход за диапазон double.**
   - Если 0 < t − err_norm < 4,9·10⁻³²⁴, `float` даёт 0,0, и далее в `error_bound` — деление на ноль.
   - В субнормальной области — потеря относительной точности с округлением вверх.
   - При t − err_norm > 1,8·10³⁰⁸ — inf.
   - Ни один случай не проверяется.
3. **n = 2** — сертификат относится к матрице с 7/h⁴ вместо 8/h⁴ (разд. 1.4, И-4).

**Вердикт по сертификату:** CHANGES_REQUIRED. Нужны направленные округления и проверка диапазона; доказательство менять не нужно.

## 4. `error_bound()` (стр. 303–307)

```
rr = sum(x * x for x in r)                              # точная Fraction
return math.sqrt(float(rr)) * (1 + 4 * U) / lambda_low
```

### 4.1. Контрпример (обязательный пункт задания)

Н-1: Y-полушаг, N = 1, сетка (10, 14, a = 1, b = 1,7), старт sin², D = 1, **q = 10⁻²⁰⁰**, приближение ŝ = 0.

- Точная невязка r = F ⊗ 𝟏 ≠ 0, max|r| = 5,0·10⁻²⁰¹.
- rr = Σrᵢ² ≈ 10⁻⁴⁰¹ ⇒ **`float(rr)` = 0,0** ⇒ **`error_bound` = 0,0**.
- При этом K ≻ 0 (λ_low = 120,9 сертифицировано) и F ≠ 0 ⇒ s* = K⁻¹F ≠ 0. Численно max|s*| = 2,5·10⁻²⁰³, а точная нижняя оценка ошибки ‖ŝ − s*‖ ≥ max|r|/λ_max = 1,7·10⁻²⁰⁵ > 0.

**Функция возвращает нулевую «строгую» верхнюю границу при ненулевой ошибке.**

### 4.2. Другие дефекты

| Область | Что происходит | Следствие |
|---|---|---|
| Субнормальные rr (10⁻³⁰⁸…10⁻³²⁴) | q = 10⁻¹⁶⁰: относительная ошибка `float(rr)` = 1,1·10⁻⁵, после корня — 5,6·10⁻⁶ (Н-1) | множитель (1 + 4u) этого не компенсирует — граница может быть занижена |
| Нормальная область | float(rr): ≤ u; sqrt: ≤ u + половина ошибки аргумента; умножение на (1 + 2⁻⁵¹) (представимо точно) и деление — по ≤ u. Нижний множитель ≈ (1 − ½u)(1 − u)(1 + 4u)(1 − u)(1 − u) ≈ 1 + ½u | граница **держится, но с запасом всего ½u первого порядка**; доказательство в коде не записано |
| Переполнение rr > 1,8·10³⁰⁸ | `Fraction.__float__` → OverflowError | явная ошибка, не тихая — допустимо |
| `lambda_low` ≤ 0, None, nan, inf | не проверяется: отрицательная граница, `ZeroDivisionError`, TypeError, nan, 0 | нужна проверка |

**Вердикт по `error_bound()`:** **строгой границей не является** (И-1).

### 4.3. Ошибка набора против ошибки поля (п. 8 задания)

- Граница относится к **вектору неизвестных полушага** ŝ (вычисляемый набор S) и к точному решению s* системы с **точными коэффициентами входных double**. Это не ошибка относительно непрерывной задачи и не ошибка заданного набора.
- Ошибка поля W = G Sᵀ: ‖Ŵ − W*‖_F ≤ ‖G‖₂‖Ŝ − S*‖_F + (ошибка округления произведения G Ŝᵀ ≤ γ_N\|G\|\|Ŝ\|).
  - При плохо обусловленном G ‖G‖₂‖S‖ может быть много больше ‖W‖: `ill_conditioned.csv`, ε = 10⁻⁶ — граница по набору 0,19, разность полей 0,035.
- В отчёте QA таблица разд. 4 ставит «строгую границу (отн.)» по набору рядом с «разностью полей». Нужна явная оговорка (Р-3).
