## 4. У-1 — ошибка образования полей

Проверка точная, в целых числах по битовым образам binary64, на тех же массивах X, Y и том же ŵ, что и в энергиях:
(2⁵³ − N)·|ŵ − XYᵀ| ≤ N·|X||Y|ᵀ, то есть |e| ≤ γ_N|X||Y|ᵀ поэлементно.

| Поле, N | Строк: выполнено | Элементов | Нарушений | max \|e\|/(γ_N\|X\|\|Y\|ᵀ) | \|X\|\|Y\|ᵀ = 0 | Строк с нулевым фактором |
|---|---|---|---|---|---|---|
| предыдущее, N = 1 | 328/328 | 25 243 064 | 0 | 0,99984 | 3 155 383 | 41 (фактор C′ ≡ 0) |
| предыдущее, N = 2 | 328/328 | 25 243 064 | 0 | 0,98857 | 3 155 383 | 41 |
| предыдущее, N = 3 | 328/328 | 25 243 064 | 0 | 0,95962 | 3 155 383 | 41 |
| текущее, N = 1 | 328/328 | 25 243 064 | 0 | **0,99993** | 0 | 0 |
| текущее, N = 2 | 328/328 | 25 243 064 | 0 | 0,99116 | 0 | 0 |
| текущее, N = 3 | 328/328 | 25 243 064 | 0 | 0,98324 | 0 | 0 |

- **Нулевые и ненулевые факторы.** Нулевые факторы есть только в предыдущем поле при s = 1 (C′ ≡ 0, 123 строки). Там
  |X||Y|ᵀ = 0, вычисленное поле и точное произведение — точный нуль. Неравенство выполнено как 0 ≤ 0.
- **Сильная компенсация** (2²⁰·|XYᵀ| ≤ |X||Y|ᵀ, включая XYᵀ = 0 < |X||Y|ᵀ) в данных кампании **не встретилась ни разу** (0 элементов
  во всех классах). Поведение на таких полях проверено только тестами на синтетических данных (разд. 12). На данных это
  **не проверено**.
- **Произведения отдельных элементов** U_ikV_jk: для всех ненулевых факторов точные произведения по модулю ≥ 2⁻¹⁰²² — 984/984 на
  обоих полях. Потери значимости при образовании полей не было.
- **Запаса нет:** отношение доходит до 0,99993. Граница ВОК-4 почти достигается, как и в Q3 Е-2. Поэтому проверка нужна на каждой
  строке и не может заменяться оценкой масштаба.
- **Ограничение переноса (ред. Integrator, Р-4).** В любой новой кампании У-1 проверяется построчно; оценка масштаба её не
  заменяет. Отсутствие сильной компенсации в этих данных не переносится на другие поля.

**Статус:** неравенство |e| ≤ γ_N|X||Y|ᵀ — **VERIFIED на этих массивах** (точная проверка). Это свойство конкретных полей, а не
теорема о BLAS. Для проверенных строк П-4′ и П-3′(в) для произведений U_ikV_jk больше не нужны (ST 13, п. 1; RV Н-5).

## 5. У-2 — условия арифметики

### 5.1. Режим в том же потоке

- **Пробы** — до и после каждой из 984 строк и в начале и в конце каждого из 123 заданий, в главном потоке каждого рабочего
  процесса; кроме того, в главном процессе в начале и в конце кампании (ред. Integrator, Р-2). Все проходят:
  - Python float и векторы NumPy длиной 1, 3, 8, 257;
  - FTZ — субнормальные точные результаты ×, ÷, +, −;
  - DAZ — субнормальные операнды;
  - округление к ближайшему — ничьи к чётному и оба направления;
  - одно произведение BLAS с субнормальными результатами.
- Сравнения только по битовым образам. Операнды создаются во время выполнения из шестнадцатеричных строк, поэтому свёртки
  констант при компиляции нет. Ожидаемые значения проверены тестом как округление точного результата к ближайшему.
- Пробы и вычисления строки выполняются в одном и том же главном потоке рабочего процесса: 984/984.
- `_controlfp` во всех потоках: `0x8001f` — FTZ/DAZ выключены, округление к ближайшему.

**Механизм пробы (ред. Integrator, Р-1; по эксперименту Reviewer, RQ 4.1).**

1. На этой платформе (x64, ucrtbase) `_controlfp` читает и пишет **MXCSR** потока. Через этот регистр выполняются скалярные и
   векторные (SSE2/AVX) операции binary64 NumPy и ядер OpenBLAS. Управляющее слово x87 для этого пути не существенно.
   Reviewer подтвердил это прямым чтением MXCSR (`stmxcsr`) при каждом из пяти изменённых режимов. Проба этого инструмента
   обнаружила каждый из них.
2. **Главное доказательство режима — поведенческие пробы** (выше). Слово `_controlfp` — дополнительное свидетельство.
3. MXCSR — свой у каждого потока. Поэтому существенно, что пробы и вычисления строки выполняются в одном потоке (984/984).
4. Субнормальных операндов и результатов в проверенных операциях нет (разд. 5.2, п. 3). Поэтому FTZ и DAZ не могли изменить ни
   одну проверенную операцию и без пробы. От режима остаётся только округление к ближайшему — предпосылка П-1.

**Условия, при которых модель П-1 применима**, выполнены для каждой строки:

1. округление к ближайшему, FTZ и DAZ выключены — пробы и управляющее слово в том же потоке;

**Статус:** П-3′ и П-2 на путях `pi_double`/`q_double` — **VERIFIED для воспроизведённого вычисления**. П-1 (IEEE binary64 с
округлением к ближайшему как свойство платформы) остаётся предпосылкой, подкреплённой пробами, но не доказанной.

### 8.1. Как вычислена B_E

Собственная реализация по Э-2 (ST 5.1), отдельно от функций EN:

- целочисленные шаблоны NS 2.2 с точными h = l/n: S_q, S_l, S₂ для ŵ_p и ŵ_s, S_q и S₂ для d̂, ‖d̂‖²_h, ‖d̂‖²_a;
