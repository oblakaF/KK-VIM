## 2. Что проверено и что нет

**Проверка реализации (группа A, D-025):** соответствие кода принятой дискретной постановке и числам D-048 — остановке, энергетическому тесту,
невязке, защитам ранга, плотному DST, допускам, статусам.

**Научная квалификация КК-МВИ здесь не выполняется:**
- PROVISIONAL_FIELD_STABILIZED — стабилизация поля конечной задачи, а не сходимость к ω₀ и не сходимость при s → ∞;
- ранг не сертифицирован; запасы защит К-5 — это запасы, а не сертификат;
- точность КК-МВИ (группа B) не оценивается; её статусы не переклассифицированы.

Все результаты исследовательского режима остаются PROVISIONAL / NOT_QUALIFIED.

**Область.** Квалифицированная область не выходит за D-048:
- n = 320 семейства I — независимая проверка QA вне утверждённой области (§4); область она не расширяет;
- n = 1280 для остановки и А4-3 — только наблюдения (§4).

**Этап A не является квалификацией.** Адаптированные 69 проверок этапа A проверяют прежние утверждения QA на фиксированных s; К-1…К-9
выполнены отдельно, новыми тестами и скриптом.

### 3.6. К-6. Плотное DST

**К-6.0. Предпосылка `np.sin`.** Аргументы восстановлены выражением из `sine_matrix` @ `3da624a` и побитово воспроизводят Ψ Builder.

| n | аргументов | max ulp `np.sin` 1D / 2D | 1D == 2D | ошибка формирования x |
|---|---|---|---|---|
| 40 | 20 | 0,630 / 0,630 | да | 0,33 ulp(x) |
| 160 | 80 | 0,630 / 0,630 | да | 0,77 ulp(x) |
| 640 | 320 | 0,630 / 0,630 | да | 0,84 ulp(x) |
| 1280 | 640 | 0,630 / 0,630 | да | 0,84 ulp(x) |

Эталон — `mpmath` 50 знаков. Тот же максимум даёт `decimal` 50 знаков, используемый в CI. Предпосылка ≤ 1 ulp **подтверждена на локальной
платформе**. На Ubuntu и Windows CI тест `test_k6_np_sin_premise_on_this_platform` печатает запись платформы и максимум в ulp в журнал pytest
и проверяет предпосылку отдельно. Для других процессоров она заранее не утверждается.

**К-6.1. Точные проверки** (n = 40, 160, 640, 1280) — **PASS:**
- точные нули при ik ≡ 0 (mod n);
- Ψ = Ψᵀ;
- Ψ_{i,n−k} = (−1)^{i+1}Ψ_{ik};
- собственное целочисленное приведение QA даёт побитово те же аргументы.

**К-6.2. Элементы против `mpmath` (50 знаков)** — **PASS.** Нарушений модели 7u|Ψ| — 0.

| n | ненулевых элементов | max \|ошибка\|/(u\|Ψ\|) |
|---|---|---|
| 40 | 1 420 | 1,67 |
| 160 | 24 592 | 1,82 |
| 640 | 404 416 | 2,32 |
| 1280 | 1 626 880 | 2,25 |

Запас по модели 7u ≥ 3,0.

**К-6.3. Импульсы** e₁, e_mid, e_{n−1} при n = 40, 160, 640, 1280 — **PASS.**
- `dense` в модели (7u + γ_{n−1}(1 + 7u))|Ψ||x|: 0 нарушений; ‖ошибка‖₂ ≤ 0,78u;
- `fft` — только сообщается: ≤ 1,35u;
- `dense` − `fft` — сообщается: ≤ 0,25u.

**Отклонение в ходе работы (ошибка эталона QA, не Builder).** В первом прогоне таблица эталона содержала mp.sin(πj/n) при j ≡ 0 (mod n). Это
значение около 10⁻⁵⁰, а не 0. Элементы, где Builder верно даёт точный 0, сравнивались с этим остатком, и отношение достигало 1/u. Исправление:
точный 0 эталона при j ≡ 0 (mod n), в соответствии с К-6.1. Таблицы `k6_elements.csv` и `k6_impulses.csv` получены после исправления;
допуск не менялся.

## 5. Отклонения от формулировок плана

Критерии и допуски не менялись. Отличается только способ выполнения:

4. **К-4(б):** смещение 10⁻⁶·max|v| вычисляется по модам решения и прибавляется к выходу решения и к каждой поправке уточнения.

6. **К-3:** UNRESOLVED на s = 2 вызывается подменой `pair_energy`: τ = Q, т. е. m₂ = 0,1. E1 вызывается подменой статуса.
