## 1. Что реализовано

Модуль `src/kkvim_reference/r5_cccc_halfstep.py`.

**Система полушага** (NS 4.2–4.3, ЧФ-C1/C2). По заданному набору G на сетке G(l_f, n_f):
- A = h_f GᵀG, B = −h_f GᵀL_fG, C = h_f GᵀD4_fG, F = q h_f Gᵀ𝟏;
- K = D[A ⊗ D4_s − 2B ⊗ L_s + C ⊗ I], K vec(S) = F ⊗ 𝟏, порядок «сначала индекс члена»;
- Y-полушаг: заданный набор по x, решаемый по y; X-полушаг — наоборот.

| Контроль | Путь вычисления | Полнота |
|---|---|---|
| **R-H** | ограничение гессиана полного функционала Π_h^C на подпространство полушага: K_H = (D hₓh_y/h_s)·Pᵀ𝒜P, правая часть (q hₓh_y/h_s)·Pᵀ𝟏. 𝒜 = Hess Π_h^C/(D hₓh_y) собран из трапеций и чётной второй разности с фиктивным узлом — функция QA `r5_cccc_d2.energy_hessian` (Предложение D, PR #27). P — вложение неизвестных полушага в узловое поле: G ⊗ I для Y и [I ⊗ G_:k]_k для X | полный для N = 1, 2, 3 и обеих ориентаций; плотное решение, малые сетки (n ≤ 32) |
| **R-AC** | коэффициенты A, B, C, F в плавающей точке; блочно-пятидиагональная SPD-матрица в порядке «узел — член» (индекс jN + i, половина ширины ленты 3N − 1, У-R1); ленточный Холецкий; итеративное уточнение с невязкой **исходного** оператора (R-HP) | полный; любые n (проверено до n_s = 512) |
| **R-HP** | невязка F ⊗ 𝟏 − K vec(S) в **точной рациональной** арифметике: коэффициенты из заданных double, D4 применяется поузлово по шаблону со строками (7, −4, 1), без модального преобразования (NS 5, «Контроль решения»); η_QA по нормировке NS 5 с h решаемого направления (У-R2) | полный |
| **Строгая апостериорная граница** (дополнение QA) | ‖ŝ − s*‖₂ ≤ ‖r‖₂/λ_low: r — точная невязка R-HP; λ_low ≤ λ_min(K) подтверждается разложением Холецкого K − τI (ленточным, в `decimal`, 50 знаков) с учётом обратной ошибки разложения и преобразования элементов; s* — точное решение системы с точными коэффициентами заданного набора | собственный вывод QA, уровень Б (стандартные оценки обратной устойчивости Холецкого). **Нужна сверка Reviewer** |
| **Диагностика набора** | точный ранг (рациональная арифметика, без порога); статусы `INDEPENDENT_GIVEN_SET`, `EXACTLY_DEPENDENT_GIVEN_SET`, `NUMERICAL_FACTORIZATION_FAILED`; cond(A), cond(K), условие 2N < n_f | значения без вердиктов |

Стартовые наборы 𝒯_N: базис sin²(iπl/n) и базис произведений sin(πl/n)·sin((2i − 1)πl/n) (CM ВБC-15).

## 2. Независимость путей

| Пара | Общие элементы | Независимо |
|---|---|---|
| R-H и коэффициентный путь (R-AC) | заданный набор и функционал | R-H — двумерный гессиан (Ł, W, E; модуль D2), без формул A, B, C. R-AC — одномерные формулы A, B, C, F и D4 = L² + угловая поправка |
| R-HP и оба решателя | функционал | точная арифметика; D4 — явный шаблон со строками (7, −4, 1), а не L² + E₂; без DST |
| R-AC и R-HP | R-AC уточняет решение по невязке R-HP — так требуют PL 2.1 и D-049.2 | уточнённое решение R-AC не независимо от R-HP. Поэтому сравнение R-H с R-AC ведётся по строгим границам, а не по невязке |
| Все контроли и Builder | — | `kkvim` не импортируется (статический тест независимости пакетов и проверка `sys.modules` в отдельном процессе) |

## 4. Численные наблюдения (OBSERVATION)

Источник: `docs/results/r5_cccc_halfstep/chain.csv` и `ill_conditioned.csv` (скрипт `scripts/r5_cccc_halfstep_observations.py`, ≈ 6 с).

**Цепочка сеток.** hₓ = h_y, n_f × n_s от 16 × 16 до 256 × 512, N = 1, 2, 3, обе ориентации.

| Величина | Диапазон |
|---|---|
| cond(K) | 8,1·10² (16 × 16, N = 1) … 2,6·10⁸ (256 × 512, N = 3) |
| R-H − R-AC, ‖·‖₂/‖s‖₂ (n ≤ 32) | 6,4·10⁻¹⁵ … 9,5·10⁻¹³ |
| строгая граница, R-AC без уточнения | 6,2·10⁻¹⁴ … 1,9·10⁻⁸ |
| строгая граница, R-AC с уточнением | 4,2·10⁻¹⁴ … 7,9·10⁻⁹ |
| последняя поправка уточнения e_AC (отн., **оценка**) | 5·10⁻¹⁷ … 8,7·10⁻¹⁷ |
| η_QA без уточнения / с уточнением | ≤ 1,1·10⁻¹⁶ / ≤ 5,8·10⁻¹⁷ |

**Что это значит:**
1. **Строгая граница ведёт себя как cond(K)·u и уточнением почти не улучшается** (в 1,1–2,9 раза). Любой вектор в double имеет невязку
   порядка ‖K‖·u·‖s‖, поэтому строгая граница не может быть меньше ~cond(K)·u. Оценка e_AC ~ u — правдоподобная, но **не гарантированная**.
   Это две разные величины: строгая граница — гарантия худшего случая, e_AC — оценка. Ни одна не является порогом.
2. R-H и R-AC совпадают намного точнее своих строгих границ.
3. η_QA мала на всех сетках; порог η_max^C не назначен (NS 5, D-049.2).

**Плохо обусловленные наборы без QR** (`ill_conditioned.csv`, 32 × 32, N = 2, G₂ = G₁ + εG₂):

| ε | cond(A) | cond(K) | λ_min подтверждено | строгая граница (отн.) | разность полей R-H / R-AC |
|---|---|---|---|---|---|
| 10⁻² | 7,3·10⁴ | 7,0·10⁷ | да | 1,3·10⁻⁹ | 1,6·10⁻¹⁰ |
| 10⁻⁴ | 7,2·10⁸ | 6,9·10¹¹ | да | 1,8·10⁻⁵ | 2,4·10⁻⁶ |
| 10⁻⁶ | 7,2·10¹² | 7,0·10¹⁵ | да | 1,9·10⁻¹ | 3,5·10⁻² |
| 10⁻⁸ | — | — | нет | — | оба пути: `NUMERICAL_FACTORIZATION_FAILED` |

При плохо обусловленном наборе ненадёжен и сам контроль: разность полей растёт примерно как cond(A)·u. Это согласуется с порядком NS 5.1:
диагностика → QR → решение. Контроли надо применять к набору после QR, как требует PL (BC-6 — наблюдение, BC-7 — после QR).

## 5. Ограничения

1. **Порогов нет.** η_max^C, tol_solve, cond(S), критерии ранга — решения владельца после квалификации (D-049.2, п. 5; D-049.6). Сравнения
   с Builder (BC-1…BC-15) не выполнялись: кода CCCC в `kkvim` нет и программирование не разрешено.
2. **e_AC — оценка, не граница.** Строгая граница вычисляется отдельно и гарантирует только уровень ~cond(K)·u.
3. **Строгая граница** опирается на собственный вывод QA об обратной ошибке Холецкого в `decimal`. Нужна сверка Reviewer. Если подтвердить
   λ_min не удалось, граница не вычисляется (UNRESOLVED), а не подменяется оценкой.
4. **R-H** — плотное решение, только малые сетки (n ≤ 32). Для больших сеток контрольной парой служат R-AC с R-HP и строгой границей.
5. **Энергетические величины** (BC-11, BC-12, ST-10) — бюджет не установлен, UNRESOLVED; эти контроли его не дают.
6. **Модель округления DST для 𝒦₀** (BC-14) — вне этой задачи, UNRESOLVED до вывода.
7. **Старт 𝒯_N.** Проверены точный ранг и нагрузка при 2N < n_f. Зависимость через наложение частот при N > ⌊n_f/2⌋ на значениях в double
   не проверяется: значения синусов округлены, точное равенство функций не сохраняется. Это доказано аналитически (CM ВБC-13, п. 4).
