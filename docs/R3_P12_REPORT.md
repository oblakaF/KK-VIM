П-12 — проверка численной согласованности двух независимых реализаций с документированными моделями округления (D-038, п. 5). Она не
является строгим доказательством ошибки полной floating-point реализации, не квалифицирует моменты и не переносится на группу A основного
решателя R3.

## 1. Методика (D-038, пп. 2–4; ничего не подбиралось по данным)

**Сравниваемые величины** — прогиб в нормировке qa⁴/D с исходной стороной a (Р-3), q = D = 1:
- **w_N** — `NavierRectangle(a, b, q=1, D=1, nu=0.3)`, M_N = 2559. Узлы сетки — `at_nodes(40, 40)`, остальные точки — `at_points`;
  берётся `w_coef`.
- **w_L** — полный ряд Леви (139): `levy_series_w_grid` для узлов, `levy_series_w` для точек, M_L = 1131. Функции возвращают физический
  прогиб, поэтому значение делится на qa⁴/D исходной пластины.

**Правило в каждой точке P:** |w_N(P) − w_L(P)| ≤ B_N + B_L + R_N(P) + R_L.

| Величина | Источник | Статус |
|---|---|---|
| B_N | ЧВ-R2: 0,0021881·r²/M_N² (`w_tail_bound_coef`), равномерно по полю | строгая (D-036, D-037) |
| B_L | ЧВ-Л4: (4/π⁵)/(8M_L⁴)·(a_L/a)⁴ (`levy_field_bounds(...).truncation` / (qa⁴/D)) | строгая, подтверждена Аудитором (`9919f32`) |
| R_N | модель округления Навье для применённого способа: `rounding_w` из `at_nodes` (узлы) или из `at_points` (точки, с вкладом округления аргумента) | модель, не строгая оценка |
| R_L | модель округления Леви `levy_field_bounds(...).rounding_model` / (qa⁴/D), одна для точек и сетки | модель, не строгая оценка |

**Контрольный набор (D-038, п. 3):**
- 10 пластин (a; b): (1; 0,2), (3; 1), (2; 1), (3; 2), (1; 1), (1; 1,4), (2; 3), (1; 2), (1; 3), (1; 5);
- в каждой:
  - сетка 41 × 41 (x_i = ia/40, y_j = jb/40, включая края) — 1681 узел;
  - 36 точек около краёв: x ∈ {10⁻³a, 10⁻⁶a, 10⁻⁹a, a − 10⁻³a, a − 10⁻⁶a, a − 10⁻⁹a} при y ∈ {b/4, b/2, 3b/4}, и так же по y при
    x ∈ {a/4, a/2, 3a/4};
  - центр (a/2, b/2);
- итого 1718 сравнений на пластину. Только прогиб.

**Запас:** (B_N + B_L + R_N + R_L)/|w_N − w_L|; при нулевой разности (края) — ∞. Положение минимального запаса — наблюдение, не критерий.

**Превышения:** при любом превышении скрипт обязан независимо пересчитать **оба** усечённых ряда при тех же M_N, M_L и координатах в mpmath
(45 знаков).
- **FAIL** — |Δ_hp| > B_N + B_L сохраняется.
- **UNRESOLVED** — |Δ_hp| ≤ B_N + B_L, то есть превышение вызвано недостаточностью моделей округления; либо пересчёт невозможен.

Объяснять превышение округлением без пересчёта нельзя. В этом прогоне превышений нет (разд. 2).

## 3. Диагностика (не критерии)

**Высокоточная проверка точек минимального запаса.** Необязательный режим `--hp-min-margin`: для каждой пластины точка минимального запаса
пересчитана в mpmath (45 знаков), оба ряда — при тех же M. Результаты — `docs/results/r3/p12/hp_rechecks.csv`:
- ошибка double каждого ряда против его высокоточного значения;
- Δ_hp против B_N + B_L.

Итог по всем 10 точкам:
- ошибки double обоих рядов ≤ 4,5·10⁻²⁰ qa⁴/D, то есть оба ряда вычислены практически точно;
- Δ_hp совпадает с разностью в double во всех знаках, существенных для сравнения;
- |Δ_hp| ≤ B_N + B_L везде.

Точки минимального запаса лежат у краёв на расстоянии 10⁻³ стороны. Разности там реальны: это фактический хвост ряда Навье у края, см. ниже.

**Происхождение максимальной разности.** Глобальный максимум |w_N − w_L| = 3,137·10⁻¹⁵ qa⁴/D: пластина (1; 5), точка (a/4; 10⁻³b).
Высокоточный пересчёт даёт:
- ошибки double: Навье 6·10⁻²¹, Леви 1,5·10⁻²⁰;
- Δ_hp = −3,137·10⁻¹⁵, то есть разность **реальна** — это не округление.

## 4. Ограничения

- R_N и R_L — **модели** округления первого порядка с запасом, а не строгие оценки. Высокоточные пересчёты (разд. 3) показывают, что они
  консервативны в проверенных точках; строгой границы округления нет (D-037, п. 3; D-038, п. 2).
- B_N на 4–7 порядков больше фактических разностей. Правило D-038 обнаруживает грубые ошибки (формул, ориентации, нормировки, уровней),
  но не различает разности на уровне 10⁻¹⁵. Более тонкое сравнение потребовало бы нового решения владельца.
- Только прогиб; моменты не сравнивались (D-034, п. 3; Q-030). Табл. 8 L-107 — только справочно (Р-6).
- П-12 подтверждает согласованность эталонов R3 между собой. Она не квалифицирует основной решатель R3 (Р-7, Р-8, Р-9) и не доказывает
  сходимость КК-МВИ по s.

## 5. Воспроизведение

Из корня репозитория:

```
uv run python scripts/r3_p12_study.py                                  # points.csv, plates.csv, metadata.json, блоки отчёта
uv run --with mpmath python scripts/r3_p12_study.py --hp-min-margin    # плюс hp_rechecks.csv (диагностика, нужен mpmath)
uv run python -m pytest tests/cross/test_r3_p12.py
```

- Основной расчёт занимает несколько секунд; высокоточная диагностика — около 10 с на точку.
- mpmath не входит в зависимости проекта. Он нужен только для пересчёта: обязательного при превышении и диагностического по флагу.
- Если превышение есть, а mpmath недоступен, вердикт — UNRESOLVED.
- Метаданные запуска (коммит, версии Python и NumPy, платформа, параметры D-038) — `docs/results/r3/p12/metadata.json`.
  Поле `commit` — проверенная база эталонов (`6765d7e`). `dirty = true`: скрипт и отчёт этой работы на момент прогона ещё не были
  зафиксированы. Исходники эталонов при этом не менялись.
- Значения на другой машине могут отличаться в последних битах: матричные произведения BLAS суммируют в порядке, зависящем от CPU.
  Тест сверяет пересчёт с сохранёнными данными в пределах моделей округления, а не побитно.
