## 3. Плотное DST (`sine_matrix`, `src/kkvim/coupled.py:173-176`)

**Текущий код:** `math.sqrt(2.0 / n) * np.sin(np.outer(i, i) * math.pi / n)`. Аргумент ikπ/n доходит до ≈ (n − 1)²π/n без приведения; абсолютная
ошибка аргумента ≈ 2,35u·θ растёт с n.

**Независимое воспроизведение** (эталон — 50 знаков; Ψ зависит только от m = ik mod 2n, поэтому хватает 2n эталонных значений на сетку).
«Мой» текущий вариант побитово совпадает с `kkvim.coupled.sine_matrix`.

| n | Текущий код: max\|err\|/(u√(2/n)) / отн. | `% (2n)`: max\|err\|/(u√(2/n)) / отн. | Приведение к [0, n/2] со знаком: … / отн. |
|---|---|---|---|
| 40 | 144 / 1,7·10³u | 5,2 / 66u | 1,1 / 2,1u |
| 160 | 697 / 1,9·10⁴u | 8,1 / 164u | 1,1 / 2,1u |
| 640 | 3,0·10³ / 4,4·10⁵u | 8,1 / 683u | 1,1 / 2,9u |
| 1280 | 6,1·10³ / 2,0·10⁶u | 8,1 / 807u | 1,6 / 3,1u |

Относительная ошибка считалась без точных нулей Ψ (ik ≡ 0 mod n).

Преобразование импульсов (e₁, e_mid, e_{n−1}) при n = 1280, ‖ошибка‖₂/(u‖x‖₂):

| Вариант | Ошибка |
|---|---|
| текущий код | 1,7·10³ (подтверждает B3 QA) |
| `% (2n)` | 2,5 |
| полное приведение | 0,8 |
| `fft` | 1,4 |

**Заключение по предложенному исправлению `(np.outer(i, i) % (2 * n)) * math.pi / n`:**
1. **Математическая эквивалентность — да.** sin периодичен с периодом 2π: sin(πm/n) = sin(π(m − 2nt)/n) для целого t. Для ik < 2n новые элементы
   побитово равны текущим (проверено).
2. **Целочисленная корректность — да.** `np.outer` от `np.arange` даёт int64 (проверено на этой платформе; numpy ≥ 2 и на Windows),
   ik ≤ (n − 1)² ≈ 1,6·10⁶ при n = 1280. Переполнения нет, остаток точен.
3. **Модель QA ≤ 7u к этому порядку операций не применима.** Модель QA (`kkvim_reference/r4_dst_check.py`) — **относительная** оценка
   |Ψ̂ − Ψ| ≤ 7u|Ψ|. Её предпосылка — приведение к r ∈ [0, n/2], т. е. аргумент в [0, π/2], где |x·ctg x| ≤ 1. После `% (2n)` аргумент лежит в
   [0, 2π). Около sin = 0 при θ ≈ π и 2π абсолютная ошибка аргумента ≈ 2,35u·π даёт неограниченную относительную ошибку: замерено до 807u.
   Для варианта `% (2n)` справедлива только **абсолютная** оценка первого порядка:
   |Ψ̂_ik − Ψ_ik| ≤ √(2/n)·(2,35u·2π + 2u + 1,5u + u) ≈ 19,3u·√(2/n). Это вывод Auditor первого порядка, при предпосылке «sin в пределах 1 ulp на
   [0, 2π)»; QA проверял её только на [0, π/2]. Замер — ≤ 8,1u·√(2/n).
4. **Достаточность.** `% (2n)` **устраняет рост с n** — ошибка элемента ограничена константой, импульсы ≤ 2,5u. Как контроль точности на
   больших сетках этого достаточно, если в D-048 или в тесте записана абсолютная модель п. 3. Чтобы `dense` подпадал под **заранее
   выведенную** модель QA — покомпонентную (7u + γ_{n−1}(1 + 7u))|Ψ||x|, единственную априорную оценку DST в проекте, — нужно **полное
   целочисленное приведение** к [0, n/2] со знаком:
   - m = ik mod 2n;
   - при m ≥ n: m ← m − n и знак −1;
   - при 2m > n: m ← n − m.

   Замер: ≤ 3,1u относительно. Даже тогда ошибка самого умножения `dense` содержит γ_{n−1}, то есть растёт как O(n·u) в худшем случае;
   основным путём остаётся `fft`.
5. **Адресные тесты для Builder** (допуски — из априорной модели, зафиксированной до прогона, не по наблюдению):
   - (а) побитовое равенство новых и старых элементов при ik < 2n (только для варианта `% (2n)`);
   - (б) точные нули Ψ при ik ≡ 0 mod n и антисимметрия знака (для полного приведения);
   - (в) элементы против высокоточного эталона при n = 40, 160, 640, 1280 по таблице 2n значений — с `pytest.importorskip("mpmath")`, вне
     обязательного CI;
   - (г) преобразование импульсов e₁, e_mid, e_{n−1} при n = 1280: `dense` против `fft` и против эталона, в пределах модели;
   - (д) проверка предпосылки «np.sin ≤ 1 ulp» на фактическом диапазоне аргументов, на платформах CI (ubuntu, windows);
   - (е) результаты `transform="fft"` побитово не меняются. Для `dense` — сравнение по модели, а не побитово (AGENTS.md, разд. 4).

Исправление в код не вносилось. Математическая граница по численным испытаниям не объявляется доказанной: оценки выше — первого порядка и
условные.

## 4. Статус стабилизации поля (CONVERGED)

- **Что означает правило R2 (NUMERICAL_SPEC 11.3, п. 2).** Остановка при ε^∞ ≤ tol_∞ и ε^E ≤ tol_E на s − 1 и s, s ≥ s_min. Это критерий
  **стабилизации поля** конечной дискретной задачи при фиксированном N. Он инвариантен к представлению (поле, энергетическая норма) —
  это согласуется с ВР4-8.
- **Чего он не означает:**
  - сходимости к ω₀ (ошибка метода при фиксированном N положительна — ВБ-19, Q-025);
  - сходимости последовательности при s → ∞ (не доказана; малое ε_s — не доказательство, ЧВ-13);
  - сертификации ранга (c_d, c_rank, τ_set, δ_f — NOT_QUALIFIED; S-2 не квалифицирован).
- **Связь с продолжением через QR.** В обычном режиме `run_coupled` останавливается после s = 1 (NOT_QUALIFIED). CONVERGED достижим только
  при продолжении через QR. Поэтому решение о статусе стабилизации **неотделимо** от п. Р-1: без утверждённого (хотя бы временного)
  критерия продолжения CONVERGED в обычном режиме недостижим.
- **Рекомендация владельцу** (выбор за ним):
  - **(а)** отдельный статус, например «стабилизация поля, PROVISIONAL», не совпадающий с CONVERGED R2/R3. Это исключает смешение с
    квалифицированным CONVERGED принятых этапов;
  - **(б)** имя CONVERGED с обязательной пометкой PROVISIONAL / NOT_QUALIFIED на результате и определением в D-048: «стабилизация поля
    конечной задачи; не сходимость к ω₀; ранг не сертифицирован».

  В обоих вариантах статус допустим только после пройденных защит ранга на всех полушагах. Пометку PROVISIONAL снимать нельзя, пока
  не квалифицированы δ_f и критерий ранга.
- **Эмпирическая опора** (B6 и воспроизведение): правило срабатывает при s = 9…12 ≪ s_max. Дрейф центра после остановки ≤ 2,6·10⁻⁶ от
  ошибки w_h − ω₀, энергии — ≤ 2,5·10⁻¹⁵. Это наблюдения, не гарантия.
