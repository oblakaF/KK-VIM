## 2. Проверка по пунктам

### 2.1. Контроллер (Б-1, Б-2)

Порядок полушага s (`coupled_run.py`, `run_coupled`):
1. решение;
2. невязка и уточнение;
3. ранговая диагностика;
4. энергия, затем ERROR_DEGENERATE и E1;
5. конечность;
6. **защиты ранга и набора**;
7. стабилизация;
8. S_MAX;
9. лимит полушагов;
10. QR.

Ни один статус остановки исследовательского режима (PROVISIONAL_FIELD_STABILIZED, MAX_HALF_STEPS, RESEARCH_LIMIT_REACHED) **не предшествует защитам** — D-048.4 и C-1 выполнены.

- **Стабилизация:** `stabilized = s ≥ S_MIN and stab_ok(s) and stab_ok(s−1)`, где stab_ok = (ε^∞ ≤ 10⁻¹⁰ и ε^E ≤ 10⁻⁸). Совпадает с NUMERICAL_SPEC 11.3, п. 2 и с реализацией R2 (`controller.stopping_decision`): s−1 может быть равно 2 при s = 3.
- **Константы:** tol_∞ = 10⁻¹⁰, tol_E = 10⁻⁸, s_min = 3, s_max = 100, η_max = 10⁻¹², K_RESEARCH = 10⁶ — по D-048.2, 3, 5.
- **ε_floor:** ε_floor^(N) = 10u(max(n_x, n_y)/π)²√N/(1 − γ_N√N), γ_N = Nu/(1 − Nu) — совпадает с D-048.3 и R4_NUMERICAL_SPEC 6.3. Нарушение tol_E ≥ 10ε_floor даёт ERROR_INPUT только в исследовательском режиме. Граница при N = 3 — n ≈ 2265: сетки D-048 до 1600 правило проходят.
- **S_MAX:** `last = min(half_steps, S_MAX)`, полушага сверх S_MAX нет. s = S_MAX ⇒ MAX_HALF_STEPS (при half_steps ≥ S_MAX). Явный half_steps < S_MAX без стабилизации ⇒ RESEARCH_LIMIT_REACHED.
- **Ранг:** S-1 присваивается только при доказанной зависимости (n < 2N, ERROR_DEGENERATE решателя); PROVISIONAL_RANK_GUARD_STOP и PROVISIONAL_SET_GUARD_STOP — до QR, N сохраняется; S-2 не присваивается (`check_run`).
- **CONVERGED** не используется (`converged` всегда False).

### 2.4. Невязка (Б-4)

- `refine_once` (`coupled.py`) делает ровно один шаг:
  - ρ = F ⊗ 1 − K vec(V) вычисляется в узлах (`coupled_operator`, разностные операторы, без DST);
  - коррекция решается теми же модальными системами D·M_k·δ̂_k = (Ψρ)_k с M_k = μ_k²A + 2μ_kB + C — тот же вывод, что ЧФ-3;
  - V ← V + Ψδ̂, `modal` обновляется согласованно.
- После уточнения η_N вычисляется **заново** по узловой невязке (`coupled_residual`). Если η_N > η_max — ERROR_LINEAR_SOLVE, при неконечном значении — ERROR_NONFINITE. Отказ Холецкого при коррекции — ERROR_LINEAR_SOLVE; неконечная модальная невязка или результат — ERROR_NONFINITE.
- Условие `not (eta <= ETA_MAX)` корректно обрабатывает NaN.
- Контроль только при `research_mode=True` — по дополнению к D-048.
- Тесты инъекцией возмущения и ошибочной коррекции покрывают обе ветви.

### 2.5. Dense (Б-5)

**Математическая корректность целочисленного приведения** (`sine_matrix`):
- m = ik mod 2n;
- m ≥ n ⇒ sin(πm/n) = −sin(π(m − n)/n);
- 2m > n ⇒ sin(πm/n) = sin(π(n − m)/n);
- аргумент лежит в [0, π/2];
- m = 0 ⇒ точный +0.0, включая устранение −0.0 при m = n.

Все ветви верны. Переполнения int64 нет при n < 3·10⁹; практическое ограничение — память n².

**Независимая проверка рецензента** (mpmath, 30 знаков, sin(π·m/n) только с периодом 2n, **без** формул отражения — в отличие от эталона теста Builder, который использует ту же редукцию):

|---|---|---|---|---|---|---|
| 40 | 101 | 0 | 0 | 0 | 2,14u | да |
| 160 | 689 | 0 | 0 | 0 | 2,14u | да |
| 640 | 3905 | 0 | 0 | 0 | 2,70u | да |
| 1280 | 8961 | 0 | 0 | 0 | 2,00u | да |

Матрица симметрична побитово.

**Разделение.**
- Математическая корректность приведения доказана построчно и подтверждена до n = 1280.
- Модель 7u — условная (предпосылка: np.sin в пределах 1 ulp на [0, π/2]); на этой платформе она выполнена эмпирически. Это не квалификация c_DST (NOT_QUALIFIED, D-048.6). Применение dense до n = 1280 — после независимой проверки QA.

## 3. Дефект Д-1 (блокирующий)

**Где:** `src/kkvim/coupled_run.py:234` (`return close(Fraction(n_y, n_x))`) и вызов `src/kkvim/coupled_run.py:335` (`is_mandatory_s2_grid(a, b, n_x, n_y)`), куда передаются **исходные** аргументы n_x, n_y, а не `int(n_x)`, `int(n_y)` (как в `params`).

**Суть:**
- `Fraction(np.int64(320), np.int64(1600))` хранит числитель и знаменатель как `np.int64`;
- при сравнении с `Fraction(b)` произведение с большими Python-целыми не помещается в int64, и возникает `OverflowError: int too big to convert`;
- исключение не перехватывается, и `run_coupled` вместо статуса выбрасывает его на s = 2.

**Воспроизведение:**

```python
import numpy as np
from kkvim.coupled_run import run_coupled, is_mandatory_s2_grid
is_mandatory_s2_grid(1.0, 0.2, np.int64(1600), np.int64(320))   # OverflowError
run_coupled(1.0, 0.2, 1.0, 1.0, np.int64(1600), np.int64(320), 2, transform="fft",
            half_steps=2, research_mode=True)                     # OverflowError (uncaught)
```

На `main` @ `8c4dbe1` тот же вызов `run_coupled` возвращает RESEARCH_LIMIT_REACHED, s = 2, то есть это **регрессия**. С целыми Python результат на ветке правильный (mandatory = True).

Затронуты все шесть пар семейства II при numpy-целых размерах. Семейство I не затронуто: там сравнение идёт с `CONTROL_R` из целых Python.

**Требуемое исправление (Builder):** приводить размеры к `int` — например, вызывать `is_mandatory_s2_grid(a, b, params.n_x, params.n_y)` и/или `Fraction(int(n_y), int(n_x))` внутри функции. Добавить модульный тест с `np.int64` размерами для обеих функций.
