## 1. Математическая независимость двумерного спектрального контроля (`r4_spectral_control.py`; отчёт, разд. 2)

### 1.1. Вывод из Π_h

Принятый функционал (R4_NUMERICAL_SPEC 2.1): Π_h(w) = ½D h_x h_y Σ(Δ_h w)² − q h_x h_y Σw, суммы по внутренним узлам,
Δ_h = L_x ⊗ I + I ⊗ L_y.

| Шаг QA | Проверка | Результат |
|---|---|---|
| Ψ_ik = √(2/n) sin(πik/n): симметрична, ортогональна, Ψ² = I; −L = Ψ diag(μ)Ψ, μ_k = (4/h²)sin²(kπ/(2n)) | стандартный спектр матрицы Дирихле; совпадает с R4_NUMERICAL_SPEC 2.2, п. 2 и тестом QA против явной L | верно |
| Ŵ = Ψ_x W Ψ_y, W = Ψ_x Ŵ Ψ_y; Δ_h W = −Ψ_x(diag(μˣ)Ŵ + Ŵ diag(μʸ))Ψ_y | L_y симметрична, Ψ инволютивна | верно |
| a_h = D h_x h_y Σ λ_kl Ŵ_kl², **λ_kl = (μˣ_k + μʸ_l)²** | ‖·‖_F инвариантна относительно ортогональных Ψ | верно; множитель h_x h_y — тот же, что в Π_h |
| l_h = q h_x h_y cˣᵀŴcʸ, c = Ψ𝟏 | 𝟏ᵀW𝟏 = (Ψ𝟏)ᵀŴ(Ψ𝟏) | верно; правая часть — сумма по внутренним узлам, как в 2.1 |
| Π_h = ½Dh_xh_y Σλ(Ŵ − Ŵ*)² − ½Dh_xh_y ΣλŴ*², Ŵ* = q cˣcʸ/(Dλ) | раскрытие квадрата: λŴ* = q cc/D | верно |
| Y-полушаг: W = UVᵀ ⇒ Ŵ = ÛV̂ᵀ; при свободной V̂ задача распадается по y-модам l: min Σ_k λ_kl(Û_k·v_l − Ŵ*_kl)² | Ψ_y невырожденна, поэтому свободная V ⇔ свободная V̂; Ŵ_kl = Û_k·v_l | верно |
| X-полушаг — замена x ↔ y | код: `_weighted_lstsq(sq, V̂, W*)`, строки — x-моды | верно |
| Ортонормирование заданного набора | QR в спектре = ортонормирование в узлах (Ψ ортогональна); span не меняется (ВБ-16; R4_NUMERICAL_SPEC 2.6, п. 5) | верно |

**Связь с принятой системой.** Нормальные уравнения задачи моды l:

Σ_k λ_kl Û_kÛ_kᵀ = μ_l²(ÛᵀÛ) + 2μ_l Ûᵀdiag(μˣ)Û + Ûᵀdiag(μˣ²)Û,

что с точностью до h_x совпадает с M_l = μ_l²A + 2μ_lB + C (ЧФ-3). Значит, QA решает **ту же** вариационную задачу на M_h(U), а не близкую
альтернативную. Совпадает «+2μB» (R4_NUMERICAL_SPEC 2.3).

### 1.2. Независимый численный пересчёт (скрипты A, A2)

Собственная плотная сборка Δ_h произведениями Кронекера в **узловом** пространстве, без DST и без спектральных весов. На каждом
полушаге:
- ортонормированный базис span(U) берётся через SVD, а не QR;
- решается min‖Δ_h G v − z‖, где z = Δ_h ω_h;
- используется `lstsq`, без нормальных уравнений.

Охват: N = 2, 3; r = 0,2; 1; 5; сетки (12, 20), (20, 12), (24, 40), (40, 16); s = 1…6.

**Отличие от полей `run_control` — не больше 5,2·10⁻¹³ отн.**

Вариант через нормальные уравнения (GᵀKG) даёт 2,2·10⁻¹¹ и энергию до 1,9·10⁻¹¹. Это ожидаемая потеря от cond(ΔᵀΔ) в моём пути, а не
ошибка QA. Тем самым проверены разные n_x ≠ n_y, оба направления полушагов и множители h_x h_y.

**Статус: VERIFIED** — алгоритм QA решает ту же дискретную задачу КК-МВИ.

### 1.4. Узловая проверка стационарности (`projection_residual`) — ограничение интерпретации

Невязка стационарности нормирована на масштаб округления |Δ_h|²|W|. Этот масштаб растёт ~n⁴, поэтому чувствительность к ошибке поля падает
~n⁻⁴ (скрипт A3, r = 1, N = 2, s = 2):

| n | гладкая ошибка поля 10⁻⁶ | 10⁻⁸ | отброшен член 2B (поле неверно на 100 %) |
|---|---|---|---|
| 40 | 2,4·10⁻¹² | 2,4·10⁻¹⁴ | 1,1·10⁻⁶ |
| 80 | 1,5·10⁻¹³ | 1,6·10⁻¹⁵ | 7,0·10⁻⁸ |
| 320 | 6,8·10⁻¹⁶ | 1,1·10⁻¹⁶ | 2,8·10⁻¹⁰ |

При пороге теста 10⁻¹³ проверка надёжно ловит **ошибки формулы**, но не подтверждает **точность поля**: при n = 320 ошибка 10⁻⁶ проходит.

**Статус:** как проверка формулы — VERIFIED; как мера точности поля — **NOT_VERIFIED** (Р-7).

Количественная точность контроля подтверждается иначе:

### 2.1. Особое внимание — r < 1

Потеря точности ЧВ-Л1 при α_m < π/2 подтверждена:

| α | 0,157 | 0,314 (r = 0,2, m = 1) | 0,524 | π/2 | 3 |
|---|---|---|---|---|---|
| отн. ошибка скобки T | 1087u | 160u | 51u | 8,9u | 3,8u |

**Причина:**
- T = O(α⁴) при малом α: прогиб ограничен короткой стороной b, а C₀ ∝ a⁴;
- в любой форме, составленной из величин порядка единицы, T вычисляется с вычитанием;
- ошибка растёт примерно как u/α⁴;
- устойчивая форма ЧВ-Л1 устраняет переполнение, но не это вычитание.

Абсолютная ошибка Леви-x при r = 0,2 — 1,1–1,3·10⁻¹⁴ от max|w|. Это много меньше любого сравнения, но модели округления не соответствует.

## 3. QA-δ2: DST-I (`r4_dst_check.py`; отчёт, разд. 4)

**Совпадение с SciPy.** `scipy.fft.dst(type=1, norm="ortho")` = Ψx — проверено тестом QA при n = 4…640.

### 3.1. Оценка плотного произведения

Утверждение: |fl(Ψ̂x) − Ψx| ≤ (7u + γ_{n−1}(1 + 7u))|Ψ||x| покомпонентно.

Собственный счёт ошибки элемента Ψ̂ = fl(√(2/n))·fl(sin(fl(fl(π·r)/n))), r ∈ [0, n/2]:

| Источник | Вклад |
|---|---|
| аргумент: fl(π) (0,35u) + умножение (u) + деление (u) | ≤ 2,35u отн. |
| перенос ошибки аргумента в sin: множитель \|x ctg x\| ≤ 1 на (0, π/2] | ≤ 2,35u |
| собственная ошибка sin: 1 ulp | ≤ 2u отн. |
| √(2/n) | ≤ 1,5u |
| произведение | u |
| **итого** | **≤ 6,85u ≤ 7u** |

Оценка **верна**, но с запасом лишь 0,15u. Перечень в docstring QA не называет ошибку представления fl(π) и неявно считает 1 ulp = u
(редакционно, Р-8).

Модель произведения γ_{n−1}|Ψ̂||x| справедлива при любом порядке суммирования и с FMA. Предполагается классическое произведение без
алгоритмов типа Штрассена, что для OpenBLAS dgemm выполняется.

**Значения у нуля:**
- r ≡ 0 mod n даёт точный нуль благодаря целочисленной редукции;
- малые аргументы ≥ π/n не дают исчезновения порядка;
- относительная модель sin применима;
- оценка покомпонентна относительно |Ψ||x|, поэтому сокращение в самом Ψx допустимо.

**Предпосылки проверены исчерпывающе на этой платформе** (скрипт C, все n = 2…1280 и все r ≤ n/2):

| Величина | Измерено | Допущено QA |
|---|---|---|
| ошибка `np.sin` (векторный путь NumPy 2.5.4) | ≤ 0,762 ulp | ≤ 1 ulp |
| ошибка аргумента | ≤ 2,24u | — |
| ошибка элемента Ψ̂ | ≤ 4,17u | 7u |

Тест QA с 40 знаками (n ≤ 640) нарушений не нашёл; наибольшее отношение «ошибка / оценка» — 0,27.

**Разделение по уровню доказательности:**

| Утверждение | Статус |
|---|---|
| строго доказано в стандартной модели при предпосылках sin и BLAS: оценка плотного произведения | **VERIFIED** |
| подтверждено исчерпывающе только для Windows + NumPy 2.5.4, n ≤ 1280: предпосылка точности sin | VERIFIED на этой платформе; для других платформ, версий NumPy и n > 1280 — **NOT_VERIFIED** (дешёвая исчерпывающая проверка рекомендуется) |
| только эксперимент: быстрый DST | норма ошибки ≤ 2,34·u·log₂n·‖x‖₂, покомпонентно до 40,5u\|Ψ\|\|x\| |
| не проверено для SciPy | алгоритм и точность поворотных множителей `scipy.fft` (pocketfft); **c_DST — NOT_VERIFIED** |

**Наблюдение 2,34 не выдаётся за константу.** Отчёт прямо говорит «не является константой модели и не предлагается как норматив».

### 4.1. Новая оценка δ_f(storage) ≤ κ_rep(2√N·u + N·u²)

**Вывод.**
- Пусть Û = U* + δU, |δU| ≤ u|U*| покомпонентно, тогда ‖δU‖₂ ≤ ‖δU‖_F ≤ u‖U*‖_F ≤ u√N‖U*‖₂; то же для V.
- Тождество δW = δU·V*ᵀ + U*·δVᵀ + δU·δVᵀ (R4_NUMERICAL_SPEC 5.2, п. 6(ф)) после деления на σ₁(W*) даёт заявленную оценку.
- **Доказательство верно.**

**Ответы на вопросы задания.**
- **К какому представлению относится κ_rep.** К **точному** (вещественному) представлению, которое округляется, во **взвешенных** факторах:
  κ_rep = ‖U*_w‖₂‖V*_w‖₂/σ₁(W*_w), где U*_w = √h_x·U*, V*_w = √h_y·V*, W* — точное поле.
  Например, (U*T, V*T⁻ᵀ) для точной T. Это совпадает с условием НА-2 (5.2, п. 6).
- **Какие операции покрыты.** **Только одно** корректное округление каждого элемента взвешенных факторов при записи в double.
  - **Образование** взвешенных факторов из уже сохранённых, fl(√h·U), добавляет ещё одно округление на элемент. Тогда в той же форме
    получается ≤ κ_rep(4√N·u + O(u²)).
  - Ошибка самого fl(√h) — общий скалярный множитель: на ρ_N и κ_rep он не влияет, в δ_f входит как относительный сдвиг ≤ u.
  - Ошибки вычисления факторов (решение мод, сборка, DST, перенос по s) оценкой **не покрываются**.
- **Можно ли взять κ_rep сохранённых массивов.** Только с поправкой. Положим e := 2√N·u + N·u², κ′ := κ̂_rep/(1 − √N·u)², где κ̂_rep
  вычислен точно по сохранённым массивам. Тогда при e·κ′ < 1 строго κ_rep,точн ≤ κ′/(1 − e·κ′):
  - ‖U*‖ ≤ ‖Û‖/(1 − √N·u);
  - σ₁(W*) ≥ σ₁(Ŵ) − e‖U*‖‖V*‖.

  Сверх этого нужна ошибка **вычисления** κ̂_rep через QR/SVD — постоянная типа c_d, **NOT_VERIFIED**. В первом порядке величины совпадают.
  Скрипт D: κ_точн и κ_сохр совпадают в 5 знаках при κ ≈ 7·10³ и 7·10⁷.
- **Численная проверка (скрипт D).**
  - Точные рациональные факторы, округлённые один раз: δ_f = 1,5·10⁻¹³…1,8·10⁻⁹ при оценке 2,8·10⁻¹²…2,8·10⁻⁸ — **выполняется**.
  - Вычисленные факторы конструкции QA: δ_f = 2,1·10⁻¹³…3,2·10⁻⁹ — примерно вдвое больше чистого хранения. Ниже оценки, но не
    покрывается её выводом.
- **Перенос на накопленную δ_f не допускается.** QA этого и не делает (отчёт, табл. разд. 5: «δ_f от решения мод … накопления —
  NOT_VERIFIED»).

**Статус оценки хранения: VERIFIED** с условиями, перечисленными выше.

### 6.1. Неточность docstring про m²n²

- m²n² для нечётных m, n — нечётное целое, поэтому оно точно в binary64 ⇔ m²n² ≤ 2⁵³. Достаточно M⁴ ≤ 2⁵³, т. е. **M ≤ 9741** (наибольшее
  нечётное; 9743⁴ > 2⁵³).
- Утверждение «точно при M ≤ 9999» **неверно**: при M = 9999 округляются 32 985 произведений (при M = 9743 — три).

Собственный счёт первого порядка в стандартной модели:

| Шаг | Вклад |
|---|---|
| a², b², n²/b², m²/a², сумма двух положительных | ≤ 3u |
| квадрат | ≤ 7u |
| × m²n² (точно при M ≤ 9741, иначе +u) | ≤ 8u (9u) |
| обращение | ≤ 9u (10u) |
| два `math.fsum` | ≤ 11u (12u) для S |
| константа: a·b (u), math.pi⁸ (8 × 0,35u + 1 ulp ≤ 2u), ·D, деление | ≤ 7,8u |
| q·const, ·S, −½q·J | 3u |
| **итого** | **≤ 21,8u** (≤ 22,8u при 9741 < M ≤ 9999) **≤ 24u** |

Перечень QA (9u + u + u + 13u = 24u) **пропускает три последних умножения** и завышает константу. Итог 24u всё равно верен.

Предпосылка `pow` проверена на этой платформе: π⁸ — 0,39 ulp.

**Ответы на вопросы задания.**
- Правильная область гарантированной точности произведений: M ≤ 9741.
- Ограничить M до 9741 **или** учесть одно лишнее округление на член — оба варианта сохраняют 24u.
- Бюджет 24u **не меняется**.
- Фактические результаты при M = 4001 **не затронуты**: 4001⁴ = 2,56·10¹⁴ < 2⁵³. Измерено ≤ 6,2u.
