## 4. У-2 — арифметика и режим процессора

### 4.1. Механизм `_controlfp` (собственный эксперимент)

AUD 276–290 вызывает `ucrtbase._controlfp(0, 0)` и декодирует `_MCW_DN` (0x03000000) и `_MCW_RC` (0x300). Чтобы не принимать пробу
на веру, Reviewer прочитал MXCSR напрямую — машинной инструкцией `stmxcsr` из исполняемой страницы — и менял режим в отдельном
процессе:

| Режим, установленный `_controlfp` | `_controlfp(0,0)` | MXCSR (`stmxcsr`) | Свои пробы NumPy и BLAS | Проба AUD |
|---|---|---|---|---|
| по умолчанию | `0x8001f` | `0x1fa0`: FTZ(b15) = 0, DAZ(b6) = 0, RC = 0 | без сброса, к ближайшему | ok |
| `_DN_FLUSH` | `0x108001f` | FTZ = 1, DAZ = 1 | сброс в NumPy и BLAS | **отказ** (31 проба) |
| `_DN_FLUSH_OPERANDS_SAVE_RESULTS` | `0x208001f` | DAZ = 1 | DAZ в NumPy и BLAS | **отказ** (19) |
| `_DN_SAVE_OPERANDS_FLUSH_RESULTS` | `0x308001f` | FTZ = 1 | FTZ в NumPy и BLAS | **отказ** (26) |
| `_RC_UP` / `_RC_CHOP` | `0x8021f` / `0x8031f` | RC = 2 / 3 | направленное округление | **отказ** (20 / 15) |

Выводы:

1. На этой платформе (x64, ucrtbase) `_controlfp` читает и пишет **MXCSR** — регистр, через который выполняются скалярные и
   векторные (SSE/AVX) операции NumPy и ядра OpenBLAS. Битовая раскладка отличается от MXCSR, но взаимно однозначна.
   `0x8001f` = все исключения маскированы, `_DN_SAVE`, `_RC_NEAR`: FTZ и DAZ выключены, округление к ближайшему. Интерпретация
   QA верна.
2. Управляющее слово x87 (`_control87`, то же значение) для этого пути не существенно: код x64 MSVC, NumPy и `dgemm` OpenBLAS
   выполняют операции binary64 на SSE2/AVX, а не на x87.
3. MXCSR — свой у каждого потока. FTZ, установленный в другом потоке, главный поток не меняет; новый поток получает значение по
   умолчанию. Поэтому важно, что пробы и вычисления строки выполняются в одном главном потоке рабочего процесса (AUD 907, 1093;
   984/984). BLAS с одним потоком исполняется в вызывающем потоке.
4. Проба AUD обнаруживает каждый из пяти изменённых режимов. Главное доказательство — **поведенческие** пробы, а слово
   `_controlfp` — дополнительное. QA этот механизм не описывает (Р-1).

### 5.2. Собственная реализация B_E (SCR)

Без функций AUD. Свои целые через `frexp`. ‖·‖²_a — 13-точечным оператором 𝒜, где множители 1/h⁴ и 1/(hₓ²h_y²) вынесены из целых
сумм; в AUD — узловой шаблон с весами. S_q, S_l, S₂ — свой узловой шаблон NS 2.2. Невязка ‖D𝒜ŵ_s − q‖²_h — точно. Корни с
точностью 2⁻⁷⁰. Константы — `consts.py` прошлой рецензии.

**γ_s.** γ_собств = a_h(w̃_s, d̃) − l_h(d̃), d̃ = w̃_p − w̃_s, по 13-точечной форме. Точно γ_собств = −γ_B1 на 984/984 строках. Знак
согласуется: γ_B1 = h_s ρᵀΔ при Δ = C′ − V, то есть a_h(w̃_s − ω, w̃_s − w̃_p), и E_s = ΔP̂ − Q̂ + γ_s.
