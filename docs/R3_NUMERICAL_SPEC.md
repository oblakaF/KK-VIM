  конечны и > 0; q конечна и ≠ 0; |ν| < 1. Для R3 добавляется b конечна и > 0.
- **Проверка диапазона r в решателе.** Для эталонов принята точная симметричная проверка max(a, b) ≤ 5(1 + 4u)·min(a, b), u = 2⁻⁵³,

- **Опорная длина** a (сторона вдоль x); w̄ = wD/(qa⁴), x̄ = x/a, ȳ = y/b [D-036, Р-3; MATH_SPEC 2.5, В-12]. Для сравнения с L-107 при r < 1 —

## 3. Дискретизация (схема R2 без изменений)

Все пункты — [R2 БЕЗ ИЗМЕНЕНИЙ]: схема NUMERICAL_SPEC.md записана для отрезка ℓ и шагов h_x, h_y и в R3 не меняется (D-036;
R3_NUMERICAL_SPEC_DRAFT 3.1). Сетки R3 — разд. 6.

### 3.1. Одномерная сетка и операторы [NUMERICAL_SPEC 3.1]

- G(ℓ, n): h = ℓ/n, узлы ξ_i = i·ℓ/n (не накоплением), i = 0…n; внутренние узлы 1…n − 1; n ≥ n_min = 4 [И-1, NUMERICAL_SPEC 3.3].
- Главное условие f₀ = f_n = 0 — точно (не неизвестные).
- ⟨u, v⟩ = hΣ_{i=1}^{n−1}u_iv_i (трапеции; концевые слагаемые равны нулю).
- (D⁺f)_{i+½} = (f_{i+1} − f_i)/h; (Lf)_i = (f_{i−1} − 2f_i + f_{i+1})/h², i = 1…n − 1 [ОПУБЛ. L-107 (g)].
- Естественное условие f″ = 0: (Lf)₀ = (Lf)_n := 0 ⇔ фиктивная точка f₋₁ = −f₁ [ОПУБЛ. L-107, с. 400]; L²f = L(Lf) [ЧВ-2].
- Тензорная сетка: V_h^x = ℝ^{n_x−1} на G(a, n_x), V_h^y = ℝ^{n_y−1} на G(b, n_y); n_x, n_y задаются независимо [NUMERICAL_SPEC 3.2].
- Поле — только в узлах тензорного произведения w_ij = X_iY_j; контрольная точка — узел, только если x* = i·a/n_x и y* = j·b/n_y
  при целых i, j (проверка в рациональной арифметике); иначе «точка не является узлом сетки» [NUMERICAL_SPEC 3.2].

### 3.2. Дискретный функционал [NUMERICAL_SPEC 4.1, ЧВ-3]

$$(\Delta_hw)_{ij}=(L_xw)_{ij}+(L_yw)_{ij}\ \text{(внутренние узлы)},\qquad a_h(w,v)=D\sum_{i,j}h_xh_y(\Delta_hw)_{ij}(\Delta_hv)_{ij},$$
$$l_h(w)=q\sum_{i,j}h_xh_yw_{ij},\qquad \Pi_h(w)=\tfrac12a_h(w,w)-l_h(w).$$

ν-независимость (дискретная Лемма 1) — ЧВ-3; положительная определённость a_h ≥ D(μ₁ˣ + μ₁ʸ)²‖w‖²_h — NUMERICAL_SPEC 4.1.

### 3.3. Дискретные полушаги [NUMERICAL_SPEC 5.2, 5.3, ЧВ-5]

**Y-полушаг** (s нечётно; задан X = X^{s−1} на G(a, n_x)): M_s^h = {X ⊗ Ỹ : Ỹ ∈ V_h^y};

$$K=D\bigl[A_hL_y^2-2B_hL_y+C_hI\bigr],\qquad KY=F_h\mathbf 1,$$
$$A_h=\langle X,X\rangle_x,\quad B_h=\sum_{i=0}^{n_x-1}h_x(D^+X)^2_{i+\frac12}=-\langle X,L_xX\rangle_x,\quad C_h=\langle L_xX,L_xX\rangle_x,\quad F_h=q\langle X,\mathbf 1\rangle_x .$$

**X-полушаг** (s чётно; задан Y = Y^{s−1} на G(b, n_y)): симметрично, K = D[A_hL_x² − 2B_hL_x + C_hI], коэффициенты из Y на G(b, n_y),
система KX = F_h1. Одна функция-решатель для обоих направлений [NUMERICAL_SPEC 5.3].

- При n_x ≠ n_y Y-полушаг использует G(b, n_y), а коэффициенты — G(a, n_x); X-полушаг — наоборот [NUMERICAL_SPEC 3.2].
- Граничная аппроксимация: главное условие точно; естественное — через (L_yY)₀ = (L_yY)_{n_y} := 0; фиктивные узлы не хранятся
  [NUMERICAL_SPEC 5.2, п. 6].
- Устойчивость: K симметрична положительно определена, собственные значения D(A_hμ_k² + 2B_hμ_k + C_h) ≥ DA_hμ₁² > 0 [NUMERICAL_SPEC 5.2, п. 7].
- Порядок O(h_x² + h_y²) при каждом фиксированном s и max(h_x, h_y) ≤ h₀(s) — доказан для любых a, b [ЧВ-7, ЧВ-8a, ЧВ-8;
  NUMERICAL_SPEC 5.4–5.5]. Асимптотическое разложение ошибки не доказано [D-032, п. 7].

### 3.4. Начальная функция и коэффициенты [NUMERICAL_SPEC 6, 7]

- X⁰_i = sin(πx_i/a) в узлах G(a, n_x). Коэффициенты — **вариант B** [И-2, NUMERICAL_SPEC 6.2–6.3]: те же сеточные суммы, что в Π_h;
  замкнутые формулы ЧВ-6: A_h = a/2, B_h = (a/2)μ₁, C_h = (a/2)μ₁², F_h = qh_x·ctg(π/(2n_x)), μ₁ = (4/h_x²)sin²(π/(2n_x)). Они зависят
  только от a и n_x.
- Интегрирование коэффициентов последующих полушагов — только формулы разд. 3.3 (трапеции для A_h, C_h, F_h; средние точки для B_h);
  смешение квадратур запрещено [NUMERICAL_SPEC 7.1, 7.3]. Производные заданного множителя всегда разностные.

### 3.5. Решение одномерных систем и невязка [NUMERICAL_SPEC 8]

- Факторизация [И-6]: r₁,₂ = (B ± √(B² − AC))/A (комплексный корень), K = DA(L − r₁I)(L − r₂I); две трёхдиагональные задачи Дирихле
  (L − r₁I)Z = g/(DA), (L − r₂I)Y = Z, Y := Re Y. Сборка пятидиагональной матрицы с Холецким не используется.
- Невязка без сборки матрицы: ρ = g − D[A·L(LY) − 2B·LY + C·Y]; η = ‖ρ‖_∞ / (D(16A/h⁴ + 8B/h² + C)‖Y‖_∞ + ‖g‖_∞) [NUMERICAL_SPEC 8.2].
- Контроль [И-7, NUMERICAL_SPEC 8.3]: η ≤ 10⁻¹² и ‖Im Y‖_∞ ≤ 10⁻¹²‖Y‖_∞ — принято; иначе один шаг уточнения; иначе ERROR_LINEAR_SOLVE;
  NaN/±∞ — ERROR_NONFINITE.

### 3.6. Нормировка и поле [NUMERICAL_SPEC 9.1, И-4]

- После полушага s: c = σ‖f‖_∞, σ = sign⟨f, 1⟩; f ← f/c, g ← g·c; поле w⁽ˢ⁾ = g ⊗ f не меняется (≤ 2u в узле).

- Нормировочно-инвариантные величины: β = B/A, γ = C/A, χ = F²/A. Критерии используют только поле w и Π_h.
- Полное поле: w_ij = X_iY_j на тензорной сетке (n_x + 1) × (n_y + 1), края — точные нули.

### 3.7. Масштабные свойства схемы [NUMERICAL_SPEC 9.3, ЧВ-14]

## 7. Порядок p и Ричардсон [D-039; Р-8, разд. 12; рецензия `9a218a6`, разд. 7.3, 8]

### 7.1. Правила

**Порядок p — P-C-min** [D-039]:
- уровень допускается к проверке p при ζ_c ≤ ζ_c^{R2}(20) и min(n_x, n_y) ≥ 20 (классы A ∪ Q);
- если в цепочке не меньше двух соседних пар Q–Q — обязательны **две самые грубые пары Q–Q**; иначе обязательна **самая мелкая допущенная
  тройка** последовательных уровней с удвоением обеих компонент;
- пары для А-4 (s = 1, ζ_A4) и А-5 (s = 1…3, ζ_A5) выбираются **раздельно**;
- критерий **p ∈ [1,9; 2,1]** (без изменений, NUMERICAL_SPEC 18.1); p = log₂(E(L)/E(2L)) в общих узлах по эталону (NUMERICAL_SPEC 12);
- **монотонность** ошибки — на всех допущенных уровнях цепочки (R2: «e убывает с n = 20», NUMERICAL_SPEC 18.1, А-2а, А-4а);
- остальные допущенные пары — диагностика (вычисляются и публикуются).

**Ричардсон — отдельное правило** [D-039]:
- к критерию допускается только пара **Q–Q** (ζ_c грубого уровня ≤ ζ_c^{R2}(80));
- обязательны две самые грубые пары Q–Q, если они есть; прочие — диагностика;
- применяется только при наблюдаемом p ∈ [1,9; 2,1] на этой паре (NUMERICAL_SPEC 12; D-032, п. 7);
- критерий: |w_RE − w_ex| ≤ 0,05·|w_{2n} − w_ex|, w_RE = (4w_{2n} − w_n)/3 в узлах грубой сетки — в центре и по полю (А-4б), в центре
  (А-5б) [NUMERICAL_SPEC 12, 18.1]; экстраполяция — при фиксированном s, пределом КК-МВИ по s не называется;
- **нет пар Q–Q → UNRESOLVED** по Ричардсону (p при этом может квалифицироваться); **одна пара → ограниченный объём**, не двухпарная
  квалификация R2 и не «полный PASS» двухпарного критерия;
- **r = 1:** пары R2 (80,80) → (160,160), (160,160) → (320,320) для p и Ричардсона; (320,320) → (640,640) — необязательная (D-032, п. 7).

w¹ = X⁰Y¹ [MATH_SPEC 9.1, В-29; D-030]. Эталон обязан соответствовать **этой** ориентации при любом r.

**Проверка ориентации полного ряда Леви.** `kkvim_reference.levy.levy_series_w` строит ряд (139) вдоль **короткой** стороны a_L = min(a, b)
и возвращает поле в исходных координатах [R3_LEVY_REFERENCE_DRAFT, разд. API; QA `3bb3232`]. Его член m = 1 — первый полушаг старта
вдоль короткой стороны:
- **r ≥ 1** (a_L = a): член m = 1 совпадает с В-29 исходного старта по x — проверено Reference против независимой замкнутой формы В-29
  (r_L = 1; 1,4; 1,5; 2; 3; 5; допуск 100u·C₀) — PASS [R3_LEVY_REFERENCE_DRAFT, табл. «Б»; QA `3bb3232`];
- **r < 1** (a_L = b): член m = 1 совпадает с В-29 на пластине b × a со стартом **Y⁰ = sin(πy/b)** и **не** совпадает с первым полушагом
  исходной пластины (разность > 1 % максимума) [R3_LEVY_REFERENCE_DRAFT, табл. «В»]. Поэтому `levy_series_w(M = 1)` при r < 1 **не является**
  эталоном А-4.

**Выбор нормативного эталона А-4.**

| Вариант | Ориентация | Точность (источник) | Решение |
|---|---|---|---|
| **(1)** `ParsevalRecursion(a = a, b = b, q = q, D = D, s_max = 1).field_on_grid(1, n_x, n_y)` | исходная: X⁰ = sin(πx/a), Y¹ на (0, b), при всех r | реализация против В-29 в mpmath (50 знаков): ≤ 1,7·10⁻¹⁶ (r = 0,2), ≤ 4,7·10⁻¹⁶ (прочие r) относительно max\|w\|; бюджет `field_error` (s = 1) 2,0·10⁻¹⁴ (r = 0,2) … 2,5·10⁻¹⁴ — модель первого порядка, не строгая граница [QA `a636baf`, разд. 4] | **основной нормативный эталон** для всех r ≠ 1 |
| (2) замкнутая формула В-29 в double | исходная | при r = 0,2 теряет ≈ 3 знака из-за вычитания 1 − P·ch(…): 8,2·10⁻¹⁴ (поле), 2,4·10⁻¹⁴ (центр); 1,9·10⁻¹⁴ при r = 1/3; модель 32u·Σ\|слагаемых\| консервативна (факт ≤ 0,07 модели) [QA `a636baf`, разд. 4] | только диагностика; ошибку формулы в double не смешивать с ошибкой реализации Парсеваля |
| (3) `levy_series_w(..., M = 1)` | вдоль короткой стороны | при r ≥ 1 — = В-29 старта по x в пределах 100u·C₀ [Levy, табл. «Б»] | допустим при r ≥ 1 как независимая перекрёстная проверка эталона; **не допускается при r < 1** |
| r = 1 | исходная | `levy_w1` R2; А-4в ≤ 5·10⁻¹³ | регрессия R2 без изменений |

**API и сравнение.**
- Поле эталона: `field_on_grid(1, n_x, n_y)` — значения w¹ в узлах x_i = ia/n_x, y_j = jb/n_y (целочисленная редукция аргумента, края — точные
  нули) [R3_PARSEVAL_REFERENCE, разд. 2]. Центр — узел (n_x/2, n_y/2) (обе компоненты кратны 4).
- Сравниваются **узловые** значения дискретного w_h¹ и эталона на одной сетке; нормы e_c, e_∞ — относительные (NUMERICAL_SPEC 14), поэтому от
  выбора опорной длины и от нормировки множителей не зависят (Р-3; И-4: поле при нормировке не меняется).
- Допуски А-4а/А-4б не меняются.

**Учёт погрешности эталона в допуске А-4** [без нового допуска]:
- До сравнения QA проверяет условие R2 для полуаналитического эталона (NUMERICAL_SPEC 15.7; А-10б): относительная погрешность эталона
  ≤ 10⁻¹² и ≤ 1/100 наименьшей измеряемой ошибки МКР на используемых уровнях. Для s = 1 бюджет 2,5·10⁻¹⁴ ≤ 10⁻¹² (выполнено по данным QA).
  Отношение «бюджет / E(n)» записывается для каждой пары; если на какой-либо паре оно > 1/100, вывод по этой паре — **UNRESOLVED** (условие
  15.7 не выполнено), а не PASS/FAIL.
- Влияние на p: |Δp| ≲ 2δ/(E(L)·ln 2), δ — погрешность эталона; при δ/E ≤ 1/100 это ≤ 0,03, при фактическом δ ≈ 10⁻¹⁶…10⁻¹⁴ и ошибке порядка R2 (s = 1: e_c(320) = 5,4·10⁻⁷, STATUS, R2, шаг 4) —
  пренебрежимо. Оценка — модельная [ЗАМЕЧАНИЕ ЗР-2]; бюджет — не строгая граница.

**Независимые от дискретного решателя проверки эталона А-4:** реализация Парсеваля против В-29 в 50 знаках (QA `a636baf`, разд. 4);
`levy_series_w(M = 1)` против замкнутой В-29 при r ≥ 1 (Levy, табл. «Б»); `levy_w1` R2 при r = 1 (Levy, табл. «А»). Все они не используют
`kkvim` (D-028; тест независимости пакетов).
