### 2.1. Геометрия

- **l_x = 1.** Номинальное отношение r = l_y/l_x задаётся рационально; фактическая сторона — **l_y = fl(r)** (binary64).
- Размеры сеток (n_x, n_y) — **целые числа интервалов**.
- **Два разных шага сетки (Н-5):**
  - **точный шаг h = l/n** — точное рациональное число от binary64-значения l. Он задаёт точную дискретную задачу: эталоны,
    сертификаты, V* (BR, разд. 1), точные γ_s, B_E и предпосылки (функции `kkvim_reference` с точной арифметикой);

    оценками этих путей (ST; У-3).

  Проверка Integrator (точная рациональная арифметика над значениями binary64):

| r | fl(r) = r точно | Сетки, где fl(h_x) ≠ fl(h_y) (double-шаг) | Точный шаг: h_x = h_y? |

## 4. Классификатор

### 4.1. Величины на строке

Строка — один полушаг s собственной траектории (блоки A, B, D, S) или парный полушаг B-C (блок C). Записываются:

- P̂_p, P̂_s, Q̂_s — значения пути G-4 (`pi_double`, `q_double`);
- ΔP̂_s = P̂_p − P̂_s — в точной рациональной арифметике (ST 1.1);
- Γ_up,s — путь B1 (GP 5.3, п. 1);
- B_E,s — строгая верхняя граница (ST 5.1, 5.4; реализация по образцу QA-EB 8.1);
- τ′_s = Γ_up,s + B_E,s — точная рациональная сумма **записанных** верхних границ Γ_up,s и B_E,s. E1/E2 и разрешимость решаются
  относительно этого записанного значения.

Все сравнения — точные, над рациональными значениями binary64 и строгими верхними границами, **без допусков**.

Предпосылки сертификата — каждая проверяется на строке (D-054.1, п. 5; ST 13; QA-EB разд. 3–7):

| ID | Предпосылка |
|---|---|
| П-а | привязка данных: входы (sha256 / blob git), воспроизведение значений строки побитово |
| П-б | У-1 на обоих полях |
| П-в | У-2: режим округления к ближайшему, FTZ/DAZ — пробы в том же потоке до и после строки; П-3′ и П-2 на путях `pi_double`/`q_double`; конечность P̂_p, P̂_s, Q̂ |
| П-г | У-3: константы сетки, нормальность множителей, знаменатели > 0, глубина попарного суммирования |
| П-д | Н-7: точный нуль предыдущего поля, где ε_a^C(s−1) = 0 |
| П-е | применимость B_E (ST 5.4): область корней, знаменатель D^{1/2}μ_low > 0, конечность |

### 4.2. Статус строки (дерево решений, однозначно)

1. Не выполнена хотя бы одна предпосылка П-а…П-е, или её нельзя проверить → **UNRESOLVED_CERTIFICATE** с перечнем причин.
   - E1/E2 и разрешимость всё равно вычисляются и записываются, но не как проверенные.
   - Если при этом E1 или E2 нарушены, строка дополнительно получает **диагностическую метку E_DIAG**. Строки E_DIAG перечисляются в
     отчёте **отдельно** и не скрываются за общим UNRESOLVED (Н-8). Блокировки E_DIAG не вызывает.
2. Иначе, если нарушено E1 (ΔP̂_s ≥ −τ′_s) или E2 (|ΔP̂_s − Q̂_s| ≤ τ′_s) → **FAIL_COMPUTATION** (вычислительная согласованность).
3. Иначе, если Q̂_s ≤ τ′_s → **UNRESOLVED_RESOLVABILITY** (установленная неразрешимость).
4. Иначе (Q̂_s > τ′_s) → **PASS**.

Отдельно:

- точка, не исполненная по правилу ресурсов (PL 6.3), — **UNRESOLVED_RESOURCES** с измеренными значениями пробы;
- строка, не исполненная по другой причине, — **UNRESOLVED** с указанием причины.

**Равенства и нули:**

- E1/E2 — нестрогие: ΔP̂_s = −τ′_s и |ΔP̂_s − Q̂_s| = τ′_s нарушением не являются;
- разрешимость — строгая (D-054.2, п. 1): Q̂_s = τ′_s → UNRESOLVED_RESOLVABILITY;
- Q̂_s = 0 → UNRESOLVED_RESOLVABILITY, так как τ′_s ≥ 0;
- τ′_s = 0 при Q̂_s > 0 → PASS только при ΔP̂_s = Q̂_s точно (E2).

Статус строки относится к **вычислительной согласованности** энергетического контроля. О сходимости КК-МВИ, точности решения, модели
и ранге он ничего не утверждает (D-054.1, п. 4).

### 4.3. Вердикт кандидата разрешимости (Б-3)

**Область вердикта** — только **блок A, N = 1, s = 1, 2, 3**: фиксированный список из **102** обязательных строк (34 сетки × 3),
утверждаемый до запуска (разд. 12). Невыполненная строка остаётся в знаменателе 102 со статусом UNRESOLVED.

Порядок (первое выполненное условие определяет вердикт):

1. **BLOCKED_CAMPAIGN** (разд. 4.4) → вердикт кандидата **не выдаётся** до устранения причины.
2. **FAIL_CANDIDATE** — хотя бы одна установленная неразрешимость Q̂_s ≤ τ′_s (UNRESOLVED_RESOLVABILITY) среди 102 обязательных строк
   (D-054.2, п. 3). Это не FAIL решателя и не дефект метода.
3. **UNRESOLVED_CANDIDATE** — установленной неразрешимости нет, но не все 102 обязательные строки подтверждены (есть
   UNRESOLVED_CERTIFICATE, UNRESOLVED_RESOURCES или неисполненные строки).
4. **PASS_CANDIDATE** — все 102 обязательные строки блока A, N = 1, s = 1, 2, 3 — PASS. Это прохождение кандидата на выборке D1, а не
   норматив и не квалификация решателя.

**Правило против подгонки (D-054.2, п. 4).**

- Если в обязательной области D1 при установленных предпосылках обнаружено Q̂_s ≤ τ′_s, результат — FAIL_CANDIDATE (при отсутствии
  BLOCKED_CAMPAIGN).
- Кандидат (c, область s) по результатам D1 не корректируется. Новый кандидат допускается только по новому решению владельца и на новой
  выборке.
- Недостаток сертификата или неисполненная строка без установленного контрпримера — UNRESOLVED_CANDIDATE (п. 3).
- Порядок пп. 1–4 не меняется.

**Блоки B, C, D, S в вердикт кандидата не входят.** Их строки классифицируются тем же деревом (разд. 4.2); статусы — OBSERVATION,
RESEARCH_ONLY (N = 2, 3) или контроль. Автоматически до квалификационных они не повышаются; N ≥ 2 не квалифицируется (D-049.5).

Строки блока A при s = 4…8 классифицируются тем же деревом; на вердикт кандидата они не влияют, их разрешимость — OBSERVATION.

### 4.4. Вердикт кампании

- **BLOCKED_CAMPAIGN:**
  - FAIL_COMPUTATION на любой строке **немутированной** кампании (любой блок) при подтверждённых предпосылках. При установленных
    предпосылках нарушение E1/E2 противоречит Э-2: дефектен код или доказательство, и записанное τ′ недостоверно на всех строках общего
    вычислительного пути;
  - несовпадение входов с зафиксированными хешами до расчёта;
  - FAIL положительного контроля В (разд. 6).
- **Ожидаемый FAIL в специально инъецированном контроле** (контроль Г — мутации вычислительного пути; синтетические строки контроля A
  с заданным нарушением E1/E2) **не означает блокировку кампании**: это сработавший канал обнаружения на отдельно мутированных данных,
  а не строка кампании.
- **Контроль Б** (инъекция нарушенной предпосылки П-а…П-е) ожидает **UNRESOLVED_CERTIFICATE**, а не FAIL (разд. 4.2, п. 1; разд. 6).
  FAIL_COMPUTATION допускается только при установленных предпосылках и нарушении E1/E2 (разд. 4.2, п. 2). Иной результат инъекции
  контроля Б — неожиданный результат контроля (разд. 12, п. 4).
- Иначе вердикт кампании — вердикт кандидата (разд. 4.3) с полным перечнем строк UNRESOLVED и их причин и отдельным перечнем строк
  E_DIAG.

### 5.1. Наблюдения точности: TS-1 и форма BC-1 (ОП-1, ОП-5)

**TS-1 (OBSERVATION).**

- Величина:

  e_field = ‖Ũ(V̂ − V*)ᵀ‖_a / ‖ŨV*ᵀ‖_a.

  - Ũ — заданный набор полушага (после QR при N ≥ 2); V̂ — решение B-C; V* — точное решение дискретной системы полушага для
    фиксированного входа: точные коэффициенты от сохранённого binary64-набора, точный шаг h = l/n (BR, разд. 1).
  - ‖·‖_a — энергетическая норма поля; ‖Ũ(V − V*)ᵀ‖_a = h_s^{1/2}‖x − x*‖_K (BR, разд. 3). Это та же относительная ошибка поля, что в
    BR и CA.
  - e_field включает ошибку сборки коэффициентов и ошибку решения (BR, разд. 5).
- **Кандидат TS-1:** e_field ≤ 10·u·n_s² (c_f = 10). **n_s** — число интервалов в решаемом направлении текущего полушага.
- **Знаменатель** ‖ŨV*ᵀ‖_a должен иметь сертифицированную положительную нижнюю границу; иначе — UNRESOLVED.
- e_field — сертифицированный интервал по эталону BR с бюджетом 1/100 в той же норме (разд. 5, п. 8).
- TS-1 не заменяет BC-1. Превышение кандидата — OBSERVATION, а не FAIL.

**Справочно (OBSERVATION, область D0; не квалификация TS-1).** 476 полушагов Е-4, интервалы ошибки поля относительно
сертифицированного эталона; число точек, где нижняя граница e_field выше 10·u·n_s² (по верхней границе — те же числа):

| Сборка C | Источник | Превышений 10·u·n_s² | max e_field/(u·n_s²) |
|---|---|---|---|
| OLD (прототип `r5_cccc_bc`) | BR, `e4_reference.csv` (PR #39); совпадает с OLD в CA | **91/476** (из них 28 при N = 1) | ≈ **453,36** (`1x1:160x32`, N = 2, Y) |
| NEW C-3⁺ | CA, `rows.csv`, `NEW_field_rel_*` (PR #40) | **0/476** | ≈ **1,286** |
| CONTROL | CA, `rows.csv`, `CONTROL_field_rel_*` (PR #40) | **0/476** | ≈ 1,286 |

- Данные CA — замена C на отдельных полушагах с входами Е-4, а не траектории. Числа OLD не характеризуют C-3⁺, числа NEW не
  переносятся на траектории кампании D1.
- Кандидат c_f = 10 сохраняется без изменения.

**Форма BC-1 (OBSERVATION, D-054.4, п. 1).**

- Эталон — метод BR, заново применённый к каждому новому фиксированному входу (повтор метода, а не перенос данных). Предпосылки эталона
  проверяются построчно: K SPD, сертификат λ_low, точная сборка при h = l/n, лестница точности p = 40, 80, 160, сходимость уточнения.
  Отказ — UNRESOLVED.
- **Интервал в ∞-норме:** d∞ = ‖V̂ − V_ref‖∞ вычисляется точно; радиус эталона b∞ ≤ ‖r‖₂/λ_low (неравенство ‖·‖∞ ≤ ‖·‖₂ для ошибки
  самого эталона); интервал — [d∞ − b∞, d∞ + b∞]. **∞-норма ошибки B-C из её 2-нормы не выводится.**
- Бюджет 1/100 — в той же относительной норме; нулевая измеряемая ошибка — UNRESOLVED.
- Определение ∞-нормы набора при N ≥ 2 фиксируется до запуска (разд. 12).
- tol_solve не назначается (D-054.4, п. 2).
