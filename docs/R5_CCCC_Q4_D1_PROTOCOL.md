## 1. Что проверяет кампания

1. **Сертифицированный энергетический контроль** с τ′_s = Γ_up,s + B_E,s (D-054.1) на собственных траекториях B-C и на парных
   полушагах. E1/E2 здесь — контроль согласованности вычислений, а не сходимость, точность или ранг (D-054.1, п. 4).
2. **Кандидат разрешимости** c = 1, Q̂_s > τ′_s, обязательная область s ∈ {1, 2, 3} (D-054.2).
3. **Наблюдения точности** (OBSERVATION): BC-1 в ∞-норме набора, ошибка поля в энергетической норме (TS-1, кандидат c_f = 10),
   невязка η (кандидат η_max^C = 100u) (D-054.4).
4. **Ранговая диагностика** при N = 2, 3 — RESEARCH_ONLY / NOT_QUALIFIED (D-054.5).

**Кампания не делает:**

- не назначает K_E, tol_solve, η_max^C, TS-1, K, c_d, c_rank, τ_set, cond(S), tol_∞, tol_E, s_min, s_max, c_R;
- не меняет c и обязательную область s после запуска (разд. 5, п. 1);
- не делает статистических утверждений (разд. 5, п. 2);
- не квалифицирует N ≥ 2, Builder и рабочий решатель;
- не меняет данные PR #38–#42 и #44.

## 2. Выборка: геометрия и сетки

### 2.1. Геометрия

- **l_x = 1.** Номинальное отношение r = l_y/l_x задаётся рационально; фактическая сторона — **l_y = fl(r)** (binary64).
- Размеры сеток (n_x, n_y) — **целые числа интервалов**; шаги вычисляются как h_x = fl(1/n_x), h_y = fl(l_y/n_y), как в пути EN.
- **Точного равенства** binary64-значения l_y рациональному r и равенства h_x = h_y в binary64 протокол **не утверждает**, если оно
  не выполняется. Проверка Integrator (точная рациональная арифметика над значениями binary64):

| r | fl(r) = r точно | Сетки, где fl(h_x) ≠ fl(h_y) |
|---|---|---|
| 1, 3/2, 5/2, 4, 1/4 | да | нет |
| 2/3 | **нет** | **(198, 132), (396, 264)**; на (48, 32), (96, 64) — равны |
| 2/5 | **нет** | нет |

  На всех 28 основных сетках n_y/n_x = r точно (номинально h_x = h_y). Сами h = 1/n и l_y/n в binary64, как правило, неточны;
  константы сетки проверяются построчно (У-3). Анизотропные сетки на 1 × 1 имеют h_x ≠ h_y по построению.
- **Ориентация** — по D-049.3, п. 2: первый полушаг по y при заданных функциях от x. Записывается в протокол каждого расчёта.
- **Старт** — 𝒯_N = span{sin²(iπx/a), i = 1…N} (D-049.3, п. 1). Число полушагов фиксировано: s = 1…8, без остановки по стабилизации.

**Правила блоков:**

- **Блок D, граничный случай (14, 6), N = 3.**

    ранга — защитная остановка до QR. S-1 присваивается только при доказанной зависимости (D-049.5, п. 2), а N = ⌊n_y/2⌋ её не
    доказывает.

## 4. Классификатор

### 4.1. Величины на строке

Строка — один полушаг s собственной траектории (блоки A, B, D, S) или парный полушаг B-C (блок C). Записываются:

- P̂_p, P̂_s, Q̂_s — значения пути G-4 (`pi_double`, `q_double`);
- ΔP̂_s = P̂_p − P̂_s — в точной рациональной арифметике (ST 1.1);
- Γ_up,s — путь B1 (GP 5.3, п. 1);
- B_E,s — строгая верхняя граница (ST 5.1, 5.4; реализация по образцу QA-EB 8.1);
- τ′_s = Γ_up,s + B_E,s — как точная рациональная верхняя граница.

Все сравнения — точные, над рациональными значениями binary64 и строгими верхними границами, **без допусков**.

Предпосылки сертификата — каждая проверяется на строке (D-054.1, п. 5; ST 13; QA-EB разд. 3–7):

| ID | Предпосылка |
|---|---|
| П-а | привязка данных: входы (sha256 / blob git), воспроизведение значений строки побитово |
| П-б | У-1 на обоих полях |
| П-в | У-2: режим округления к ближайшему, FTZ/DAZ — пробы в том же потоке до и после строки; П-3′ и П-2 на путях `pi_double`/`q_double` |
| П-г | У-3: константы сетки, нормальность множителей, знаменатели > 0, глубина попарного суммирования |
| П-д | Н-7: точный нуль предыдущего поля, где ε_a^C(s−1) = 0 |
| П-е | применимость B_E (ST 5.4): область корней, знаменатель D^{1/2}μ_low > 0, конечность |

### 4.2. Статус строки (дерево решений, однозначно)

1. Не выполнена хотя бы одна предпосылка П-а…П-е, или её нельзя проверить → **UNRESOLVED (сертификат)** с перечнем причин.
   E1/E2 и разрешимость всё равно вычисляются и записываются, но не как проверенные.
2. Иначе, если нарушено E1 (ΔP̂_s ≥ −τ′_s) или E2 (|ΔP̂_s − Q̂_s| ≤ τ′_s) → **FAIL (вычислительная согласованность)**.
3. Иначе, если Q̂_s ≤ τ′_s → **UNRESOLVED (разрешимость)**.
4. Иначе (Q̂_s > τ′_s) → **PASS**.

Отдельно (PL 6.3): точка, которая не исполнена по правилу ресурсов, — **UNRESOLVED (ресурсы)** с измеренными значениями пробы.

Статус строки относится к **вычислительной согласованности** энергетического контроля. О сходимости КК-МВИ, точности решения, модели
и ранге он ничего не утверждает (D-054.1, п. 4).

### 4.3. Вердикт кандидата разрешимости

Обязательные строки — строки с s ∈ {1, 2, 3}. Вердикт выносится отдельно по каждой группе: блок A; блок C, N = 1; блок D, N = 1 [И];
для N = 2, 3 (блоки B, C, D) — так же, с меткой RESEARCH_ONLY.

1. В группе есть обязательная строка FAIL (вычислительная согласованность) → вердикт **не выносится**: кампания **BLOCKED** по
   вычислительному пути (разд. 5, п. 4).
2. Иначе, есть обязательная строка UNRESOLVED (разрешимость) → кандидат **FAIL** (D-054.2, п. 3). Это не FAIL решателя.
3. Иначе, есть обязательная строка UNRESOLVED (сертификат или ресурсы) → кандидат **UNRESOLVED** [И].
4. Иначе (все обязательные строки PASS) → кандидат **PASS** в этой группе.

**Итог кандидата для N = 1** [И]:

- FAIL — если FAIL хотя бы в одной из групп A, C (N = 1), D (N = 1);
- PASS — если PASS во всех трёх;
- UNRESOLVED — в остальных случаях без BLOCKED.

Вердикты групп N = 2, 3 — RESEARCH_ONLY: они не квалифицируют N ≥ 2 (D-049.5).

Строки s = 4…8 классифицируются тем же деревом. На вердикт кандидата они не влияют; их разрешимость — OBSERVATION.

### 4.4. Вердикт кампании

- **BLOCKED** — любая строка FAIL (вычислительная согласованность) в любом блоке; несовпадение входов с зафиксированными хешами до
  расчёта; противоречие с доказательством (FAIL контроля В разд. 6).
- Иначе вердикт кампании — набор вердиктов кандидата (разд. 4.3) с полным перечнем строк UNRESOLVED и их причин.

## 5. Условия квалификации

1. **Порог c и область s не меняются** после запуска D1. Если кандидат не проходит, новый кандидат требует нового решения владельца и
   отдельной проверочной выборки (D-054.2, п. 4).
2. **Статистических утверждений нет**: выборка детерминированная. Утверждения о «95 % доверии» и подобные не делаются.
3. **Арифметические предпосылки** проверяются на каждой строке (разд. 4.1).
4. **FAIL E1/E2 при установленных предпосылках блокирует** проверку вычислительного пути (разд. 4.4).
5. **Неразрешимость обязательного s** при установленных предпосылках означает FAIL соответствующего кандидата (разд. 4.3).
6. **Нарушение предпосылки — UNRESOLVED**, а не FAIL метода.
7. **BC-1 — OBSERVATION** (D-054.4, п. 1). TS-1 и η — тоже OBSERVATION относительно кандидатов c_f = 10 и η_max^C = 100u. Константы
   между нормами не переносятся.
8. **Бюджет эталона 1/100** по D-049.6, п. 4. Если для наблюдения точности бюджет не выполнен, наблюдение получает **UNRESOLVED
   (бюджет эталона)**.
9. **Второй вычислительный путь** для ключевых чисел γ и B-C (D-053.4):
   - γ_s — путь B1 и отличающийся путь, например 13-точечная форма a_h (как в рецензии PR #44, разд. 5.2) или тождество ВОК-2;
   - B-C — сборка C вариантом CONTROL (D-054.3, п. 2) и эталон с уточнением (R-AC с уточнением или сертифицированный эталон PR #39).

   Конкретные пути и подвыборка фиксируются до запуска (ОП-4).
10. **Ограничение общего типа исполнителей** (D-053.2, п. 6) раскрывается в отчёте. Новым нормативным требованием сверх D-053.4 оно не
    объявляется.

## 8. Ресурсы (PL 6.3) и обязательные пробы

**Правило PL 6.3.** Тяжёлая точка исполняется, только если проба той же конфигурации укладывается в пределы, зафиксированные до запуска:

- пик памяти ≤ 50 % RAM машины;
- факторизация ≤ 30 мин;
- уточнение сходится (PL §1.4).

Иначе точка получает **UNRESOLVED (ресурсы)** с измеренными значениями. Упрощение схемы, замена решателя и ослабление допуска ради
прохождения не допускаются.

**Обязательные пробы перед запуском** — полушаг наибольшей конфигурации каждого блока, включая точное вычисление B_E и предпосылок:

- блок A: (320, 1280) — 409 600 узлов; (400, 1000) — 400 000; (400, 600) — 240 000;
- блок B: наибольшая сетка блока при N = 3 (после ОП-2);
- блок C: (80, 320) и (100, 250) при N = 3, вместе с цепочкой R-AC;
