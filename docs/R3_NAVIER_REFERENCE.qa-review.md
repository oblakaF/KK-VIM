## 8. Поправка 4u (решение владельца А) — коммит `5090e26`

**Воспроизведение проблемы на `9a42416`:** `NavierRectangle(a=3, b=0.6, …)` → `ValueError: ERROR_INPUT`. Float 0,6 меньше 3/5; точное
отношение b/a = 0,2·(1 − u/3).

**Правило:** точное отношение заданных float (целочисленная арифметика) удовлетворяет 0,2·(1 − 4u) ≤ b/a ≤ 5·(1 + 4u), u = 2⁻⁵³. Допуск —
только на представление входных чисел, не расширение физической области R3; бо́льшего допуска нет.

**Изменения** (`navier.py`, тесты автора, `R3_NAVIER_REFERENCE.md` разд. 2.1 — один коммит; расчётные формулы не менялись):
- `_in_range_exact` проверяет правило 4u точно; конструктор и публичные функции строгих границ (`deflection_tail_bound_rect`,
  `deflection_integral_coef_rect`, `deflection_integral_tail_bound_rect`) применяют одно и то же правило к своему входу;

  ложный отказ: a = 0,7, b = 0,13999999999999993 — точное отношение 0,2·(1 − 3,93u) принимается, а fl(b/a) = 0,2·(1 − 4,5u) лежит вне полосы.

**Проверено:**
- a = 3, b = 0,6 и a = 0,6, b = 3 принимаются; центр пластины 3 × 0,6 совпадает с центром r = 0,2 в пределах округления (M = 2559);

## 10. Неблокирующие замечания

- **Н-1.** Полоса 4u несимметрична относительно перестановки сторон: 1/(0,2(1 − 4u)) > 5(1 + 4u) на ≈ 16u² относительно. Пластина с точным
  отношением в интервале [0,2(1 − 4u); 0,2/(1 + 4u)) принимается, а её `swapped()` — нет. Ширина интервала ≈ 16u² ≈ 2·10⁻³¹ относительно; правило
  применено буквально, как решено владельцем.
- **Н-2.** `docs/R3_NAVIER_REFERENCE.md` (документ автора) в шапке и в разд. 5, п. 3 говорит, что независимая квалификация не выполнена и
  допуск δ_w(r) не решён. После этой квалификации и D-037 статус документа нужно обновить при интеграции. QA менял в нём только описание 4u.
- **Н-3.** `NavierRectangleConvergence` по-прежнему не содержит правила приёмки. Критерий δ_w(r) применён здесь как квалификационный, а не
  встроен в модуль; встраивать его не требуется и этим заданием не предусмотрено.
