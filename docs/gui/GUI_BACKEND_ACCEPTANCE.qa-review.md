## 5. Замечания (неблокирующие)

**Н-1. Перевод единиц не всегда даёт ближайшее к десятичному значению число double.**
- `backend/units.py`: `to_base(value, unit) = value * 1e-2` (`1e-3`). Множитель не представим точно, поэтому округлений два.
- Минимальный пример: `to_base(70.0, "cm") = 0.7000000000000001`, тогда как ввод «0,7 m» даёт `0.7`. Ещё 9 mm → 0.009000000000000001, 13 mm → 0.013000000000000001.
- Отклонение — не больше γ₂ = 2u/(1 − 2u); проверено для 1…2000 cm и mm, максимум 1,28·10⁻¹⁶ отн. (1023 mm).
- Отказов или пропусков проверки b/a ∈ [0,2; 5] из-за этого не найдено (перебор 1…2000 cm/mm и смешанных единиц на границе b/a = 5).
- Влияние на результат — на уровне округления. Но утверждение `KKVIM_BACKEND.md` о «точных десятичных приставках СИ» неверно.
- Предложение Builder: делить на целую степень 10 (`value / 100`, `value / 1000`) или считать через `decimal` по введённому тексту. Это не исправлялось.

**Н-2. HALF_STEP_LIMIT_REACHED без кода в строке остановки.**
- Для нормативного расчёта с half_steps = 1 строка остановки — «Нормативный режим D-047: выполнено заданное число полушагов». Кода статуса в ней нет, в отличие от остальных статусов.
- NOT_QUALIFIED показан в строке научного статуса, код — в журнале («Решатель вернул HALF_STEP_LIMIT_REACHED»), поэтому ошибки статуса нет.
- Минимальный пример: N = 2, нормативный, `half_steps = 1`, 24×24.

**Н-3. Машинный вид PROVISIONAL_FIELD_STABILIZED.**
- В интерфейсе стабилизация показана как предупреждение (подтверждено).
- Но `stop.kind` в `manifest.json` равен `"met"` — так же, как у CONVERGED R3. В журнал расчёта строка остановки пишется уровнем «ИНФО»: `runs.py` выбирает уровень по `stop_kind == "met"`.
- Метки PROVISIONAL / NOT_QUALIFIED в манифесте и CSV есть, а текст содержит «не сходимость», так что сходимость не утверждается.
- Внешнему читателю манифеста нужно учитывать `statuses.mark`. Предлагается отдельный `kind` для стабилизации R4 или уровень «ПРЕДУПРЕЖДЕНИЕ» в журнале.

## 6. Ограничения проверки

- **Данные PR #24 не в `main`.** В CI с неглубоким checkout сравнения с эталонами пропускаются. Тест Builder `test_gui_qa_control_cases.py` без данных тоже пропускается. Для постоянной проверки нужно слияние PR #24 или каталог `KKVIM_QA_CONTROL_DIR`.
- **CI проекта не устанавливает extra «gui»,** поэтому Qt-тесты (Builder и QA) в CI пропускаются. Здесь они выполнены локально на 3.13 и 3.14.
- **Межплатформенное правило R4** (`_model`) выполнено только на этой машине под Python 3.14. Linux не проверялся.
- **Модальные диалоги не нажимались.**
  - «Стоп» проверен через `RunManager.stop` — то, что делает «Да» в `QMessageBox`.
  - Выбор папки экспорта (`QFileDialog`) заменён вызовом `MainWindow.export_run`.
- **Без научных выводов.** Эталоны PR #24 получены той же библиотекой и не являются независимыми научными решениями. Проверка подтверждает интеграцию, а не точность R3/R4.
