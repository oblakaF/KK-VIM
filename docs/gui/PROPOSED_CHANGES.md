# KK-VIM GUI — предложения по зависимостям и общим документам

- **Этап:** P0. **Статус:** предложения на рассмотрение владельца (2026-10-12).
- **Ветка:** `gui/prototype`.
- **Связанный документ:** [GUI_DESIGN.md](GUI_DESIGN.md).

Здесь собраны изменения, которые GUI потребует за пределами `docs/gui/` и `src/kkvim_gui/`.
**Ни одно из них не применено.** `pyproject.toml`, `uv.lock`, `docs/DECISIONS.md`,
`docs/STATUS.md`, `docs/ROADMAP.md`, `docs/PROJECT_GOALS.md`, `README.md`, `AGENTS.md`, тесты
и CI в ветке не изменялись. Каждое предложение применяется только по явному решению владельца.

---

## 1. Новые зависимости

> **Применено в ветке `gui/prototype` на этапе P1 (разрешение владельца 2026-10-12):**
> группа `gui` = `PySide6-Essentials>=6.10.1`, `pyqtgraph>=0.14.0`; отдельная тестовая группа
> `gui-test` = `pytest-qt>=4.5.0` (не в `dev`: pytest-qt без Qt-биндинга ломает запуск pytest
> в существующем CI); `[project.gui-scripts] kkvim-gui`; `src/kkvim_gui` в составе wheel;
> `uv.lock` обновлён. matplotlib не добавлен (этап P6). Проверено на Python 3.13 и 3.14
> с версиями из lock-файла и с нижними границами. Ниже — исходное предложение P0.

### 1.1. Перечень

| Пакет | Назначение | Нужен с этапа | Группа | Лицензия |
|---|---|---|---|---|
| PySide6 | окна, виджеты, темы (Qt 6) | P1 | `gui` (необязательная) | LGPL-3.0 (также GPL / коммерческая) |
| pyqtgraph | экранные научные графики и цветовые поля | P3 | `gui` | MIT |
| matplotlib | публикационный экспорт PNG/PDF/SVG, mathtext | P6 | `gui` | Matplotlib License (основана на PSF, совместима с BSD) |
| pytest-qt | автоматические тесты окон | P1 | `dev` | MIT |

- **Минимальные версии** определяются при добавлении тем же способом, что в D-028:
  первые выпуски со сборками под CPython 3.13 и 3.14 (win_amd64, manylinux x86_64) на PyPI,
  с проверкой локально на обеих версиях Python. Сейчас версии не утверждаются.
- **Научное ядро не зависит от GUI:** `pip install kkvim` и CI научной части не устанавливают Qt.
  GUI ставится как `kkvim[gui]` или `uv sync --extra gui`.

### 1.2. Предлагаемое изменение `pyproject.toml` (текст, не применён)

```toml
[project.optional-dependencies]
gui = [
    "PySide6>=<определить>",
    "pyqtgraph>=<определить>",
    # "matplotlib>=<определить>",   # добавляется на этапе P6
]

[project.gui-scripts]
kkvim-gui = "kkvim_gui.app:main"

[dependency-groups]
dev = [
    "pytest>=8.4.0",
    "pytest-qt>=<определить>",
]

[tool.hatch.build.targets.wheel]
packages = ["src/kkvim", "src/kkvim_gui"]
```

Изменение раздела `tool.hatch.build.targets.wheel` затрагивает решение D-028 (состав пакетов),
поэтому включено в проект решения (раздел 2).

### 1.3. Последствия

- **uv.lock** изменится. При слиянии `gui/prototype` с `main` lock-файл перегенерируется
  (`uv lock`), а не сливается вручную.
- **CI:** для тестов окон на Linux нужен режим `QT_QPA_PLATFORM=offscreen`; на runner Ubuntu
  могут понадобиться системные библиотеки Qt (EGL, xkbcommon). Проверяется при первом запуске.
  Предлагается отдельное задание CI `gui`, чтобы сбой GUI не скрывал результаты научных тестов
  (раздел 6).
- **Размер окружения** заметно растёт (PySide6 — сотни мегабайт). Поэтому группа необязательная.

### 1.4. Будущая зависимость: таблицы XLSX (этап P7)

Конструктор отчёта (GUI_DESIGN.md, 18) сохраняет таблицы в XLSX. Ни Qt, ни NumPy, ни matplotlib
этого не умеют, поэтому понадобится отдельная библиотека в группе `gui`. Кандидаты определяются
при подготовке P7: лицензия, поддержка Python 3.13/3.14, запись без Excel. До решения владельца
зависимость не добавляется. Общий PDF-отчёт строится уже утверждёнными средствами (matplotlib
с этапа P6 и/или Qt), отдельной зависимости не требует [предварительно].

## 2. Проект записи для `docs/DECISIONS.md`

Номер присваивает владелец. В локальной копии основного проекта есть неопубликованная запись
D-029, поэтому номер здесь не указан.

> ### D-0xx. Графический интерфейс KK-VIM
>
> - **Статус:** Принято (предварительно — в части стека).
> - **Содержание:**
>   - GUI разрабатывается в отдельном пакете `src/kkvim_gui/` в ветке `gui/prototype`;
>     научные пакеты `kkvim` и `kkvim_reference` не импортируют `kkvim_gui`; `kkvim_gui`
>     не импортирует `kkvim_reference`;
>   - стек GUI: PySide6 + pyqtgraph (предварительно); публикационный экспорт — matplotlib;
>     зависимости — необязательная группа `gui`, научное ядро от них не зависит;
>   - GUI не определяет математическую модель, параметры метода и производные величины:
>     состав формы задаёт реестр возможностей бэкенда; неутверждённое помечается
>     «предварительно»;
>   - интерфейс на русском; научные рисунки — EN / RU, по умолчанию EN, язык рисунков
>     независим от языка интерфейса;
>   - публикационный экспорт: белый фон, PNG 300/600 dpi, PDF/SVG, без элементов интерфейса,
>     независимо от темы;
>   - демонстрационные результаты маркируются TEST DATA везде, включая экспорт;
>   - темы Light (по умолчанию) и Dark на едином наборе токенов;
>   - компоновка и визуальный стиль — `docs/gui/GUI_DESIGN.md`.
> - **Не входит:** выбор численных схем и критериев остановки; 3D-визуализация.
> - **Область:** код GUI, его зависимости, тесты и CI.
> - **Основание:** решение владельца проекта (2026-10-12).
> - **Связи:** D-001, D-009, D-026, D-028; AGENTS.md, разделы 3–4.
> - **Требует проверки:** версии зависимостей под Python 3.13 и 3.14; выполнение CI задания `gui`.

## 6. Тесты и CI

- **Тест независимости** `tests/test_package_independence.py` — расширить запреты:
  `kkvim → kkvim_gui`, `kkvim_reference → kkvim_gui`, `kkvim_gui → kkvim_reference`.
  Сейчас словарь `FORBIDDEN` допускает по одному запрещённому пакету на пакет; потребуется
  перечень. Это изменение общего тестового файла, поэтому оно вынесено сюда.
- **Тесты GUI** — отдельный каталог `tests/gui/` с pytest-qt; пропускаются, если группа `gui`
  не установлена.
- **CI** — отдельное задание `gui` (Windows и Ubuntu, Python 3.13): `uv sync --locked --extra gui`,
  `QT_QPA_PLATFORM=offscreen`, `pytest tests/gui`. Существующие задания не меняются.

## 7. Программный интерфейс между GUI и научным пакетом

GUI будет обращаться к решателю только через адаптер `kkvim_gui/backend/kkvim_adapter.py`.
Чтобы адаптер стал возможен, научной части понадобится (после утверждения спецификаций R1–R2,
по отдельному решению):

1. **Реестр возможностей:** поддерживаемые теории, закрепления, нагрузки; параметры метода
   с допустимыми диапазонами, единицами и назначением.
2. **Запуск с событиями:** итерация k и величины, которые спецификация определяет для
   мониторинга (Q-009); возможность прерывания.
3. **Результат:** сетка, поля, история итераций, производные величины (например,
   цилиндрическая жёсткость), статус критерия остановки, система координат и знак прогиба.
4. **Единицы:** правила согласования по D-009.

Это запрос к будущему API, а не требование к его форме: GUI подстраивается под научный пакет
через адаптер, а не наоборот. До появления API GUI работает только с DemoBackend.
