# GUI KK-VIM — подключение расчётного ядра

Ветка `gui/kkvim-backend`. Цели G3.1–G3.3. Дополняет [GUI_DESIGN.md](GUI_DESIGN.md), разделы 3.3–3.6, 5.3, 6 и 8.4.
Научные решения и код `kkvim` не меняются.

## 1. Архитектура

| Модуль | Назначение |
|---|---|
| `kkvim_gui/backend/kkvim_adapter.py` | Единственный модуль GUI, импортирующий `kkvim` (проверяется тестом). Вызывает решатели без изменений и копирует результат |
| `kkvim_gui/backend/request.py` | `RunRequest` — вход расчёта: введённый текст и единица плюс значение в СИ (m, Pa) |
| `kkvim_gui/backend/units.py` | Точные десятичные приставки СИ: `mm`, `cm`, `kPa`, `MPa`, `GPa` |
| `kkvim_gui/backend/outcome.py` | `RunOutcome` — неизменяемая копия результата; массивы только для чтения |
| `kkvim_gui/backend/process.py` | Расчёт в отдельном процессе (`multiprocessing`, spawn). «Стоп» завершает процесс |
| `kkvim_gui/backend/export.py` | `manifest.json`, `history.csv`, `field.csv` |
| `kkvim_gui/analysis/results.py` | Вкладки окна анализа по массивам решателя (pyqtgraph) |

Пакет `backend/` не зависит от Qt. Вычислительный процесс импортирует только его.

## 2. Вызовы решателя

| N | Функции `kkvim` | Научный статус |
|---|---|---|
| 1 | `rectangle_run.run_rectangle_physical`, `rectangle_run.halfstep_report` | решатель R3 ACCEPTED (D-043); отдельный расчёт — не научная приёмка |
| 2–3 | `rectangle.validated_rectangle_input` (проверки R3 и D), затем `coupled_run.run_coupled` | всегда **PROVISIONAL / NOT_QUALIFIED** (D-047, D-048) |

**Порядок проверки ввода** (`check_request`):
- сначала собственная проверка библиотеки `validated_rectangle_input`, поэтому E < 0 и t < 0 отклоняются и для N = 2–3, хотя D > 0;
- затем ограничения области, которые GUI не пропускает:
  - только SSSS: CCCC не реализован;
  - N = 1–3;
  - `dense` только при max(n_x, n_y) ≤ 40 (D-048.6): проверяются обе размерности, в том числе прямоугольные сетки
    (40×40 — допустимо; 40×41, 41×40, 40×160 — отказ).

Отклонённый ввод не вычисляется. Правило dense — одна функция `kkvim_adapter.dense_problem`. Её применяют:
- форма: сообщение под выбором «Преобразование DST» появляется сразу, «Выполнить расчёт» недоступна;
- `check_request`;
- диспетчер `RunManager.start`: процесс не создаётся;
- вычислительный процесс: `execute` до вызова `kkvim`.

**Режимы R4** передаются в `run_coupled` без подмены. По умолчанию — нормативный режим D-047 (`research_mode=False`, D-048.3).
Исследовательское продолжение через QR (D-048.5) включается только флажком «Исследовательское продолжение через QR».
Правило остановки исследования выбирается только при включённом флажке. Любая смена N сбрасывает выбор в нормативный режим,
поэтому исследовательский расчёт не запускается неявно.

| Режим в GUI | Аргументы `run_coupled` | Итог |
|---|---|---|
| Нормативный D-047 (по умолчанию; флажок выключен) | `research_mode=False` | NOT_QUALIFIED (или HALF_STEP_LIMIT_REACHED) после s = 1 |
| Исследовательский D-048: остановка по стабилизации (флажок включён) | `research_mode=True, stop_on_stabilization=True` | PROVISIONAL_FIELD_STABILIZED / MAX_HALF_STEPS / остановки защит |
| Исследовательский: фиксированное число полушагов (флажок включён) | `research_mode=True, stop_on_stabilization=False` | RESEARCH_LIMIT_REACHED / MAX_HALF_STEPS |

Допуски R4 (tol_∞, tol_E, s_min, s_max, η_max, K_RESEARCH) фиксированы решением D-048 и не редактируются. Для N = 1 доступны
tol_∞, tol_E, s_min, s_max и строгий режим NUMERICAL_SPEC.md 11.2 и 11.4; значения по умолчанию берутся из `kkvim`.

**Безразмерный прогиб:**
- w̄ = wD/(qa⁴), a — сторона по x (MATH_SPEC 2.5);
- для N = 1 — `RectangleResult.dimensionless_field`;
- для N = 2–3 — то же выражение по полю `run_coupled`.

## 3. Статусы

Коды решателя показываются без изменения смысла. Три статуса показываются раздельно: выполнение, остановка, научный статус.

- **Стабилизация R4.** PROVISIONAL_FIELD_STABILIZED отображается как предупреждение («не сходимость к точному решению»), а не как успех.
- **Ошибки.** Статус решателя `ERROR_*` — это ошибка выполнения. Если поле последнего выполненного полушага сохранено:
  - его можно открыть только кнопкой «Открыть диагностику (расчёт не завершён)»;
  - окно, рисунки и экспорт помечаются «ДИАГНОСТИКА · расчёт не завершён».
- **Без поля.** Расчёт без поля (STOPPED_RANK_LOSS_PROVEN, ERROR_INPUT) анализ поля не открывает; протокол и экспорт доступны.

## 4. Экспорт и протокол

**Протокол.** После каждого расчёта в `<данные приложения>/runs/<дата>_runNNN/` сохраняются:
- `manifest.json` — вход, параметры, статусы, журнал;
- `history.csv`.

На Windows это `%LOCALAPPDATA%\KK-VIM\kkvim-gui\runs`; путь меняется параметром `--protocol-dir`.

**Экспорт.** «Сохранить результаты…» в «Ходе расчёта» и «Экспорт ▾» в окне анализа записывают `manifest.json`, `history.csv` и `field.csv`
(узлы i, j, x [m], y [m], w [m], w_bar [1]).

**Единицы:**
- в JSON каждое размерное значение записано как `{"value", "unit"}`;
- у числовых столбцов CSV единица указана в заголовке; у текстовых столбцов и флагов единицы нет.

**Маркировка.** Первая строка CSV и `marks` в манифесте содержат PROVISIONAL / NOT_QUALIFIED для R4, DIAGNOSTIC для ошибок и TEST DATA для демонстрации.

**Точность.** Числа записываются через `repr`: значения совпадают с массивами решателя побитово. Экспортируются настоящие результаты
библиотеки, а не эталоны QA.

## 5. Запуск

```
uv sync --extra gui --group gui-test
uv run --extra gui kkvim-gui                 # решатель KK-VIM
uv run --extra gui python -m kkvim_gui       # то же
uv run --extra gui kkvim-gui --demo          # только демонстрация, TEST DATA, решатель не вызывается
uv run --extra gui kkvim-gui --protocol-dir D:\kkvim_runs
```

Порядок работы:
1. «Новый расчёт».
2. Параметры пластины, N и параметры метода.
3. «Выполнить расчёт» (F5).
4. «Ход расчёта» → «Открыть анализ результатов».

## 7. Ограничения

**Не реализовано:**
- CCCC;
- N = 4–6;
- моменты и напряжения;
- сравнение с эталонами (вкладка «Сравнение» неактивна);
- проекты `.kkv`;
- открытие сохранённых результатов;
- отчёт и публикационный экспорт рисунков;
- изолинии;
- пауза.

**Ход расчёта.** Решатель не сообщает промежуточные полушаги, поэтому s и k показываются после завершения.

**Остановка.** У решателя нет точки кооперативной отмены, поэтому «Стоп» завершает процесс принудительно.
