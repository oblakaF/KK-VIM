# GUI KK-VIM — функциональная предварительная версия (SSSS, N = 1)

Ветка `gui/ssss-n1-functional-preview`. Цели G3.1, G3.2; подготовка G5. Это **не** официальный выпуск R7.
Научные решения, спецификации, допуски и код `kkvim` / `kkvim_reference` не меняются.

## 1. Запуск без команд Python

| Способ | Что делает |
|---|---|
| Двойной щелчок по `KK-VIM-GUI.cmd` в корне репозитория | при первом запуске собирает приложение, далее открывает `dist\kkvim-gui-preview\Scripts\kkvim-gui.exe` |
| `scripts\windows\build_gui_preview.ps1 [-Target <папка>]` | сборка: wheel проекта (hatchling, `[project.gui-scripts] kkvim-gui`) в отдельное окружение с версиями из `uv.lock` |
| `kkvim-gui.exe` | оконное приложение без консоли |

Требуется `uv` в PATH (только для сборки). `uv.lock` и `.venv` проекта сборка не изменяет.

## 2. Объём

- **Доступно:** Кирхгоф–Ляв, SSSS, равномерная q, N = 1. Расчёт выполняет принятый решатель R3 (`kkvim.rectangle_run.run_rectangle_physical`, D-043) через существующий адаптер.
- **Недоступно, показано в форме выключенным:**
  - N = 2–3 (R4, NOT_QUALIFIED);
  - N = 4–6;
  - CCCC;
  - теории Тимошенко и Редди.
- **Двойная защита.** Даже если N ≠ 1 установлено программно, `MainWindow._start_run` его отклоняет. Превью-профиль включает `kkvim_gui.app.main` (`preview=True`). Классы окон по умолчанию сохраняют прежнее поведение для тестов бэкенда.

## 3. Результаты и сохранение

- **Вкладка «Поля»:**
  - «Карта и изолинии» — цветовое поле массива решателя и 10 изолиний по узловым значениям;
  - «3D-вид» — аксонометрический каркас того же поля.
- **Масштаб прогиба в 3D-виде.** Высота на рисунке равна −K·w. Значение K подписано на рисунке и записано в `manifest.json` (`visualization`); числовые значения не изменяются. «Авто» подбирает K из ряда 1–2–5 так, чтобы наибольший прогиб на рисунке был не больше 0,1·max(a, b).
- **«Сохранить расчёт и отчёт…»** (окно анализа и «Ход расчёта») создаёт папку `kkvim_<время>_runNNN/` с файлами:
  - `manifest.json`, `history.csv`, `field.csv` — существующий формат `backend.export`;
  - `field.png` и `surface.png`;
  - `report.html` — входные данные, значения в СИ, модель и метод, max|w| с координатами узла, w̄ = wD/(qa⁴), значение в центре (если там есть узел), статусы, история, ограничения.
- **Проверяемость отчёта.** Числа отчёта приведены и в форме `repr`, поэтому их можно сверить с `manifest.json` и `field.csv` точно.
- **Ошибки.** Ошибки ввода и сбои решателя показываются в форме и в «Ходе расчёта». Расчёт без поля результатом не сохраняется.

## 4. Проверка установленного приложения

`kkvim-gui.exe --smoke-test <папка>` проходит пользовательский путь в настоящих окнах:
- форма по умолчанию;
- расчёт;
- анализ;
- 3D-вид;
- сохранение пакета.

Результат: снимки окон, пакет расчёта и `smoke.json`. Код выхода 0 означает статус CONVERGED и сохранённый пакет.

## 5. Ограничения

- Отдельный расчёт — не научная приёмка. CONVERGED — выполнение критерия остановки, а не оценка погрешности.
- Максимум |w| ищется по узлам; значение в центре не интерполируется.
- Нет моментов, напряжений, сравнения с эталонами, проектов `.kkv`, открытия сохранённых расчётов.
- 3D-вид — каркас без удаления невидимых линий; углы обзора фиксированы.
- Приложение не подписано и не имеет установщика: это окружение Python с `kkvim-gui.exe`.
