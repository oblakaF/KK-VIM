# KK-VIM GUI на Windows: запуск двойным щелчком

Задание GUI-WIN-RUNNABLE-P1. Цели G3.3, G3.4, G5. Это рабочая программа на локальной машине, **не** квалифицированный
научный выпуск: научные статусы результатов не меняются (раздел 5).

## 1. Запуск

1. Откройте папку репозитория KK-VIM и дважды щёлкните `KK-VIM-GUI.cmd`.
2. Откроется полный интерфейс: SSSS и CCCC, N = 1–6, в обычном режиме. Демонстрационный режим и прежнее превью N = 1
   не открываются.

При каждом запуске `KK-VIM-GUI.cmd` сначала проверяет, собрана ли установленная программа из текущих исходников.
Проверка занимает доли секунды. Программа — `dist\kkvim-gui\Scripts\kkvim-gui.exe`, оконная, без консоли Python.

## 2. Первая сборка и что для неё нужно

- **Нужно:** Windows, PowerShell (входит в Windows) и [uv](https://docs.astral.sh/uv/) в PATH.
- **Python ставить не нужно:** uv сам загрузит Python 3.14, если его нет.
- **Сеть:** без неё первая сборка возможна, только если пакеты уже есть в кэше uv.
- **Как проходит первая сборка:** окно консоли показывает ход сборки, затем программа запускается. Обычно это меньше
  минуты, если пакеты уже в кэше uv.
- **Из чего собирается:**
  - wheel проекта (hatchling, точка входа `kkvim-gui = kkvim_gui.app:main`);
  - точные версии `uv.lock`: numpy, scipy, PySide6-Essentials, pyqtgraph;
  - переносимое внутри папки окружение (`uv venv --relocatable`).
- **Что не меняется:** `uv.lock` и `.venv` проекта.
- **Вручную, без запуска:** `powershell -ExecutionPolicy Bypass -File scripts\windows\build_gui.ps1`. Ключи:
  - `-Check` — только проверить актуальность;
  - `-IfStale` — собрать, только если установка устарела.

## 3. Где лежит программа и как она обновляется

- **Место:** `dist\kkvim-gui\` в папке репозитория (`dist\` не попадает в git). Отметка сборки —
  `dist\kkvim-gui\kkvim-gui-build.json`: отпечаток SHA256 исходников, время, версия uv.
- **Когда пересобирается.** Отпечаток охватывает:
  - все файлы `src\`;
  - `pyproject.toml`, `uv.lock`, `README.md`;
  - скрипт сборки и версию Python.

  После обновления репозитория (`git pull`, переключение ветки) отпечаток меняется, и следующий запуск сам пересобирает
  программу. Устаревшая сборка не запускается никогда. Прежнее превью без отметки тоже считается устаревшим.
- **Сбой пересборки.** Если пересборка не удалась (нет uv, ошибка сборки, программа открыта и папку нельзя заменить):
  - прежняя установка остаётся как была;
  - ничего не запускается;
  - окно показывает причину;
  - код выхода: 1 — ошибка сборки или занятая папка, 2 — нет uv.

  Закройте открытые окна KK-VIM и запустите снова.
- **Как устроена замена:** новая сборка готовится в `dist\kkvim-gui.staging`. Она заменяет прежнюю только после проверки
  запуска на итоговом месте. Скрипт пишет только в `dist\kkvim-gui`, `dist\kkvim-gui.staging`, `dist\kkvim-gui.previous`
  и `dist\build-gui`. Другие папки и файлы пользователя не трогаются, процессы не завершаются.
- **Что не хранить в `dist\kkvim-gui`:** собственные файлы. Эта папка заменяется целиком.

## 4. Где сохраняются расчёты

- **Протокол каждого расчёта** — `manifest.json` и `history.csv`, без поля. Он пишется в
  `%LOCALAPPDATA%\KK-VIM\kkvim-gui\runs\<дата>_runNNN\`; другую папку задаёт ключ `--protocol-dir`.
- **«Сохранить расчёт и отчёт…»** (в «Ходе расчёта» и в окне анализа) создаёт в выбранной папке новую подпапку
  `kkvim_<время>_runNNN\`:
  - `manifest.json`, `history.csv`;
  - файл поля (раздел 5);
  - `field.png`, `surface.png`, `report.html` (с разделом «Сравнение с независимыми эталонами»);
  - `comparison.csv` — только если вкладка «Сравнение с эталоном» показывает сравнение с эталонами.
- Серия нагрузок: «Серия нагрузок» в блоке «Нагрузка», «Рассчитать серию», затем «Нагрузка — прогиб…» в «Ходе расчёта»;
  «Сохранить серию…» создаёт новую папку `kkvim_series_<дата>_sNNN` с `load_series.csv`, `series_manifest.json` и графиком.
- Эталон Навье для SSSS считается установленной программой в отдельном процессе (`python -I -m kkvim_navier_worker` из той же
  установки); исходники и папка `scratch` для этого не нужны.
- **Перезапись.** Существующая папка расчёта не перезаписывается.

## 5. Принятый результат и исследовательский — как различить

| Расчёт | Файл поля | Пометка | Научный статус |
|---|---|---|---|
| SSSS, N = 1, CONVERGED | `field.csv` | нет | решатель R3 ACCEPTED (D-043); отдельный расчёт — не научная приёмка |
| SSSS, N = 2–3 | `field_research.csv` | PROVISIONAL / NOT_QUALIFIED | R4 (D-047, D-048), не сходимость |
| SSSS, N = 4–6; CCCC, N = 1–6 | `field_research.csv` | RESEARCH_ONLY / PROVISIONAL / NOT_QUALIFIED | только исследование |
| Защитная остановка, остановка по правилу, ошибка с полем | `field_diagnostic.csv` | DIAGNOSTIC | только диагностика, не результат |

- Пометка видна в «Ходе расчёта», на значке окна анализа, на рисунках, в первой строке CSV и в `report.html`.
- `manifest.json` (схема 2) содержит `statuses.solver_status`, `statuses.field_role`, `statuses.field_file` и
  `statuses.requested_run_completed`.
- Для CCCC при N ≥ 2 полушаг s = 2 выполняется только после сертификатов RN-5 и RT-7 решателя. Отказ сертификата
  показывается как защитная остановка с диагностическим полем s = 1.

## 6. Ограничения установки

- **Не автономный исполняемый файл.** `kkvim-gui.exe` — точка входа окружения Python в `dist\kkvim-gui`. Окружение
  ссылается на интерпретатор Python, установленный uv на этой машине. Перенос папки на другой компьютер не проверялся и
  не поддерживается. Для автономного дистрибутива нужен отдельный инструмент упаковки; в этой работе он не добавлялся.
- **Нет подписи и установщика.** Программа не подписана и не имеет установщика или ярлыка в меню «Пуск».
- **Где проверено:** Windows 10, Python 3.14 (uv), uv 0.13.
