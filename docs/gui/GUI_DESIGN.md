# KK-VIM GUI — архитектура и дизайн

- **Этап:** P0 — документация архитектуры и дизайна. Кода GUI нет.
- **Статус документа:** P0 предварительно утверждён владельцем (2026-10-12); окончательные решения
  по вопросам раздела 15 внесены.
- **Ветка:** `gui/prototype` (рабочая копия `D:\git\KK-VIM-GUI`).
- **Читатели:** владелец проекта (утверждение) и агент GUI Designer (реализация этапов P1–P7).
- **Связанный документ:** [PROPOSED_CHANGES.md](PROPOSED_CHANGES.md) — предложения по новым
  зависимостям и изменениям общих документов проекта. Здесь они не применяются.

Документ фиксирует решения владельца по GUI, принятые 2026-10-12 в ходе обсуждения
по макетам Figma, и описывает, как их реализовать. Формальная запись в `docs/DECISIONS.md`
делается владельцем отдельно (предложение — PROPOSED_CHANGES.md, раздел 2).

Обозначения: **[решение]** — утверждено владельцем; **[инж.]** — инженерный выбор этого документа,
может быть пересмотрен без изменения решений; **[спец.]** — определяется научной спецификацией
проекта, GUI не решает; до спецификации в интерфейсе помечается «предварительно».

## 2. Принципы и ограничения

1. **GUI не определяет математику.** В GUI нет формул расчёта. Производные величины
   (например, цилиндрическая жёсткость) вычисляет научный пакет и передаёт в результате; GUI
   только отображает (AGENTS.md, раздел 3: разрешение писать служебный код не даёт права
   выбирать модель).
2. **Состав формы задаёт бэкенд.** Доступные теории, закрепления, нагрузки и параметры метода
   берутся из реестра возможностей бэкенда (раздел 3.4). Неподдерживаемое отображается
   неактивным с подсказкой «планируется» или не отображается.
3. **Неизвестное помечается, а не придумывается.** Всё, что зависит от неутверждённой
   спецификации, показывается с пометкой «предварительно» (перечень — раздел 13).
4. **Три статуса раздельно** (AGENTS.md, раздел 4): выполнение расчёта, выполнение критерия
   остановки, научная приёмка. Ни один элемент интерфейса не объединяет их в общий «успех».
5. **Демонстрационные данные не маскируются под результаты** (раздел 9).
6. **GUI не трогает научный код и документы.** Код GUI — только в `src/kkvim_gui/`.
7. **Без пустых областей.** Компоновка рассчитана на 1280×800 без прокрутки основной страницы.

## 3. Архитектура

### 3.1. Пакеты и направления зависимостей

```
src/kkvim/            научное ядро            — GUI не изменяет
src/kkvim_reference/  независимые эталоны     — GUI не изменяет
src/kkvim_gui/        графический интерфейс
```

- `kkvim_gui` может импортировать `kkvim` — только в модуле адаптера бэкенда (3.4).
- `kkvim` и `kkvim_reference` **не импортируют** `kkvim_gui`. Проверяется тестом
  (PROPOSED_CHANGES.md, раздел 6).
- `kkvim_gui` **не импортирует** `kkvim_reference` [инж.]. Сравнение с эталонами (будущая
  вкладка) читает сохранённые результаты эталонов как данные; способ их получения — решение
  будущего этапа G4.

### 3.2. Структура пакета `kkvim_gui` [инж.]

```
kkvim_gui/
  __main__.py, app.py      запуск; QApplication; выход после закрытия последнего окна
  settings.py              настройки пользователя (QSettings): тема, язык графиков по умолчанию
  theme/
    tokens.py              цветовые и размерные токены Light / Dark (раздел 10)
    qss.py                 генерация QSS из токенов
    plot_style.py          стиль экранных графиков из токенов
  i18n/                    перевод интерфейса (Qt tr / .ts) — позже
  model/
    run_config.py          RunConfig — входные данные со своими единицами
    run_result.py          RunResult — результат, статусы, происхождение данных
    project_file.py        чтение и запись .kkv
  backend/
    base.py                интерфейс Backend, реестр возможностей, события выполнения
    demo.py                DemoBackend — синтетические данные TEST DATA
    kkvim_adapter.py       адаптер к kkvim — после появления решателя
  figures/
    spec.py                FigureSpec — описание рисунка, не зависящее от отрисовки
    text/en.json, ru.json  каталог текстов рисунков (раздел 7)
    symbols.py             математические символы в трёх представлениях
    screen.py              экранная отрисовка (pyqtgraph, зависит от темы)
    publication.py         публикационная отрисовка (P6; не зависит от темы)
  widgets/                 общие виджеты: карточка, поле с единицей, плашка статуса, таблица
  main_window/
    window.py              MainWindow: панель приложения + QStackedWidget
    start_view.py
    setup_view.py          все блоки параметров
    plate_scheme.py        схема пластины (QPainter, без OpenGL)
    run_view.py            выполнение и завершение

    window.py              AnalysisWindow (отдельный QMainWindow)
    tabs/                  overview, fields, sections, values, convergence, comparison
    inspector.py
```

### 3.3. Модель данных [инж.]

**RunConfig** — входные данные расчёта. Каждое размерное значение хранится как пара
«число + единица СИ ввода» (например, `h = 10.0 mm`) без пересчёта (GUI-D14). Правила согласования единиц —
предмет спецификации ввода-вывода (D-009) [спец.]; пересчёт в единицы решателя выполняет адаптер
бэкенда, а не форма.

**Файл проекта `.kkv`** — JSON: `schema_version`, `RunConfig`, метаданные проекта
(имя, даты). Результаты в файл проекта не встраиваются.

**RunResult / папка результата** [инж.]:

```
<run_id>/
  manifest.json   schema_version, run_id, дата, версия программы, git commit,
                  data_origin ("demo" | "solver"), RunConfig, статусы, скалярные результаты
  arrays.npz      сетка x, y; поля; история итераций
```

- `data_origin` — единственный источник признака TEST DATA (раздел 9). Интерфейс не даёт его
  изменить.
- Окно анализа открывается по `RunResult` в памяти или по папке результата; результат
  неизменяем после завершения расчёта.
- Состав полей и истории итераций — [спец.] (раздел 13).

### 3.4. Бэкенд

Интерфейс `Backend` [инж.]:

- `capabilities()` — реестр возможностей: теории, закрепления, нагрузки, параметры метода
  с допустимыми диапазонами и единицами;
- `validate(config)` — формальная и предметная проверка входа;
- `start(config)` → поток событий: `stage(text)`, `iteration(k, metrics)`, `log(level, text)`,
  `finished(result)`, `failed(error)`, `cancelled()`; `cancel()`.

**DemoBackend** — генерирует события по таймеру и синтетические поля (раздел 9).
Реестр возможностей DemoBackend отражает только утверждённую первую реализацию
(Кирхгоф–Ляв; изотропный линейно-упругий материал; равномерная нагрузка; SSSS, CCCC; N = 1–3,
исследование N = 4–6; D-003, D-005–D-007).

**Адаптер kkvim** (изоляция процесса — 3.6) — создаётся после появления решателя и согласования программного интерфейса
с научной частью (PROPOSED_CHANGES.md, раздел 7). Реальный расчёт выполняется в отдельном
процессе: интерфейс не блокируется, расчёт можно прервать, сбой решателя не закрывает GUI.
DemoBackend может работать в основном процессе на QTimer.

### 3.5. Окна и состояния

- **MainWindow** — одно на приложение; состояния: `Start → Setup → Run(running) →
  Run(finished | cancelled | failed)`; из завершённых состояний — возврат к `Setup`.
- **AnalysisWindow** — создаётся только кнопкой «Открыть анализ результатов» (или «Открыть
  результаты…» со стартовой страницы). Можно открыть несколько. Окно хранит свой `RunResult`
  и не зависит от последующих изменений параметров в главном окне. Закрытие главного окна
  не закрывает окна анализа; приложение завершается после закрытия последнего окна.
- Изменение параметров после расчёта делает результат главного окна устаревшим (плашка
  «параметры изменены после расчёта»); открытые окна анализа остаются действительными.


### 3.6. Изоляция GUI и вычислительного процесса [решение]

- Каждый реальный расчёт выполняется в **отдельном процессе** (не в потоке GUI). GUI и процесс
  обмениваются только событиями и данными (3.4); сбой, зависание или остановка расчёта не
  завершают программу и не закрывают окна.
- «Стоп» завершает процесс расчёта штатным запросом, а если он не завершился за отведённое
  время — принудительно, вместе со всем деревом дочерних процессов. Запуск получает статус
  «Остановлен пользователем» и фактическую длительность; частичные данные остановленного
  запуска как результаты не показываются.
- Пауза поддерживается, только если бэкенд объявит безопасный механизм приостановки
  в реестре возможностей; иначе её нет в интерфейсе.
- Ограничение числа вычислительных потоков (21.1) передаётся процессу при запуске
  и сохраняется в параметрах запуска.
- Сейчас реального вычислительного процесса нет: демонстрационный бэкенд работает
  в процессе GUI на таймере, и его «Стоп» меняет только состояние демонстрационного запуска.

## 4. Общие элементы окон

### 4.1. Панель приложения (под системной рамкой Windows)

Высота 44–48 px, фон `header.bg` (тёмно-синий в обеих темах).

```
┌ ▲ КК-ВИМ │ plate_ssss_01.kkv ●  Главная  Настройка расчёта  Ход расчёта  [TEST DATA · демо-данные] ⚙ ┐
```

- слева: знак и имя программы; имя проекта; `●` — несохранённые изменения;
- главное окно: навигация «Главная · Настройка расчёта · Ход расчёта» (17.1; уточнено на P1.5,
  заменяет кнопку «⌂ Главная»; макеты разделов 5–6 показывают исходный вариант панели);
- справа: плашка TEST DATA (только при `data_origin = demo` или DemoBackend) и «⚙»;
  шестерёнка открывает небольшое меню под собой (выровнено по её правому краю): «Настройки»
  и «Справка F1». Отдельной кнопки «?» нет (уточнено после P2.2). «F1» в меню — подсказка,
  а не второе сочетание: F1 остаётся контекстным сочетанием окна (17.3); на узком окне имя
  проекта скрывается, плашка сокращается (19.2).

Заголовок системной рамки: `КК-ВИМ — <проект>` и `КК-ВИМ: анализ — <run_id>`.

### 4.2. Строка состояния

Слева — состояние (`● Готово`, `● Выполняется`, `● Ошибка`); справа — бэкенд и версия
(`Бэкенд: демонстрационный · KK-VIM 0.0.0`).

### 4.3. Окно «Настройки»

Модальное окно из меню «⚙» → «Настройки» любого окна. Выбор — сегментными переключателями
(выбранный сегмент залит акцентным цветом в обеих темах; фокус клавиатуры — отдельная рамка;
Tab, Space и стрелки ←/→). Изменения применяются кнопкой OK, «Отмена» ничего не меняет:

- **Тема:** Light (по умолчанию) │ Dark — применяется ко всем окнам;
- **Язык графиков по умолчанию:** EN (по умолчанию) │ RU — начальное значение при запуске
  (раздел 7.2);
- позже: язык интерфейса (после появления перевода).

### 4.4. Размеры и масштаб

Пересмотрено на P1.5 (GUI-D19, раздел 19): жёсткий минимум 1280×800 отменён.

- размеры — в логических пикселях Qt; Windows делит физическое разрешение на масштаб:
  Full HD при 150 % — около 1280×720, при 175 % — около 1097×617, при 200 % — 960×540;
- расчётный (начальный) размер обоих окон — 1440×900, но не больше доступной рабочей области;
- минимальный размер — 960×540 логических пикселей (Full HD при 200 %), но не больше
  доступной рабочей области [инж.];
- полная компоновка без прокрутки рассчитана на ширину от 1100 логических пикселей; уже —
  адаптивная компоновка (раздел 19.2); основные действия видны всегда.

**Колонки.** Левая — около 60 % ширины: сетка карточек 2×2, широкая карточка метода и под ними
таблица «Сводка». Правая — около 40 %: схема модели на всю высоту колонки.
(Уточнено на P1 по скриншотам: «Сводка» перенесена под блоки параметров, чтобы не оставлять
пустых областей; схема ASCII выше показывает исходный вариант.)

**Блоки и поля.**

| Блок | Поля | Источник состава |
|---|---|---|
| Геометрия | a, b, h; единица длины каждого поля — m / cm / mm (D-009) | D-005, D-009 |
| Материал | E, ν; тип материала — текст «изотропный, линейно-упругий» | D-006 |
| Нагрузка | тип «равномерная» (единственный доступный); q | D-005 |
| Граничные условия | сегментный переключатель SSSS / CCCC | D-007 |
| Расчётная модель и метод | теория (список с единственным активным пунктом «Кирхгоф–Ляв»); N (1–3; 4–6 с пометкой «исследование»); остальные параметры — по реестру бэкенда | D-003, D-006; остальное [спец.] |

Поля метода, кроме N, до утверждения NUMERICAL_SPEC отображаются с пометкой «предварительно»
(Q-009 — критерии остановки и нормы; Q-010 — разностные схемы).

**Поле ввода с единицей.** Число и единица внутри одного поля: единица — выпадающий список,
если допускается выбор, иначе текст. Точка и запятая принимаются как десятичный разделитель;
текст поля автоматически не переписывается (раздел 11.2).

**Проверка ввода** (реализовано на P2.1).

- значения формы хранятся в одной модели настройки главного окна (`SetupModel`) и сохраняются
  при переходах между разделами в пределах сеанса; при запуске фиксируется снимок параметров,
  который показывают «Ход расчёта» и окно анализа;
- разбор числа и формальная проверка — при подтверждении значения (Enter, уход из поля)
  и перед запуском (11.2); поле, уже отмеченное ошибкой, перепроверяется при каждом изменении,
  и сообщение исчезает, как только значение исправлено;
- формальные правила GUI: значение задано; это число; конечное; a, b, h, E > 0; k_max — целое
  ≥ 1 (число итераций, D-003); ν и q — только «конечное число»; «Сетка МКР» и «Критерий
  остановки» не проверяются до NUMERICAL_SPEC (Q-009, Q-010);
- предметные диапазоны (например, допустимые ν, отношения размеров) задаёт спецификация
  [спец.]; GUI их не придумывает;
- ошибка показывается под полем (красная рамка и текст на русском), без модальных окон;
  введённый текст сохраняется;
- нижняя панель: «✓ Формальная проверка ввода пройдена. Научные ограничения не проверялись:
  решатель не подключён, расчёт демонстрационный (TEST DATA)» или «⚠ Исправьте поля: n
  (первое — …)» с кнопкой «Перейти к полю»; формулировки не создают впечатления научной
  проверки;
- «Выполнить расчёт» и F5 сначала проверяют все поля; при ошибках расчёт не запускается,
  фокус переходит к первому ошибочному полю (страница прокручивается к нему).

**Схема модели** (`plate_scheme.py`, QPainter; реализовано на P2.2, уточняет исходный вариант
с аксонометрией):

- вид сверху прямоугольной пластины в **точной пропорции a : b** (длины переводятся в метры
  только для рисунка; при крайних отношениях пропорции сохраняются, подпись «Пропорции a : b
  сохранены»); размерные линии a и b с засечками; подписи — введённый текст и единица СИ;
- небольшой вид сбоку с толщиной h; если толщина или длина вида сбоку утрированы — подпись
  «вид сбоку · не в масштабе»;
- нагрузка q: на виде сверху — нейтральный точечный узор по всей площади; на виде сбоку —
  «гребёнка» линий, перпендикулярных пластине, **без стрелок**; подпись «q = … — равномерно
  распределённая по всей площади»;
- закрепления: SSSS — треугольники по краям; CCCC — штриховка заделки; краткая легенда
  текущего варианта;
- **оси координат и направление (знак) нагрузки не показываются**, пока постановка КК-ВИМ
  их не зафиксирует: `MATH_SPEC.md` (часть A) не принят (D-029); соглашения спецификации
  эталона Навье относятся к эталону и на схему КК-ВИМ не переносятся; на схеме — пояснение;
- схема показывает **текущий ввод** (модель настройки); «Ход расчёта» и окно анализа — снимок
  параметров запуска;
- при недопустимых a, b или h геометрия не рисуется: «Схема ожидает исправления параметров: …»;
  при недопустимом q геометрия остаётся, нагрузка помечена «ожидает исправления»;
- перерисовка при каждом изменении параметров; цвета из токенов темы; векторная отрисовка
  с косметическими перьями (чётко при любом DPI).

**Нижняя панель действий.** Слева — сводка проверки; справа — «Сохранить проект» (Ctrl+S)
и «▶ Выполнить расчёт» (F5, основная кнопка).

### 5.3. Ход расчёта — диспетчер запусков [решение]

Уточнено после P2.2: большой график сходимости убран из главного окна. Все научные графики —
только в окне «Анализ результатов».

```
├────────────────────────────────────────────────────────────────────────────────────┤
│ Завершён — 7 с                                      [Открыть анализ результатов] │
│ ✓ Выполнение: завершён   ✓ Критерий остановки выполнен на k = 8 (s = 16)   ○ Приёмка │
│ КК-ВИМ · N = 3 · k_max = 100 · сетка МКР: … · SSSS · a … b … h … · TEST DATA        │
│ ⚠ Доступно в окне анализа: заготовки … — TEST DATA, не результаты решателя          │
├──────────────────────────────────────────────────┬─────────────────────────────────┤
│ Диспетчер запусков                               │ Выбранный запуск     TEST DATA  │
│ Дата и время │ Метод  │ Параметры │ Статус │ Длит.│ Проект, Метод, Параметры,       │
│ 12.10 10:48  │ КК-ВИМ │ N = 3 …   │Завершён│  7 с │ Пластина, Этап,                 │
│ 12.10 10:52  │ КК-ВИМ │ N = 2 …   │Выполн. │  3 с │ Счётчики: s — полушаги,         │
│                                                  │ k — завершённые циклы (D-030),  │
│                                                  │ Прошло времени, Важные сообщения│
├──────────────────────────────────────────────────┴─────────────────────────────────┤
│ ▸ Подробный журнал (свёрнут)                                                        │
```

- **Диспетчер** — таблица запусков текущего сеанса: дата и время запуска; метод (КК-ВИМ;
  в будущем МКР, МКЭ, Навье); краткие параметры метода (N, k_max, сетка МКР и другие
  применимые); статус (выполняется, завершён, остановлен, ошибка); **индивидуальная
  длительность** каждого запуска («Завершён — 5 с», «Завершён — 30 с»).
- Время каждого запуска измеряется отдельно: во время выполнения обновляется, после
  завершения или остановки фиксируется. **Оценка оставшегося времени не вычисляется.**
- История хранится только в текущем сеансе; постоянное сохранение — отдельная задача.
- **Выбранный запуск** (справа): проект; метод и теория; параметры; пластина; текущий этап;
  счётчики (только для итерационных методов); прошедшее время; важные предупреждения и ошибки.
- **Счётчики КК-ВИМ не смешиваются** (D-003, D-030): N — число членов; s — выполненные
  координатные полушаги; k = ⌊s/2⌋ — завершённые циклы. Методы без итераций счётчиков
  не показывают; фиктивные итерации не выводятся.
- **Подробный журнал** — сворачиваемый раздел, по умолчанию свёрнут. В обычном состоянии
  видны только важные сообщения (в карточке выбранного запуска). Журнал не заполняется
  строками «Итерация 1», «Итерация 2»…: только этапы, итог и предупреждения.
- «Стоп» — с подтверждением; статус «Остановлен пользователем», фактическая длительность
  фиксируется; анализ прерванного расчёта недоступен. Сейчас остановка демонстрационная
  (меняется только состояние демонстрационного запуска). С реальным бэкендом «Стоп» завершает
  отдельный вычислительный процесс, при необходимости — принудительно всё дерево его дочерних
  процессов; главное окно и программа при этом не закрываются (3.6).
- «Пауза / Продолжить» — только когда вычислительный бэкенд предоставит безопасный механизм
  приостановки; до этого кнопок паузы нет (неработающие элементы не показываются).
- Одновременно активен не более одного запуска: на время расчёта параметры заблокированы.
- Демонстрационный бэкенд: этапы и счётчики синтетические, помечены TEST DATA; запуск
  не выдаётся за расчёт решателя.

### 5.4. Завершение расчёта [решение]

После завершения вверху показывается итог выбранного запуска: статус и фактическое время
выполнения; три раздельных статуса (выполнение, критерий остановки, научная приёмка);
основные доступные результаты с пометкой TEST DATA; кнопка **«Открыть анализ результатов»**
(только для завершённого запуска; окно анализа открывается только кнопкой, GUI-D08).
Диспетчер остаётся доступным; можно выбрать любой прежний запуск.

### 5.5. Навигация во время расчёта [решение]

- «Главная», «Настройка расчёта» и «Ход расчёта» доступны и во время выполнения.
- Над карточками страницы настройки — хорошо видимая информационная полоса «Выполняется
  расчёт. Изменение параметров временно заблокировано. Просмотр и копирование доступны»
  (только во время активного расчёта; без всплывающих окон).
- На экране «Ход расчёта» нет кнопки «Вернуться к параметрам»: переход — через верхнюю навигацию.
- Параметры активного расчёта на странице настройки **только для просмотра**: поля только
  для чтения (выделение и копирование работают), списки и переключатели неактивны, кнопка
  «Выполнить расчёт» неактивна, в нижней панели — пояснение о блокировке.
- После завершения или остановки редактирование снова доступно.
- Окно анализа и «Ход расчёта» используют снимок параметров запуска (P2.1).

## 7. Язык научных рисунков (EN / RU)

### 7.1. Требования [решение]

- Все графики и рисунки KK-VIM поддерживают EN и RU; по умолчанию — **EN**.
- Язык графиков независим от языка интерфейса (интерфейс остаётся русским).
- Переключатель «Графики RU │ EN» — в панели инструментов окна анализа.
- Переключение в любой момент, **без повторного расчёта**: перерисовываются только тексты.
- Переключение меняет **все текстовые элементы рисунков**: заголовки, подписи осей, названия
  величин, легенды, подписи цветовых шкал, аннотации.
- Экспорт PNG, PDF и SVG выполняется на выбранном языке графиков.
- Численные данные, единицы измерения и результаты расчёта при переключении не изменяются.
- Тема GUI не влияет на публикационный экспорт.

### 7.2. Поведение переключателя [решение]

- Язык графиков — общий для сеанса: переключение в любом окне анализа применяется ко всем
  рисункам приложения, включая график сходимости главного окна. Причина — при сравнении двух
  окон рядом подписи не расходятся.
- Начальное значение при запуске — из настроек («Язык графиков по умолчанию», EN).

### 7.3. Что меняется и что нет

| Элемент | При переключении EN ↔ RU |
|---|---|
| Числовые значения данных, сетка, поля | не меняются |
| Единица измерения и её масштаб (например, mm) | не меняется; никаких автоматических пересчётов (раздел 11.1) |
| Обозначение единицы | не меняется: международное обозначение СИ (`m`, `mm`, `kPa`, `GPa`) в обоих языках [решение] |
| Десятичный разделитель в подписях делений и аннотациях | по языку: EN `0.842 mm`, RU `0,842 mm` [решение; форматирование числа, значение не меняется] |

| Обозначения закреплений SSSS, CCCC | не меняются |
| Название метода | `KK-VIM` / `КК-ВИМ` |
| Маркер демонстрационных данных | EN `TEST DATA`; RU `ТЕСТОВЫЕ ДАННЫЕ · TEST DATA` [решение] (раздел 9) |

## 8. Публикационный экспорт рисунков

Реализация — этап P6. Архитектура предусматривается с P3, чтобы экранные рисунки сразу
строились из независимого описания.

### 8.1. Требования [решение]

- белый фон независимо от темы GUI;
- чёткие подписи на выбранном языке графиков (EN по умолчанию);
- единицы физических величин в подписях;
- корректные математические символы;
- PNG 300 и 600 dpi; PDF и SVG для векторного экспорта, где применимо;
- никаких элементов интерфейса на рисунке;
- TEST DATA для демонстрационных результатов (раздел 9).

### 8.2. Архитектура [инж.]

```
RunResult ──► FigureSpec (данные + ключи текстов + единицы + тип рисунка)
                 │
                 ├──► ScreenRenderer      pyqtgraph; стиль из токенов темы; интерактивность
                 └──► PublicationRenderer фиксированный стиль; без темы; PNG / PDF / SVG
```

- `FigureSpec` не зависит ни от темы, ни от библиотеки отрисовки; содержит ссылки на массивы,
  ключи текстов, единицы, выбор шкалы, признак TEST DATA.
- **PublicationRenderer — matplotlib** (рекомендация; новая зависимость, PROPOSED_CHANGES.md,
  раздел 1). Причины: векторный PDF/SVG, mathtext для формул, точный dpi, viridis/cividis
  встроены. Встроенный экспорт pyqtgraph не даёт PDF и mathtext.
- Экранные рисунки и публикационные — разные отрисовки одного FigureSpec: тема экрана
  на публикацию не влияет по построению.

### 8.3. Диалог «Рисунок для публикации…» [инж.]

| Параметр | Значения |
|---|---|
| Формат | PNG / PDF / SVG |
| Разрешение PNG | 300 / 600 dpi |
| Ширина | 85 mm (одна колонка) / 175 mm (две колонки) / своя; высота — по пропорциям рисунка |
| Язык подписей | текущий язык графиков, показывается в диалоге; переключается там же |
| Аннотации | экстремум — вкл./выкл. (по умолчанию выкл.) |
| Предпросмотр | изображение, построенное PublicationRenderer |

- **Стиль публикации (фиксированный):** белый фон; оси и текст чёрные; шрифт без засечек
  с поддержкой кириллицы и математических символов (выбор и проверка шрифта — P6); основной
  кегль 8 pt; толщина линий 0,75–1,0 pt; сетка выключена по умолчанию.
- **Векторные форматы:** оси, линии, изолинии и тексты — векторные; цветовое поле —
  встроенное растровое изображение с выбранным dpi («где применимо»).

## 11. Типографика, числа и единицы

- Шрифт интерфейса: Segoe UI Variable (запасной — Segoe UI); 9–10 pt; заголовки карточек 10 pt
  полужирный.
- Числа в таблицах и метриках — цифры одинаковой ширины (tabular figures), выравнивание
  по правому краю.
- Интерфейс (русский): десятичная запятая; научная запись `6,7·10⁻⁴`; по умолчанию
  4 значащие цифры [инж.]; единица — всегда рядом со значением.
- Рисунки — по языку графиков (7.3).

### 11.1. Единицы измерения — строго СИ [решение, GUI-D14]

- Во всей программе используется система СИ независимо от языка: входные параметры,
  вычисления, результаты, графики, таблицы, экспорт.
- Обозначения единиц — международные, одинаковые в русском интерфейсе и на рисунках EN и RU:
  `m`, `mm`, `Pa`, `kPa`, `MPa`, `GPa`, `N·m`. Русские обозначения (`м`, `мм`, `кПа`) не используются.
- Допускаются кратные и дольные единицы СИ (`mm`, `kPa`, `MPa`, `GPa` и т. п.), если масштаб
  явно указан рядом со значением и согласован с остальными данными (D-009).
- Переключатель RU/EN меняет только текстовые подписи рисунков. Выбор языка **никогда**
  не преобразует единицы и численные данные.
- Безразмерные величины (ν, N, k) отображаются без единицы.
- Каждое размерное поле ввода показывает свою единицу. Выбор единицы из списка (например,
  длина `m` / `cm` / `mm` по D-009) — только явное действие пользователя.
- Правила пересчёта ввода в единицы решателя — спецификация ввода-вывода (D-009, раздел 13);
  GUI молча единицы не пересчитывает.

### 11.2. Ввод чисел и десятичный разделитель [решение]

- Все числовые поля принимают **точку и запятую** как десятичный разделитель, независимо
  от локали Windows и языка графиков: `0.1` = `0,1`; `-0.25` = `-0,25`; `1.5e-3` = `1,5e-3`.
  Экспонента — `e` или `E`, знак — `+`/`-` (минус U+2212 при вставке тоже принимается).
- Разделители тысяч в числовых полях не используются и не принимаются.
- Текст поля во время ввода **не изменяется**: нет посимвольной замены разделителя, масок
  и валидаторов, блокирующих набор. Промежуточные состояния (`-`, `0,`, `1e-`, пустое поле)
  допустимы во время редактирования.
- Разбор выполняется **при подтверждении** значения (Enter, уход фокуса, запуск расчёта).
  Введённый текст при этом не переписывается, чтобы не терять историю отмены.
- Недопустимое значение: поле помечается ошибкой, под полем — сообщение; **введённый текст
  сохраняется**; расчёт не запускается.
- Разобранное значение хранится как обычное число Python (`float`). В JSON (`.kkv`,
  `manifest.json`) и других машинных форматах — стандартная запись числа с точкой.
- Результат расчёта не зависит от того, какой разделитель ввёл пользователь: одинаковые
  значения дают одинаковый `RunConfig`.
- Научное ядро получает только числа; разбор текста — задача GUI.
- Реализация разбора и проверки — этап P2. В P1 числовые поля — обычные QLineEdit
  со стандартным редактированием (12.1).

## 12. Клавиатура

### 12.1. Стандартное редактирование Windows [решение]

Во всех редактируемых полях и окнах (QLineEdit, редактируемые QComboBox, редакторы ячеек
таблиц, поля диалогов) работает стандартное поведение:

| Действие | Клавиши |
|---|---|
| Копировать / Вставить / Вырезать | Ctrl+C / Ctrl+V / Ctrl+X |
| Отменить изменение | Ctrl+Z |
| Повторить изменение (где поддерживается) | Ctrl+Y и Ctrl+Shift+Z |
| Выделить всё | Ctrl+A |
| Удаление | Backspace, Delete |

- Сочетания работают независимо от раскладки Windows (RU и EN).
- Используются стандартные механизмы Qt (`QKeySequence::Copy`, `Paste`, `Cut`, `Undo`, `Redo`,
  `SelectAll`). Программа **не перехватывает** эти сочетания глобально: глобальные сочетания
  приложения (12.2) с ними не пересекаются, а в редактируемом виджете действует его собственное
  поведение.
- Контекстное меню полей и кнопки стандартных диалогов — стандартные Qt на русском языке
  (подключается перевод Qt `qtbase_ru`).
- Для числовых полей используется QLineEdit с собственным разбором (11.2), а не
  QSpinBox/QDoubleSpinBox: их разбор зависит от локали и не принимает оба разделителя.
  Если QSpinBox/QDoubleSpinBox понадобится, он должен соответствовать 11.2 и этому разделу.

## 16. Интерактивные графики X–Y [решение, GUI-D15]

Относится ко всем двумерным графикам с осями X и Y: сходимость, сечения, будущие сравнения.
**Не относится** к цветовым полям w(x, y): их интерактивное управление, интерактивный выбор
сечений на поле пластины и 3D-визуализация отложены (GUI-D13).

Общее правило: все интерактивные действия меняют только **вид** графика. Численные данные,
единицы СИ и результаты расчёта не меняются; расчёт не запускается.

### 16.1. Перемещение и масштаб (P3)

- Перемещение графика мышью — перетаскивание левой кнопкой в области построения.
- Колесо мыши — приближение и отдаление относительно положения курсора.
- Отдельные кнопки «+» (приблизить) и «−» (отдалить) — относительно центра области построения.
- Кнопка **«Исходный вид»** полностью восстанавливает первоначальный масштаб и положение
  (сохраняется при первом построении; не пересчитывается заново по текущему виду).
- Щелчок отличается от перетаскивания порогом смещения около 4 логических пикселей [инж.]:
  перетаскивание не фиксирует точку (16.4).

### 16.2. Координаты курсора (P3)

- При движении мыши в области построения непрерывно показываются координаты X и Y курсора
  с единицами СИ (например, `x = 1.250 m   w = −0.610 mm`).
- Поле координат — элемент интерфейса графика (под областью построения справа); в экспорт
  не входит.
- Числа — с десятичным разделителем языка графиков (7.3); единицы СИ одинаковы в обоих языках.
- Вне области построения поле координат очищается.
- Для логарифмической оси показывается значение величины, а не её логарифм.

### 16.3. Несколько кривых (P5)

- Каждая кривая включается и отключается отдельно (флажки в списке «Линии ▾» и/или в легенде).
- Команды «Показать все» и «Скрыть все».
- Скрытие кривой не удаляет её данные; повторное включение показывает те же данные.
- Скрытые кривые не участвуют в привязке (16.4) и не попадают в экспорт (16.7).
- «Исходный вид» учитывает исходный диапазон всех кривых графика, а не только видимых [инж.].

### 16.4. Привязка к кривой — Snap (P5)

Отдельная кнопка-переключатель **Snap**.

- **Активная кривая.** Привязка выполняется только к одной активной кривой. Если видимых кривых
  несколько, пользователь выбирает активную в списке, где перечислены только видимые кривые.
  Если активную кривую скрыли, привязка отключается до выбора другой.
- **Маркер, а не указатель.** Системный указатель мыши остаётся свободным; ограничивается только
  положение измерительного маркера.
- **Только отображаемая линия.** Маркер ставится в ближайшую точку отображаемой ломаной
  активной кривой (по расстоянию на экране в логических пикселях).
- **Интерполяция.** Между соседними исходными узлами маркер движется по отрезку отображаемой
  ломаной — линейная интерполяция в координатах отображения (на логарифмической оси —
  в логарифмических координатах, как нарисована линия) [инж.].
- **Плавное следование.** Маркер движется вдоль кривой без перескоков: поиск начинается
  с отрезков рядом с предыдущим положением маркера; переход на удалённый участок той же кривой —
  только если он ближе к указателю на заметную величину (гистерезис) [инж.].
- **Порог.** Если указатель дальше порога от активной кривой (около 20 логических пикселей,
  [инж.]), привязка не выполняется: маркер скрыт, показываются только координаты курсора (16.2).
- **Интерполированные значения не являются результатами решателя.** Подпись маркера
  различает «узел i» (совпадение с исходным узлом) и «интерполяция между узлами i и i+1».
  Интерполированные значения не записываются в таблицы результатов и в экспорт данных CSV.

### 16.5. Проекции на оси и фиксация точки (P5)

- Отдельная кнопка-переключатель **«Проекции»**.
- От маркера (при Snap) или от курсора (без Snap) — две пунктирные линии до осей X и Y,
  на осях — значения координат; координаты обновляются непрерывно.
- **Фиксация точки:** щелчок левой кнопкой (без перетаскивания) фиксирует текущую точку
  с её проекциями и подписью. Повторный щелчок по графику переносит фиксацию; Esc или кнопка
  «Снять фиксацию» снимает её [инж.]. Зафиксированная точка — элемент интерфейса; в экспорт
  не входит.

### 16.6. Меню «Оформление графика» (P6)

Отдельное меню (кнопка «Оформление ▾» в панели графика) с параметрами:

| Параметр | Значения |
|---|---|
| Фон всего рисунка | цвет |
| Фон области построения | цвет |
| Цвет осей и подписей | цвет |
| Цвет линий сетки | цвет |
| Цвет каждой кривой | цвет, независимо для каждой |
| Толщина линий | для каждой кривой |
| Тип линии | сплошная, штриховая, пунктирная, штрихпунктирная |
| Маркеры точек | вкл./выкл. для каждой кривой |

- **«Сбросить оформление»** возвращает стандартные настройки.
- **Стандартные настройки на экране** берутся из токенов текущей темы (`plot.*`, раздел 10);
  цвета кривых по умолчанию — палитра Okabe–Ito.
- Оформление хранится отдельно для каждого графика в пределах окна анализа и действует
  до закрытия окна [инж.]. Сохранение оформления в файлы — отдельное решение.

### 16.7. Язык, единицы, экспорт

- Тексты графиков — по языку графиков (раздел 7): EN по умолчанию, RU по выбору; переключение
  не меняет данные и не запускает расчёт.
- Единицы — СИ в обоих языках (11.1).
- Публикационный экспорт не зависит от темы интерфейса (раздел 8).
- Экспорт учитывает **видимость кривых** (скрытые не экспортируются) и **выбранное оформление**:
  явно заданные в меню 16.6 цвета, толщины, типы линий и маркеры. Стандартные значения
  экспорта — публикационный стиль (8.3), а не токены темы.
- **Открытый вопрос владельцу:** фоны рисунка и области построения, явно изменённые в меню 16.6,
  переносятся в публикационный экспорт или экспорт всегда на белом фоне (8.1)? До решения —
  экспорт на белом фоне.
- Элементы взаимодействия не экспортируются: курсор, поле координат, маркер Snap, проекции,
  зафиксированная точка, панель инструментов графика.
- Демонстрационные данные маркируются на экранных рисунках и в экспорте (раздел 9).

## 17. Навигация и справочная система [решение, GUI-D16, GUI-D17]

### 17.1. Верхняя навигация главного окна (P1.5)

- В тёмно-синей панели главного окна — разделы **«Главная · Настройка расчёта · Ход расчёта»**.
  Текущий раздел подчёркнут.
- Состояния «Выполнение» и «Завершение» показываются внутри раздела «Ход расчёта»; отдельного
  раздела «Завершение» нет.
- «Ход расчёта» доступен после первого запуска расчёта в сеансе. Во время выполнения
  все разделы доступны; параметры активного расчёта — только для просмотра (5.5; уточнено
  после P2.2).
- Окно анализа остаётся отдельным и открывается только кнопкой (GUI-D08); в его панели
  навигации нет.
- Служебный переключатель состояний в строке состояния и Ctrl+1…4 — **только режим разработки**
  (`kkvim-gui --dev`); обычный пользователь их не видит.

### 17.2. Контекстные подсказки (P1.5)

- Элемент участвует в справке, если у него задан ID темы (`set_help`, свойство `helpTopic`);
  вложенные элементы (например, поле ввода внутри поля с единицей) наследуют тему.
- Подсказка появляется после задержки около 500 ms [инж.] рядом с курсором и **не перекрывает
  элемент**: под ним, если не хватает места — над ним, для очень высоких элементов — сбоку.
- Подсказка исчезает при уходе указателя, нажатии кнопки мыши, вводе с клавиатуры, прокрутке
  колесом и смене активного окна.
- Подсказка не забирает фокус и прозрачна для мыши; события клавиатуры и мыши не перехватываются.
  Внутри элементов со справкой она заменяет стандартную всплывающую подсказку Qt.
- Содержание: название темы, краткое определение (`summary` статьи) и строка «F1 или ⓘ —
  подробная справка».
- Рядом с названием параметра — значок **ⓘ**, открывающий статью.
- На P1.5 подключены: геометрия (a, b, h), материал (E, ν), выбор теории. Остальные параметры —
  по мере появления статей.

### 17.3. F1 и справочный центр (P1.5)

**F1** открывает справку в таком порядке выбора темы:
1. тема видимой подсказки;
2. тема элемента под указателем;
3. тема выбранного элемента (с фокусом ввода) или его страницы;
4. тема страницы под указателем;
5. тема текущей страницы или вкладки окна (`help_context`);
6. без контекста — справочный центр в режиме общего поиска.

F1 работает в главном окне и в окне анализа; это не сочетание редактирования (12.1).
Пункт «Справка» в меню «⚙» открывает поиск по справке.

**Справочный центр** — отдельное окно, одно на приложение:
- сверху — строка поиска (без учёта регистра и различия «е/ё»; ищет в названиях, кратких
  определениях, ключевых словах и тексте);
- **основное оглавление — в алфавитном порядке А–Я**, сгруппированное по первой букве;
- справа — статья: название, тематический раздел и статус, выделенное краткое определение,
  текст, «Связанные темы», «Основание»;
- ссылки между статьями — `topic:<ID темы>`;
- тематические фильтры по разделам — в будущем (метаданные `category` уже есть).

Тематические разделы (метаданные статей): Начало работы; Параметры модели; Теории пластин;
Метод КК-ВИМ; Граничные условия; Итерации и сходимость; Результаты; Независимые методы и эталоны;
Научная литература; Ограничения программы.

### 17.4. Статьи справки

- Каждая статья — отдельный файл `src/kkvim_gui/help/articles/<ID темы>.md`; имя файла
  совпадает с ID. **ID тем постоянные**: на них ссылаются элементы GUI и другие статьи.
- Заголовок файла: `id`, `title`, `category`, `summary` (не длиннее 240 символов), `keywords`,
  `related`, `sources`, `status` (`stub` — заготовка, `draft` — черновик, `reviewed` — проверено).
- **Краткая подсказка и статья используют одно поле `summary`**, поэтому определения не
  расходятся.
- Зарезервированная запись (отображается упрощённо; полноценная система научных формул —
  позже): `$$ … $$` — выключная формула LaTeX; `$ … $` — формула в строке; `[@KEY, с. N, ур. (k)]` —
  ссылка на источник (ведёт в раздел «Научная литература»).
- **GUI не пишет научные статьи, формулы и научные утверждения.** Научные статьи, формулы
  и литературные материалы готовятся в основном проекте по проверенным источникам и переносятся
  в справку отдельным заданием. Сейчас в справке — служебные статьи (о справке, порядке работы,
  параметрах формы) с основанием из документов проекта и заготовки разделов.

### 17.5. Архитектура

```
kkvim_gui/help/
  articles.py   загрузка и проверка статей, алфавитный указатель, поиск (без Qt)
  render.py     статья -> Markdown для просмотра; формулы и ссылки (без Qt)

  service.py    F1, выбор темы по контексту, единственное окно справки
  window.py     справочный центр
  articles/     файлы статей
```

## 18. Конструктор финального отчёта [решение, GUI-D18]

Кнопка **«Собрать отчёт…»** — справа от вкладок окна анализа. На P1.5 она показана неактивной
с подсказкой; полная реализация — этап P7, после появления графиков (P3–P5), таблиц (P5)
и публикационного экспорта (P6).

### 18.1. Выбор пользователя

| Параметр | Значения |
|---|---|
| Компоненты | флажки: какие графики, поля и таблицы включить |
| Общий PDF-отчёт | да / нет |
| Рисунки | для каждого выбранного рисунка: PNG, SVG, PDF |
| Качество PNG | 300 или 600 dpi |
| Таблицы XLSX | да / нет |
| Язык рисунков | RU / EN (по умолчанию — текущий язык графиков) |
| Папка назначения | выбор папки; все компоненты сохраняются в одну папку отчёта |

### 18.2. Папка отчёта и manifest.json

```
<папка отчёта>/
  manifest.json
  report.pdf               если выбран общий отчёт
  figures/<рисунок>_<en|ru>[_TEST-DATA].png|svg|pdf
  tables/<таблица>[_TEST-DATA].xlsx
```

`manifest.json` содержит: идентификатор расчёта (`run_id`); входные параметры (`RunConfig`
с единицами СИ); версии программы, зависимостей и git commit; три статуса (выполнение,
критерий остановки, научная приёмка); `data_origin`; язык рисунков; дату сборки; перечень
сформированных файлов с форматом, разрешением, исходным компонентом и контрольной суммой.

### 18.3. Правила

- Экспортируются **только действительно доступные результаты**; недоступные компоненты
  в диалоге неактивны с причиной.
- Демонстрационные данные маркируются **TEST DATA** в каждом файле (рисунки, PDF, XLSX)
  и в `manifest.json`; тестовые значения не выдаются за научные.
- Сборка отчёта **не изменяет** исходные данные расчёта: только чтение `RunResult`.
- Рисунки строятся PublicationRenderer (раздел 8), независимо от темы и экрана.
- Если папка не пуста, существующие файлы не перезаписываются без подтверждения [инж.].
- Формат XLSX требует новой зависимости — отдельное решение (PROPOSED_CHANGES.md, 1.4).

### 18.4. Проверки (P7)

| № | Проверка |
|---|---|
| R1 | В папку попадают только выбранные компоненты; все — в одну папку |
| R2 | `manifest.json` содержит run_id, входные параметры, версии, статусы, перечень файлов |
| R3 | Недоступные результаты не экспортируются |
| R4 | TEST DATA во всех файлах демонстрационного отчёта и в manifest.json |
| R5 | Исходные данные расчёта после сборки не изменены (контрольные суммы) |
| R6 | PNG 300/600 dpi, язык RU/EN — как выбрано |

## 19. Мониторы, DPI и адаптивность [решение, GUI-D19]

### 19.1. Требования

- Корректная работа на Full HD, QHD и 4K при масштабе Windows 100, 125, 150, 175 и 200 %.
- Чёткие шрифты, линии и SVG-иконки; без обрезанных надписей и кнопок.
- Адаптивные размеры и размещение; основные действия доступны при большом масштабе.
- Корректное перемещение окон между мониторами с разным DPI.
- Качество экспортируемых изображений не зависит от экрана (раздел 8: dpi задаётся в экспорте).

### 19.2. Реализация [инж.]

- Все размеры — в логических пикселях Qt; шрифты — в пунктах; дробный масштаб без округления
  (`HighDpiScaleFactorRoundingPolicy.PassThrough`); Qt 6 сам отслеживает DPI каждого монитора.
- Иконки — SVG или рисуются QPainter; значок приложения — набор размеров 16–256.
- Минимальный размер окон — 960×540 логических пикселей, но не больше рабочей области (4.4).
- **Страница настройки** перестраивается по ширине: от 1100 — блоки параметров слева,
  схема справа; 760–1100 — схема под блоками; меньше 760 — одна колонка. Страница прокручивается,
  нижняя панель с «Выполнить расчёт» всегда видна.
- **Панель приложения** на узком окне скрывает имя проекта и сокращает плашку до «TEST DATA»;
  навигация, справка и настройки видны всегда.
- Сегментные переключатели не сжимаются меньше текста; сжимаются поля и списки.
- В окне анализа на узком окне скрывается дублирующая подпись «Данные: демонстрационные».

### 19.3. Логические размеры для проверки

| Монитор и масштаб | Логическая рабочая область (примерно) |
|---|---|
| Full HD, 100 % | 1920×1040 |
| Full HD, 150 % | 1280×690 |
| Full HD, 175 % | 1097×590 |
| Full HD, 200 % | 960×520 |
| QHD, 150 % | 1707×930 |
| 4K, 200 % | 1920×1040 |

## 20. Рабочая область окна анализа [решение, GUI-D20]

Вдохновлено интерфейсами OriginPro, MATLAB, COMSOL и OpenModelica; реализуется без
конструктора рабочих пространств и без дополнительных сложных панелей и меню.

### 20.1. Регулируемые панели (P4)

- Ширину панелей (рисунок, инспектор) пользователь меняет мышью (разделитель QSplitter).
- Правая информационная панель (инспектор) скрывается и снова показывается кнопкой; освободившееся
  место занимает график.
- Размеры и видимость панелей запоминаются (настройки пользователя, отдельно для каждой вкладки) [инж.].
- Кнопка **«Сбросить расположение»** возвращает исходную компоновку.

### 20.2. Разворачивание графика (P5)

- Двойной щелчок по заголовку графика разворачивает его на всю рабочую область вкладки;
  повторный двойной щелчок восстанавливает прежнее расположение.
- Особенно для вкладки «Сечения» с двумя графиками.
- Двойной щелчок по области построения этого действия не вызывает (там работают перемещение
  и фиксация точки, раздел 16).

### 20.3. Переход к числовым данным (P5)

- Правый щелчок по кривой → **«Показать исходные значения»**: таблица исходных узлов выбранной
  кривой (координаты и значения в единицах СИ).
- Если под указателем несколько кривых, пользователь выбирает нужную.
- Данные только для чтения; интерполированные значения Snap в таблицу не входят (16.4).
- Таблица поддерживает копирование (12.1); демонстрационные данные помечены TEST DATA.

### 20.4. Копирование рисунка (P6)

- Действие **«Копировать рисунок»** (контекстное меню графика и панель графика) помещает рисунок
  в буфер обмена Windows для вставки в Word, PowerPoint и другие программы.
- Учитываются текущий язык RU/EN, видимость линий и оформление (16.6–16.7).
- Рисунок строится PublicationRenderer: без элементов управления GUI, независимо от темы;
  формат буфера — растровое изображение и, если поддерживается, векторный формат [инж.].
- Демонстрационные данные маркируются TEST DATA.

### 20.5. Не входит

Конструктор рабочих пространств; дополнительные сложные панели и меню; 3D и интерактивные
двумерные поля; готовые профили оформления «Для экрана» / «Для статьи» (исключены решением
владельца 2026-10-12: остаются ручные настройки оформления и сброс к стандартным, 16.6);
изменения математического ядра.

### 21.1. Ресурсы вычисления в окне подтверждения (F2) [решение]

- Раздел «Ресурсы вычисления»: **CPU — автоматически / вручную**; по умолчанию — автоматически.
- Вручную: максимальное число вычислительных потоков, от 1 до числа логических процессоров,
  доступных на компьютере (определяется во время работы).
- Выбранное ограничение сохраняется вместе с параметрами запуска (снимок запуска,
  `manifest.json`) и показывается в сведениях о запуске.
- Интерфейс **не обещает** процент загрузки CPU или ускорение: подпись — «ограничение числа
  потоков; фактическое использование и время зависят от метода и задачи».
- Если метод не поддерживает управление параллелизмом (по реестру возможностей бэкенда),
  выбор недоступен с честной пометкой «метод не поддерживает управление числом потоков».
- Фиктивное управление ядрами процессора не создаётся: настройка появится вместе с бэкендом,
  который её реально применяет.
