# KK-VIM

Программа для расчёта статического изгиба квадратных и прямоугольных пластин
**методом вариационных итераций Крысько–Кириченко (КК-ВИМ)**.

В первоисточниках авторы указаны в порядке «Кириченко, Крысько»; в документах проекта метод
называется КК-ВИМ.

## Научная цель

Воспроизвести метод по первоисточникам, исследовать его точность, сходимость и вычислительную
эффективность и сравнить результаты с независимыми решениями.

## Текущее состояние

Фактическое состояние и следующий шаг — [docs/STATUS.md](docs/STATUS.md). Реализованы и приняты решатели линейной
пластины Кирхгофа–Лява, SSSS, q = const, N = 1:

- **R2 — ACCEPTED (D-035):** квадрат;
- **R3 — ACCEPTED (D-043):** прямоугольник a × b, 0,2 ≤ b/a ≤ 5. Численная квалификация — утверждённые отношения
  сторон и сетки с max(n_x, n_y) ≤ 640; моменты и напряжения не квалифицированы; сходимость при s → ∞ не доказана.

Решатель N = 2–3 (R4) — исследовательский, PROVISIONAL / NOT_QUALIFIED; CCCC (R5): при N = 1 — только исследовательский режим `run-cccc-n1`
(D-061), при N = 2, 3 — полушаг s = 1 и, на сетках до 32 × 32 после сертификатов RN-5 и RT-7, полушаг s = 2 в режиме `run-cccc-n23` (D-063, D-065), оба RESEARCH_ONLY / PROVISIONAL / NOT_QUALIFIED; при N = 4, 5, 6 — режим `run-cccc-n46`: полушаг s = 1 (D-067) и, на сетках до 32 × 32 после сертификатов RN-5 и RT-7, полушаг s = 2 (D-068), также RESEARCH_ONLY / PROVISIONAL / NOT_QUALIFIED. Список «Первая реализация» ниже — план; возможность считается реализованной только после появления
кода и предусмотренных проверок.

## Расчёт R3 из командной строки

```
uv sync --locked
uv run python -m kkvim run --a 1 --b 1 --t 0.01 --E 2.1e11 --nu 0.3 --q 1000 --nx 24 --ny 24 --out scratch/demo
```

Единицы СИ: a, b, t в м; E, q в Па; `--nx`, `--ny` — число интервалов сетки. Команда вызывает принятый решатель
`kkvim.rectangle_run.run_rectangle_physical` и отчёт `halfstep_report` и записывает в папку `--out`:

- `result.json` — ввод, жёсткость D, статус решателя, число полушагов, параметры остановки, ограничения применимости;
- `field.csv` — узлы x, y, прогиб w [м] и безразмерный w̄ = wD/(qa⁴); только при статусе CONVERGED;
- `history.csv` — величины каждого полушага (NUMERICAL_SPEC.md 11.5).

Статус решателя (CONVERGED, STAGNATED, MAX_HALF_STEPS, ERROR_*) записывается без изменения. При другом статусе
поле последнего полушага сохраняется только как `field_diagnostic.csv` — это не решение.

| Код выхода | Значение |
|---|---|
| 0 | CONVERGED |
| 1 | STAGNATED или MAX_HALF_STEPS |
| 2 | ошибка командной строки; папка уже содержит результаты или `--out` — файл; расчёт не выполнялся |
| 3 | ERROR_* решателя, включая ERROR_INPUT |
| 4 | результаты не сохранены или сохранены частично: ошибка создания папки, записи, замены или удаления файлов (не статус решателя) |
| 5 | непредвиденная внутренняя ошибка программы (не статус решателя) |

Существующие результаты заменяются только с `--overwrite`; файлы с другими именами в папке не затрагиваются.
Каждый файл сначала полностью записывается во временный файл, поэтому недописанных файлов результатов не бывает.
Но набор файлов заменяется не атомарно: если замена или удаление прерывается (например, файл открыт другой
программой), часть файлов может относиться к новому расчёту, а часть — к прежнему. Тогда команда возвращает код 4
и пишет в stderr, какие файлы уже заменены или удалены и на каком произошла ошибка. Такую папку нельзя
использовать как результат завершённого расчёта: устраните причину и повторите расчёт с `--overwrite`. Если ошибка
произошла до первой замены, команда сообщает, что прежние файлы результатов не изменены.

**Сетка и квалификация.** В `result.json` (`applicability.necessary_grid_conditions_6_1`) отмечено, выполнены ли
для n_x, n_y необходимые условия квалификационной сетки R3_NUMERICAL_SPEC.md §6.1 (D-039): min(n_x, n_y) ≥ 20,
max(n_x, n_y) ≤ 640, обе компоненты кратны 4. Квалификационные сравнения относятся только к десяти утверждённым
отношениям сторон (1/5, 1/3, 1/2, 2/3, 1, 7/5, 3/2, 2, 3, 5) и семействам сеток I (n_x = n_y) и II (h_x = h_y)
набора §6.2; отношение сторон и семейство команда не проверяет. Принадлежность сетки к квалификационному набору
сама по себе не означает научной приёмки конкретного расчёта; заключения QUALIFIED или PASS команда не делает.
Другие допустимые решателем сетки и отношения сторон считаются как диагностические расчёты. Параметры остановки `--tol-inf`, `--tol-E`, `--s-min`,
`--s-max` по умолчанию равны значениям, с которыми R3 принят. Справка: `uv run python -m kkvim run --help`.

## Расчёт SSSS при выбранном N = 1…6

```
uv run python -m kkvim run-ssss --N 1 --a 1 --b 1 --t 0.01 --E 2.1e11 --nu 0.3 --q 1000 --nx 40 --ny 40 --out scratch/n1
uv run python -m kkvim run-ssss --N 3 --a 1 --b 1 --t 0.01 --E 2.1e11 --nu 0.3 --q 1000 --nx 40 --ny 40 --half-steps 8 --out scratch/n3
uv run python -m kkvim run-ssss --N 6 --research-only --a 1 --b 1 --t 0.01 --E 2.1e11 --nu 0.3 --q 1000 --nx 40 --ny 40 --half-steps 8 --out scratch/n6
```

| N | Путь | Научный статус | Остановка | Вне области |
|---|---|---|---|---|
| 1 | принятый R3, как `run` (D-043) | решатель принят; отдельный расчёт — не приёмка | правило R3, `--s-max` и др.; `--half-steps` не применяется | ERROR_INPUT |
| 2–3 | `run_coupled`, исследовательский режим D-048 | PROVISIONAL / NOT_QUALIFIED; CONVERGED не используется (D-048.4) | стабилизация или `--half-steps` ≤ 100; `--fixed-half-steps` — стабилизация только регистрируется | считается, отмечается `inside_area: false` |
| 4–6 | `kkvim.research_ssss`, только с `--research-only` | RESEARCH_ONLY, PROVISIONAL / NOT_QUALIFIED (D-056.7) | обязательное фиксированное `--half-steps` ≤ 40 | отказ: только матрица исследования (десять r, n_x = n_y из 40…1280, шесть сеток семейства II) |

Файлы в `--out`: `result.json` (ввод, N, закрепление, метод, путь решателя, статус, применимость, версии, причина отказа), `history.csv` и
поле: `field.csv` — только при CONVERGED решателя R3, `field_research.csv` — исследовательское поле N ≥ 2, `field_diagnostic.csv` — поле
незавершённого расчёта. Энергии в `history.csv`: при N = 2–3 — физические, N·m; при N = 4–6 — нормированные, в единицах q²a⁶/D (множитель
`energy_scale_q2_a6_over_D` в `result.json`); единицы указаны в строке комментария `#` файла и в `result.json`, имена столбцов те же.
Отказ по `--N`, `--bc` (здесь доступно только SSSS; CCCC — только исследование: N = 1 через `run-cccc-n1`, N = 2, 3 через `run-cccc-n23`, N = 4, 5, 6 через `run-cccc-n46`) и несовместимым опциям ничего не считает и не создаёт.

Без `--overwrite` имеющиеся результаты не заменяются. С `--overwrite` набор файлов заменяется целиком только после того, как новый набор
готов. Отказ по вводу, расчёт с ошибкой `ERROR_*`, прерывание и сбой записи оставляют прежние файлы без изменений: статус и причина выводятся
в stderr. Остановка по правилу расчёта (`MAX_HALF_STEPS`, `STAGNATED`, защита, E1) — действительная замена. На время замены прежний
`result.json` снимается, а новый ставится последним: папка без `result.json` или с каталогом `.kkvim-run-*`, содержащим файл `replacing`, не
является результатом завершённого расчёта. Если процесс был убит на шаге замены, следующий запуск откажет и напишет, как вернуть прежние файлы
из `old` или начать заново. Одновременное сохранение двух запусков в одну папку не поддерживается. Команда `run` пишет, как прежде.

Коды выхода: 0 — расчёт завершён как запрошено (при N ≥ 2 это не сходимость); 1 — s_max без критерия; 2 — отказ, ничего не считалось; 3 —
ERROR_*; 4, 5 — как у `run`; 6 — защитная остановка или доказанная потеря ранга (N не уменьшается); 130 — прервано пользователем. Справка:
`uv run python -m kkvim run-ssss --help`.

## Расчёт CCCC, N = 1 (только исследование)

```
uv run python -m kkvim run-cccc-n1 --a 1 --b 1 --t 0.01 --E 2.1e11 --nu 0.3 --q 1000 --nx 32 --ny 32 --half-steps 8 --out scratch/cccc
```

Защемлённая прямоугольная пластина Кирхгофа–Лява, q = const ≠ 0, ровно N = 1 (D-061). Область: 0,2 ≤ b/a ≤ 5; 7 ≤ n_x, n_y ≤ 1280; `--half-steps` обязателен,
от 1 до 8, критерия остановки нет. Первый полушаг — по y. Каждый результат — `RESEARCH_ONLY / PROVISIONAL / NOT_QUALIFIED`: «завершено» значит только, что выполнено заданное
число шагов и защиты не сработали. Это не сходимость и не квалификация.

Файлы: `result.json`, `history.csv`, `factors.csv` и поле: `field_research.csv` при завершении, `field_diagnostic.csv` при остановке. При η > 100u расчёт останавливается со статусом
`STOPPED_ETA_GUARD`. Коды выхода: 0 — заданные полушаги выполнены; 2 — вне области, ничего не считалось; 3 — `ERROR_*`; 4, 5 — как у `run`; 6 — защитная остановка; 130 — прервано.
Отказ и `ERROR_*` при `--overwrite` не меняют прежние файлы. Запись и восстановление — те же, что у `run-ssss` (D-062): сбой записи и Ctrl+C возвращают прежние файлы, после убитого процесса следующий запуск откажет и напишет, что делать. Одновременное сохранение двух запусков в одну папку не поддерживается.

`factors.csv` — файл результатов для всех трёх команд: без `--overwrite` он не даёт использовать папку, с `--overwrite` не остаётся рядом с новыми результатами.

## Расчёт CCCC, N = 2–3, полушаги s = 1 и s = 2 (только исследование)

```
uv run python -m kkvim run-cccc-n23 --N 3 --a 1 --b 1 --t 0.01 --E 2.1e11 --nu 0.3 --q 1000 --nx 32 --ny 32 --half-steps 2 --out scratch/cccc23
```

Защемлённая пластина, q = const ≠ 0, N = 2 или 3 (D-063, D-065). Область: 0,2 ≤ b/a ≤ 5; 7 ≤ n_x, n_y ≤ 1280. Полушаг s = 1: старт
sin²(iπx/a), i = 1…N, QR стартового набора, решение по y. Полушаг s = 2 (`--half-steps 2`) — только при n_x, n_y ≤ 32 (D-065.5): сертификат RN-5
ранга первого полушага по сохранённым факторам этого расчёта в точной арифметике, затем QR решённого набора, проверка RT-7 сразу после QR и
решение по x. Если сетка больше 32, RN-5 или RT-7 не выполнен — `STOPPED_RANK_GUARD_UNCERTIFIED` до s = 2, поле s = 1 диагностическое;
N не понижается, регуляризации нет. При `--half-steps` от 3 до 8 после s = 2 — остановка до QR, открывающего s = 3. Каждый результат —
`RESEARCH_ONLY / PROVISIONAL / NOT_QUALIFIED`; фиксированные полушаги не приближают решение задачи, RN-5 и RT-7 не устанавливают точности поля
s = 2, ранга w⁽²⁾ и сходимости; η и энергия s = 2 — только наблюдения.

Файлы: `result.json` (с записями RN-5 и RT-7), `history.csv`, `factors.csv` (T, R, G, A, B, C, F, V и при s = 2 сопутствующий набор) и поле:
`field_research.csv`, если выполнены все запрошенные полушаги, `field_diagnostic.csv` при остановке. Коды выхода: 0 — выполнены запрошенные 1 или 2
полушага; 2 — вне области; 3 — `ERROR_*`; 4, 5 — как у `run`; 6 — защитная остановка, в том числе перед s = 2 и s = 3; 130 — прервано. Запись —
как у `run-ssss` и `run-cccc-n1` (D-062).

## Первая реализация (план)

- линейная теория Кирхгофа–Лява;
- однородный изотропный упругий материал;
- постоянная толщина;
- квадратные и прямоугольные пластины;
- равномерная поперечная нагрузка;
- закрепления SSSS и CCCC;
- КК-ВИМ: основной диапазон N = 1–3, исследование N = 4–6;
- решение одномерных краевых задач методом конечных разностей.

## Программный каркас

Технологический стек — решение D-028: Python 3.13 (основная версия) и 3.14, NumPy, SciPy, pytest,
сборка Hatchling, окружение и зависимости — uv (`pyproject.toml`, точные версии в `uv.lock`).

- `src/kkvim/` — основной пакет: решатели R2, R3 и исследовательский R4; `python -m kkvim` — расчёт R3;
- `src/kkvim_reference/` — независимый код эталонов;
- `tests/` — автоматические тесты: установка и импорт пакета; двусторонний запрет импортов
  между `kkvim` и `kkvim_reference`.

Окружение и тесты (нужен [uv](https://docs.astral.sh/uv/)):

```
uv sync --locked
uv run pytest
```

CI (`.github/workflows/ci.yml`) на push и pull request: Ubuntu и Windows × Python 3.13 и 3.14 —
проверка актуальности `uv.lock`, установка пакета и зависимостей из lock-файла, pytest;
отдельно — самотест pre-commit hook.

## Научная библиотека

По политике проекта (D-021) оригинальные научные публикации (PDF, DjVu, DOC, DOCX) не загружаются
в GitHub, в том числе публикации с открытыми лицензиями. Они хранятся локально в `references/`
(первоисточники КК-ВИМ — в `references/primary/`). В репозитории есть только индексы,
библиографические данные и самостоятельно написанные литературные обзоры. В клоне публикаций нет:
их нужно получить самостоятельно по каталогу и сверить с SHA256 из `references/INDEX.md`.

Это добровольное правило проекта, а не юридическая оценка. Политика хранения и статус сведений
о лицензиях — в `references/INDEX.md`, раздел 6.

## Защита Git

`.gitignore` исключает публикации (PDF, DjVu, DOC, DOCX, EPUB) и архивы во всём репозитории,
а также каталог `scratch/` для временных изображений страниц, сканов и рабочих файлов.
Собственные изображения проекта (PNG, JPG) не блокируются.

Версионируемый pre-commit hook отклоняет такие файлы среди staged, в том числе добавленные
через `git add -f`. Установка — один раз в каждом клоне:

```
git config core.hooksPath .githooks
```

Самотест (во временном репозитории, проект не затрагивает):

- Git Bash, Linux, macOS: `sh .githooks/test-pre-commit.sh`
- PowerShell (Git for Windows): `& "$env:ProgramFiles\Git\bin\sh.exe" .githooks/test-pre-commit.sh`

Ограничение: локальный hook можно обойти (`git commit --no-verify` или неустановленный hook).
Он предотвращает случайное добавление, но не является абсолютной гарантией.
