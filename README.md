# KK-VIM

Программа для расчёта статического изгиба квадратных и прямоугольных пластин
**методом вариационных итераций Крысько–Кириченко (КК-ВИМ)**.

В первоисточниках авторы указаны в порядке «Кириченко, Крысько»; в документах проекта метод
называется КК-ВИМ.

## Научная цель

Воспроизвести метод по первоисточникам, исследовать его точность, сходимость и вычислительную
эффективность и сравнить результаты с независимыми решениями.

## Текущее состояние

Фактическое состояние и следующий шаг — [docs/STATUS.md](docs/STATUS.md). Реализованы и приняты решатели линейной
пластины Кирхгофа–Лява, SSSS, q = const, N = 1:

- **R2 — ACCEPTED (D-035):** квадрат;
- **R3 — ACCEPTED (D-043):** прямоугольник a × b, 0,2 ≤ b/a ≤ 5. Численная квалификация — утверждённые отношения
  сторон и сетки с max(n_x, n_y) ≤ 640; моменты и напряжения не квалифицированы; сходимость при s → ∞ не доказана.

Решатель N = 2–3 (R4) — исследовательский, PROVISIONAL / NOT_QUALIFIED; CCCC (R5) — научная подготовка,
решателя нет. Список «Первая реализация» ниже — план; возможность считается реализованной только после появления
кода и предусмотренных проверок.

## Расчёт R3 из командной строки

```
uv sync --locked
uv run python -m kkvim run --a 1 --b 1 --t 0.01 --E 2.1e11 --nu 0.3 --q 1000 --nx 24 --ny 24 --out scratch/demo
```

Единицы СИ: a, b, t в м; E, q в Па; `--nx`, `--ny` — число интервалов сетки. Команда вызывает принятый решатель
`kkvim.rectangle_run.run_rectangle_physical` и отчёт `halfstep_report` и записывает в папку `--out`:

- `result.json` — ввод, жёсткость D, статус решателя, число полушагов, параметры остановки, ограничения применимости;
- `field.csv` — узлы x, y, прогиб w [м] и безразмерный w̄ = wD/(qa⁴); только при статусе CONVERGED;
- `history.csv` — величины каждого полушага (NUMERICAL_SPEC.md 11.5).

Статус решателя (CONVERGED, STAGNATED, MAX_HALF_STEPS, ERROR_*) записывается без изменения. При другом статусе
поле последнего полушага сохраняется только как `field_diagnostic.csv` — это не решение.

| Код выхода | Значение |
|---|---|
| 0 | CONVERGED |
| 1 | STAGNATED или MAX_HALF_STEPS |
| 2 | ошибка командной строки; папка уже содержит результаты или `--out` — файл; расчёт не выполнялся |
| 3 | ERROR_* решателя, включая ERROR_INPUT |
| 4 | результаты не сохранены или сохранены частично: ошибка создания папки, записи, замены или удаления файлов (не статус решателя) |
| 5 | непредвиденная внутренняя ошибка программы (не статус решателя) |

Существующие результаты заменяются только с `--overwrite`; файлы с другими именами в папке не затрагиваются.
Каждый файл сначала полностью записывается во временный файл, поэтому недописанных файлов результатов не бывает.
Но набор файлов заменяется не атомарно: если замена или удаление прерывается (например, файл открыт другой
программой), часть файлов может относиться к новому расчёту, а часть — к прежнему. Тогда команда возвращает код 4
и пишет в stderr, какие файлы уже заменены или удалены и на каком произошла ошибка. Такую папку нельзя
использовать как результат завершённого расчёта: устраните причину и повторите расчёт с `--overwrite`. Если ошибка
произошла до первой замены, команда сообщает, что прежние файлы результатов не изменены.

**Сетка и квалификация.** В `result.json` (`applicability.necessary_grid_conditions_6_1`) отмечено, выполнены ли
для n_x, n_y необходимые условия квалификационной сетки R3_NUMERICAL_SPEC.md §6.1 (D-039): min(n_x, n_y) ≥ 20,
max(n_x, n_y) ≤ 640, обе компоненты кратны 4. Квалификационные сравнения относятся только к десяти утверждённым
отношениям сторон (1/5, 1/3, 1/2, 2/3, 1, 7/5, 3/2, 2, 3, 5) и семействам сеток I (n_x = n_y) и II (h_x = h_y)
набора §6.2; отношение сторон и семейство команда не проверяет. Принадлежность сетки к квалификационному набору
сама по себе не означает научной приёмки конкретного расчёта; заключения QUALIFIED или PASS команда не делает.
Другие допустимые решателем сетки и отношения сторон считаются как диагностические расчёты. Параметры остановки `--tol-inf`, `--tol-E`, `--s-min`,
`--s-max` по умолчанию равны значениям, с которыми R3 принят. Справка: `uv run python -m kkvim run --help`.

## Первая реализация (план)

- линейная теория Кирхгофа–Лява;
- однородный изотропный упругий материал;
- постоянная толщина;
- квадратные и прямоугольные пластины;
- равномерная поперечная нагрузка;
- закрепления SSSS и CCCC;
- КК-ВИМ: основной диапазон N = 1–3, исследование N = 4–6;
- решение одномерных краевых задач методом конечных разностей.

## Дальнейшие направления (план)

Теории Тимошенко и Редди; фон Карман; Биргер; совместная нелинейность; Грин–Лагранж;
Мори–Танака/FGM; дополнительные краевые условия.

## Принципы

- KK-VIM — независимый научный проект, создаваемый с нуля (D-001, D-026).
- Код, обзоры, спецификации, протоколы и индексы прежних проектов не используются. Из прежней
  работы сохранены только оригинальные научные публикации в `references/`.
- Научные обзоры, формулы, математические постановки и алгоритмы разрабатываются заново
  по оригинальным публикациям.
- Математику определяют первоисточники.

## Программный каркас

Технологический стек — решение D-028: Python 3.13 (основная версия) и 3.14, NumPy, SciPy, pytest,
сборка Hatchling, окружение и зависимости — uv (`pyproject.toml`, точные версии в `uv.lock`).

- `src/kkvim/` — основной пакет: решатели R2, R3 и исследовательский R4; `python -m kkvim` — расчёт R3;
- `src/kkvim_reference/` — независимый код эталонов;
- `tests/` — автоматические тесты: установка и импорт пакета; двусторонний запрет импортов
  между `kkvim` и `kkvim_reference`.

Окружение и тесты (нужен [uv](https://docs.astral.sh/uv/)):

```
uv sync --locked
uv run pytest
```

CI (`.github/workflows/ci.yml`) на push и pull request: Ubuntu и Windows × Python 3.13 и 3.14 —
проверка актуальности `uv.lock`, установка пакета и зависимостей из lock-файла, pytest;
отдельно — самотест pre-commit hook.

## Научная библиотека

По политике проекта (D-021) оригинальные научные публикации (PDF, DjVu, DOC, DOCX) не загружаются
в GitHub, в том числе публикации с открытыми лицензиями. Они хранятся локально в `references/`
(первоисточники КК-ВИМ — в `references/primary/`). В репозитории есть только индексы,
библиографические данные и самостоятельно написанные литературные обзоры. В клоне публикаций нет:
их нужно получить самостоятельно по каталогу и сверить с SHA256 из `references/INDEX.md`.

Это добровольное правило проекта, а не юридическая оценка. Политика хранения и статус сведений
о лицензиях — в `references/INDEX.md`, раздел 6.

## Защита Git

`.gitignore` исключает публикации (PDF, DjVu, DOC, DOCX, EPUB) и архивы во всём репозитории,
а также каталог `scratch/` для временных изображений страниц, сканов и рабочих файлов.
Собственные изображения проекта (PNG, JPG) не блокируются.

Версионируемый pre-commit hook отклоняет такие файлы среди staged, в том числе добавленные
через `git add -f`. Установка — один раз в каждом клоне:

```
git config core.hooksPath .githooks
```

Самотест (во временном репозитории, проект не затрагивает):

- Git Bash, Linux, macOS: `sh .githooks/test-pre-commit.sh`
- PowerShell (Git for Windows): `& "$env:ProgramFiles\Git\bin\sh.exe" .githooks/test-pre-commit.sh`

Ограничение: локальный hook можно обойти (`git commit --no-verify` или неустановленный hook).
Он предотвращает случайное добавление, но не является абсолютной гарантией.
